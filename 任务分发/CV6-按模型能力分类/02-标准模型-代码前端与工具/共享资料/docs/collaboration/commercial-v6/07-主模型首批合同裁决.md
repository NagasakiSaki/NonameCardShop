# 07：首批主模型裁决——剧情因果、读档和时钟

日期：2026-10-25。核对源码 HEAD：`16cd0b06`。这是主模型负责的 G1/G2 规则裁决，供 CV6-14/21/23/24/26 和 16/17 使用；不是新 API 已实现或候选已验收的声明。字段名称、JSON Schema 和具体补丁仍由对应作者提出，不能凭本文启用能力声明。

## 1. 已核对的现状

| 位置 | 实际行为 | 新模块必须处理的边界 |
| --- | --- | --- |
| `modules/backend/world.mjs` 的 `note` | 日志保留最近 1000 条；事件号来自世界 serial | 日志不能充当永久剧情指标或无限期事件队列 |
| `modules/backend/runtime.mjs` 的 `command` | 串行队列、fork、领域处理、persist；成功操作记 requestId | 剧情事务内不得再等待 Host.command；不能假设失败请求已持久缓存 |
| 同文件的 `saves.load*` / `saves.import` | 恢复存档世界，生成新 branchId，保留分支来源 | 读档后拒绝旧界面请求；已兑现的剧情回执必须随快照恢复 |
| 同文件的 `persist` | 提交前还会处理比赛耗时、自动任务奖励、世界校验 | 剧情与这些实际副作用的证据须来自同一次最终提交，不能提前发成功通知 |
| `modules/backend/match-time.mjs` | 玩家整场结算 30 分钟；后台比赛不额外跳时 | 剧情不得重算比赛耗时或把 NPC 赛果当玩家通过考核 |

上述是现状和扩展风险，不表示现行游戏已经发生重复剧情奖励；当前尚无正式剧情运行器。

## 2. 冻结规则：快照与读档因果

1. 日初读档恢复当天开始的全部世界因果，包括钱、卡、任务、关系、剧情游标和兑现回执；不让跨档的已读设置替代剧情状态。
2. 快照之前兑现过的效果，读取该快照后仍视为兑现。快照之后才发生的效果随世界一起撤销，玩家在新分支重新满足条件时可以再次完成；这是回读后的正常重玩，不是跨分支追加收益。
3. 旧分支的未完成网络请求、回调、事件通知不得作用于新分支。界面恢复后重新查询会话；新操作使用新 requestId，不直接重发旧窗口排队的动作。
4. 持久效果身份必须在同一剧情发生实例内稳定；不能单靠“当前 branchId + effectId”识别是否兑现，否则读档生成新分支会绕过去重。发生实例及回执随快照保留，传输请求另校验当前分支。
5. 不同实例可以执行同一模板效果；实例创建规则必须明确。一次性主线按完成状态限制新实例，可重复活动按真实活动/日程实例区分。不能以反复开关窗口生成新实例来重领。

## 3. 冻结规则：效果提交与失败

每个权威动作必须在一个现有 fork 中完成：校验当前世界/会话/节点/内容版本和前置 → 调用受控领域函数 → 写回执与下一游标 → 世界校验和仓库提交。失败不发布下一节点或业务成功；领域、回执和游标一起回滚。

同一效果实例再次提交时，返回已提交回执或一致的已完成状态，不能再次扣钱、发卡、推进时间或改资格。效果参数签名不一致必须拒绝，不能复用同一身份执行另一笔业务。

连接中断、提交结果未知时先查原操作/持久效果回执。没有确知失败前不改号重发。提交失败后允许重试，但失败响应不能被作者误当成现有 Host 已记录的终态。首版剧情不承担远端支付等不可回滚的外部副作用。

内容修改只改台词时不能更换已发生效果身份；删除或改义需迁移映射。缺旧内容或映射不可信时保留进度、挂起会话并允许经营，不自动从头执行动作。

## 4. 冻结规则：事件条件

累计售出、收入、参赛等长期条件读持久指标，不能从最近 1000 条日志临时汇总。新增指标必须说明旧档缺失时的默认/不可追溯状态，不用猜测补发奖励。

等待一次未来成交默认从进入 wait 时开始监听，不能用较早的一笔成交瞬间完成。若剧情需要“此前已完成”，内容必须明确使用历史状态/累计指标。一个事件可以通知多个独立订阅者，每个订阅者最多推进一次；不能全局消费事件导致其他任务漏收，也不能轮询同一事件无限推进。

事件身份必须绑定世界和产生分支，记录真实业务来源及关联交易/比赛。事件捕获或指标更新与实际业务提交保持一致；通知来自最终提交，回读后的旧通知无效。具体采用事务内投影、持久待处理队列或等价方案由 21/17 提出，必须证明断连、日志截断和重试不漏不重。

## 5. 冻结规则：暂停、等待与地图

- 对话、选择和普通交互持有窗口暂停租约；进入等时间、到访、成交或比赛结果的 wait 后释放剧情模态租约。不得释放其他窗口或玩家比赛的暂停。
- 对话结束、延期、读档、内容缺失和异常退出均须清理自身租约；恢复会话由当前界面重新获取，不持久化失效的进程租约。
- 玩家对战沿用整场暂停、结束 +30 一次；NPC 对战本身不暂停经营。剧情监听结果，不补算另一份时间或费用。预演/模拟/辅助训练不可作为真实玩家牌技证明。
- 第三地图首轮只验证准备/歇业状态下的离店与返回，沿用当前时钟，无独立后台钟。本轮不改变现有自动收银，不以此证明营业离屏经营已完成。
- 旅行不能静默开始第二天或绕过日结；到达失败保持有效原位置。位置、路线和人物身份校验成功后才提交地图变化，不能先传送再校验。

## 6. 后续候选必须覆盖的验收输入

| 编号 | 输入 | 必须观察到 |
| --- | --- | --- |
| G2-01 | 同一效果实例重复请求；另一次请求换 requestId | 领域效果只兑现一次，回执/游标一致 |
| G2-02 | 相同效果身份换金额、对象或目标 | 拒绝，不产生第二笔业务 |
| G2-03 | 提交故障或仓库并发冲突后重试 | 无半份奖励、无提前游标、无成功事件；重试不重复 |
| G2-04 | 奖励后存档再读取；奖励前存档再读取 | 前者不重领，后者世界收益一并回滚且可正常重玩 |
| G2-05 | 读档后到达旧分支的选择/赛果/成交通知 | 不推进新分支剧情，不执行旧界面动作 |
| G2-06 | 进入等待前已有成交；等待后真实成交并重复通知 | 前者不满足“下一笔”条件，后者每订阅者最多推进一次 |
| G2-07 | 两个任务等待同一真实事件；日志再增加超过 1000 条 | 两者均可完成，累计条件和兑现事实不因截断丢失 |
| G2-08 | 对话 → wait → 成交 → 返回对话；再叠加另一暂停窗 | 等待不自锁；只释放自己租约，不偷偷推进其他暂停中的世界 |
| G2-09 | 玩家 BO3/KOF 整场结束和 NPC 模拟对局结束 | 玩家仅 +30 一次；NPC 不额外跳时、不形成玩家资格 |
| G2-10 | 台词更新、旧节点删除、旧内容缺失、旧档无剧情字段 | 固定活动版本或显式迁移/挂起；不重奖、不堵塞自由经营 |
| G2-11 | 准备/歇业跨地图往返；目标地图不可用 | 单一世界、人物不复制；失败位置有效且不重复计时 |

这些是验收要求，尚未运行的行不得标为通过。21/24 提供候选和证据，17 接入沙盒，16 独立复现；主模型按代表正向/失败链裁决正式接入。
