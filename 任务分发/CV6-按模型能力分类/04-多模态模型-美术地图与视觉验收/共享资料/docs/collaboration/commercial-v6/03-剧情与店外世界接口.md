# 03：剧情、经营、存档与店外世界接口草案

**新增 API、字段与目录均为提案，尚未实现。** 正式入口以现有 `contracts/card-shop-host.d.ts`、源码和最近验收记录为准。21/24 先交小样例合同，由主模型冻结后下游实现。

首批因果/读档/时钟政策已由主模型核对，见 [07 首批合同裁决](07-主模型首批合同裁决.md)。下文接口形状仍为提案；效果实例身份不能因读档生成新 branchId 而丢掉已兑现事实。

## 1. 当前边界与必要改造

- `modules/backend/experience.mjs` / `contracts/shop-experience.d.ts` 已有引导、交流会与本店事件故事。`experience.stories` 是从实际事件投影的短记录，**不是分支剧情运行器**；不能改其含义或用作者故事伪造交易日志。
- `contracts/map.schema.json` 当前把 mapId 限在 store/battle-room；前端地图 manifest/loader 可查表加载，但后端经济/入口/场景仍有 store、battle-room 和固定偏移耦合。不能说只加一个 JSON 文件就支持任意世界。
- 库存、钱包、流通、费用、赛事/比赛与存档由同一 Host 权威管理。剧情模块既不自建经济副本，也不重写无名杀。

## 2. 剧情持久结构

新增 `world.narrative` 的最小提案：

```text
schemaVersion、campaignId、contentRevision
chapterStates、flags、relationships
activeSession {sessionId, sceneId, nodeId, revision, pendingIntent?}
completedScenes、consumedEffects（或等价持久回执索引）
pendingTriggers、deferredScenes、questBindings
```

上述因果状态随世界、日初/即时档一起保存。玩家“文字速度/自动播放/音量”等偏好可独立于世界，已读提示若跨档保存也不能用于解锁剧情、资格或奖励。旧档无字段默认未启用/未开始，不能一加载就发主线奖励或重发赠盒。

存档保存游标、变量、事件/副作用回执及内容版本引用，不复制整套台本、图片或音频。脚本/素材按章节和地点加载，所需旧内容包须可查找；若缺失则给可恢复提示，不把缺内容当成剧情从未发生。去重索引的压缩/保留策略不能丢掉“已兑现”事实。

命名人物目录 `personId`、实际 actorId、外观 appearanceId、地点与访问行程分开。一个人物同时只有一个实际实体；对话引用稳定 personId，通过绑定找到现有 NPC/员工/联系人，不复制一个同名随机顾客。

## 3. 拟定业务接口

| 查询/意图 | 作用 | 权威边界 |
| --- | --- | --- |
| `narrative.available` | 当前可谈场景、前置不足原因、可延后项 | 只读，不消耗触发器、不创建角色 |
| `narrative.session` | 当前会话、台词/选项、可执行动作 | 不暴露未解锁的全部剧透或可任意写的 world |
| `narrative.start/choose/advance/defer/end` | 会话流转 | 稳定 requestId、分支/内容版本、节点和选择 ID 校验 |
| `narrative.resolveIntent` | 兑现被批准的语义动作/处理业务回执 | 在同一事务核对前置、调用领域函数、写副作用回执和剧情游标 |
| `world.locations/routes` | 可见地点、出入口、通行许可和耗时说明 | 不把地图编辑坐标当玩家可写位置 |
| `world.travel` | 请求走向出口/跨地图 | 已知 routeId、来源锚点、资格、占用与失败清理 |

保留 `card-shop-ui/1.0` 的兼容响应；新增能力通过 capabilities/查询发现，旧界面可继续经营。上表不是现成命令，候选不得硬写成功回调宣称已接入。

## 4. 条件、事件与副作用一致性

剧情条件区分状态条件与事件条件：状态是当前余额/关系/人物位置，事件是实际某次成交/拾牌/赛果。事件记录需要稳定 eventId、world/branch、来源、关联交易/比赛/人物；同一事件不能被无限轮询重复消费。累计条件读持久指标，不依赖已被截断的日志。

首版动作白名单是“解锁联系人/任务、登记旗标/关系、导航或打开业务界面、请求一项已有规则定义的考核/活动”。钱、卡、资格与旅行许可必须有对应领域合同；仅播放文字或选择某一句话不能写出已获胜、已成交、已拥有。

副作用 `effectId` 稳定且与内容修订、会话、世界分支绑定；命令号由受控安全 ID 生成，满足现有长度/字符约束。执行使用现有事务 fork 中的领域函数，**不能在剧情事务里嵌套调用另一个异步 Host.command 导致死锁或半提交**。成功同时提交业务变化、回执与剧情下一节点；结果未知查原操作，不发新号再发奖。

副作用失败有独立出口；剧情旗标与奖励不能一个提交、另一个丢失。重复消息、窗口关闭、重连、内容热更新与日初回读都要覆盖。历史已兑现回执不能因编辑 nodeId/文本而消失；删节点需迁移表。

## 5. 暂停、等待、战斗与表现

对话窗通过现有窗口管理器持有暂停租约；关闭/延期释放。等待营业分钟/顾客到访/交易/比赛结束的节点必须退出模态等待，让世界按既有规则运行。不能“打开自动暂停窗口后等 10 游戏分钟”，也不通过绕开暂停补计时间。

玩家比赛暂停经营并整场推进 30 分钟；NPC 比赛连续进行。剧情只订阅最终有效赛果，不自己再加半小时、发第二份费用或把预演/模拟当玩家技术证明。训练、借牌、辅助和正式考核证据必须可区分。

镜头、立绘、声音与动画是 cue，不能确认经济结果。可跳过演出只略过允许的无业务动作；涉及花钱、消耗、阵容、关键选择或旅行时必须保留实际确认。剧情播出不重写角色坐标，移动请求仍走导航/动作队列，失败可取消/稍后继续。过场不得把服务中的顾客强行传到镜头旁。

## 6. 内容/存档/内核版本

保持 Host 合同、save schema、story schema、compiler/runtime、content revision、map/nav revision、engine profile、format 与经济/印刷版本各自独立。参考 MV5 的内核适配/升级目标，但最新 KOF/时间规则以本版为准。

活动剧情会话固定 revision；编辑器保存不改变正在说的那句话/下一选项含义。新内容默认在安全边界激活，节点别名/迁移表解决旧游标。不能恢复的会话挂起、保留进度并让玩家继续经营；不是悄悄从头再领奖。

完整引擎随机状态恢复仍未实现；剧情保存成功不等于打牌状态可精确续接。上游无名杀更新通过 profile/adapter/能力探测，剧情动作依赖语义资格/赛果，不依赖某新版 lib 私有字段。不支持目标能力时在启动考核/扣费前提示，不以模拟胜利补洞。

## 7. 店外世界注册

```text
RegionDefinition {regionId, revision, locationIds}
LocationDefinition {locationId, mapId, mapRevision, kind, visibilityPolicy, serviceIds}
RouteDefinition {routeId, fromLocation, exitAnchor, toLocation, entryAnchor,
                 accessPolicy, transitionStyle, travelTimePolicy}
PersonLocation {personId, actorId, locationId, localPosition, scheduleState}
StoreAwayPolicy {state, staffingRequirement, servicesAllowed, cashPolicy}
```

地点ID、地图文件、地区叙事名和本地坐标分开；相邻地图的显示 worldOffset 不是游戏身份，也不是无限世界绝对坐标。旧 store/battle-room ID 和业务锚点保留别名兼容，不一次改完全部存档引用。

24 的盘点应覆盖 `frontend/scenes/world-scene.mjs`、`frontend/world/map-loader.mjs`、interaction-router、navigation、schema、server/manifest、runtime、visits 与经营各自的硬编码。先注册表与第三地图灰盒，再接真实首街区。店外不是把所有地图常驻同一巨型画布；按需加载、生命周期清理，近邻无缝、远行可明确转场。

## 8. 离店时经营与 NPC

首版店外验证可选择准备/歇业时出门，先避免在未验证状态下同时改一整套离屏经营。成熟版推荐政策：无当班收银能力时只允许歇业离店或返回；有明确当班能力时，允许已批准的营业自动化。**这是待批准的未来规则，不在写本方案时改变当前自动收银。**

离屏店铺仍只有一份库存/钱/顾客/赛事记录。允许继续营业时用同一逻辑时钟与有界步进/事件调度；画面卸载不停止或复制结算。玩家打牌、剧情/普通交互暂停仍按统一时钟，无第二个偷偷推进店铺的后台时钟。

旅行耗时、离屏营业耗时和玩家比赛耗时不能重复计。短距离步行以正常时钟为准；显式远行如需一次性耗时，在路线合同中定义并持久结算一次。跨打烊/日界不静默开启第二天；读取日初恢复人在何处、店开没开、角色日程与剧情。

NPC 的全局人物身份、地图位置与本店 visit 分离。离开店铺可进入街区/离屏状态，不必等于删除 NPC；同一人不能同时在两张地图。命名人物被邀约时要核验行程与可用时间，能延后或改约，不能让所有剧情人物固定堵在门口。

## 9. 最小店外内容与未来拓展

第一块“灯桥街”只做店门、公告栏、邻店门面和社区空间入口，建立两条可来回走的路线和一个真实剧情触发点。未做建筑门口显示未开放，不用空气墙冒充完整世界。第二家可经营门店、全城交通、战斗地牢、联网经济均后置，不因预留 locationId 就宣布实现。

未来内容包可新增地区/地点/人物/剧情而无需修改中央 if 链；通过注册表、能力声明和校验报告接入。稳定资源 ID、map/nav revision、服务能力和剧情条件为扩展点，不允许内容包携带任意代码直接改玩家世界。
