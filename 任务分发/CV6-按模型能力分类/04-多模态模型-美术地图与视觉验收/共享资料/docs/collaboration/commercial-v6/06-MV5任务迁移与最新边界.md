# 06：旧任务如何迁移

MV5 是先前“成熟经营与可升级内核”规划，用户未宣布开始其实施。本次 CV6 是最新任务入口；旧文件保留为参考，不把 planned 擅自改 completed/assigned，也不要求执行者重置到旧 HEAD。

| 旧包 | 最新包 | 必须更新的边界 |
| --- | --- | --- |
| MV5-01/02 | CV6-01/02 | 纳入剧情制作/实际首章与离店体验，不仅算经营指标 |
| MV5-03 | CV6-03 | 基线已是100/200/300三档与resource-yield-1；不是尚待第一次降价 |
| MV5-04 | CV6-04/19/20 | 成长配置、世界/角色总案、具体台本分别负责，不让一包全写 |
| MV5-05 | CV6-05/24 | 命名剧情人物绑定唯一 actor；店外位置和本店 visit 分开 |
| MV5-06 | CV6-06/26 | 经营/赛事窗口与剧情播出分开，共用窗口管理器 |
| MV5-07/08/09 | CV6-07/08/09 | KOF新四张，NPC不停时；剧情订阅真实资格与赛果，不二次结算 |
| MV5-10 | CV6-10 | 已有首轮资源评分，继续来源分层/校准，不能声称所有复杂将都精确 |

MV5-19 及以后不存在。本轮新增 CV6-19～26 的任务书已写出，不能找旧同号任务自行猜职责。新可写根为 `deliverables/commercial-v6/`，不是 `playability-v*` 或 `maturity-v5`。

所有拟定 story/world API 尚未实现；当前 `experience.stories` 仍是实际经营事件投影。已有存档、用户原图、旧交付和上次修复不可因新文件夹而覆盖。
