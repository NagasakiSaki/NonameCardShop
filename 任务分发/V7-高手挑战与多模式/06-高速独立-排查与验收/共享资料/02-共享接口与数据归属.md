# 候选共用接口 v1 与权威归属

这是给各组并行实现的冻结草案 `card-shop-v7-candidate/1`，不是现有 Host 已支持的 API。所有新增命令最终由主模型接入既有 Host/UI 合同，禁止各组自行升级全局合同或直接修改运行版。字符串以 `共享合同-v1.json` 为准；本文件给语义。

## 状态所有权

| 数据 | 唯一候选生产者 | 最终权威 |
| --- | --- | --- |
| 价格档、客群参数、主题退市/阶段目录、配盒策略 | A | 世界规则与产品版本 |
| campaign进度、invite、高手实体意图、伙伴、解锁回执 | B | world.progression 命名空间 |
| format定义、备战/逐局阵容、座位计划、系列赛归约 | C | world.matches 扩展 |
| 引擎能力、native profile、ready/结果验证与映射 | D | 现有受信任引擎桥 |
| 对话显示、点击/移动意图、窗口/输入租约 | E | 只持有UI状态，Host判断可交互 |
| 审计/验收结果 | F | 独立证据，不改业务状态 |

A不写B的解锁记录，B不自行结算比赛，C不颁发解锁，D不加钱，E不直接写任何业务进度。F不“顺手修”其他候选。A输出的阶段目录必须有显式 ordinal/productId/challengerId/personId/appearanceId/formatId，B只读配置。

## 四个接入边界

候选模块优先导出同步纯函数/当前fork内同步领域函数，输入显式 DTO，不读取另组隐式全局。统一返回 `{ok:true,data,effects}` 或 `{ok:false,error:{code,message,retryable}}`；effects 是待主模型消费的**意图**，不是已到账/已移动。模块不得自行调用异步 Host.command。

1. A：`buildEconomyPolicy(config)`、`evaluateSupplyAccess({productId,progression,retired})`、`quoteProduct({tier,unit,policy,allyEffects})`、`budgetForVisit({buyerClass,wallet,reserved,visitSeed,policy})`、`planCollation({productId,unlockedProductIds,catalog,policy})`。返回明确报价/拒绝、补位池与实际配盒，不消耗世界RNG做查询。
2. B：`reduceProgression(state,event,context)`、`planChallengerVisit(state,day,context)`、`offerInvite(state,input,context)`、`replyInvite(state,input,context)`、`settleChallenge(state,verifiedSeriesResult,context)`、`deriveAllyEffects(state,config)`。context显式包含营业时间、占用/在场/版本/权限；返回state和领域意图。调度不能直接生成随机物品。
3. C：`listFormats(capabilities)`、`validateReserve(formatId,rosters,eligibility)`、`createSeries(input)`、`selectRound(series,input)`、`buildRoundPlan(series)`、`reduceSeries(series,verifiedRoundResult)`、`planRosterLocks(series)`、`normaliseLegacyMatch(old)`。技术异常与正常胜负分开；不要复用bo3的“两个人物”假设。
4. D：`probeModeCapabilities(profile)`、`mountNativeRound({container,plan,signal,onEvent})`、`validateNativeEvent({event,origin,source,expected})`、`mapNativeResult(event,plan)`。挂载句柄提供dispose；能力包含supported/reason/profile/hash，不能凭vendor文件存在返回通过。

函数名可按语言风格微调，但交付给相同语义的 adapter，不能让其他组追着作者改输入。扩展字段兼容；修改已有字段语义需要主模型统一出新草案，各组不要互相等待改合同。

## 拟接入 Host 查询

- `progression.status`：epoch、revision、当前阶段、解锁产品、下一来访、可恢复错误。
- `challenges.status`：当前邀请与挑战、人物/主题/可选格式、接战条件、延期/败北状态；没有邀请返回null。
- `allies.list`：已加入伙伴、值班、岗位/效果、上限、不可用原因。
- `actors.actions({actorId})`：可对话/约战/忙碌/距离/模式能力；普通NPC和高手统一入口，来源策略不同。
- `dialogue.offer`：最多一个当前可呈现的场景接洽，含offerId、source、actorId/personId、已有narrative proof或业务inviteId、可用选项；查询不生成邀请/不消费随机数。
- `combat.formats`：四赛制元数据、reserveCount/activeCount、可用性与原因。
- 扩展 `combat.eligible({formatId})`：与现有mode参数做兼容映射。
- `combat.series({matchId})`：系列比分、phase、备战与当前小局选择、角色/席位、继续/恢复政策。

## 拟接入命令

所有命令带现有requestId；新业务意图带worldId/branchId/expectedRevision或独立资源proof，查询给出的token不能自己拼造。

| 命令 | 主要payload | 关键规则 |
| --- | --- | --- |
| `actors.interact` | actorId, interaction:'talk'/'challenge', proof | 后端核对在场/距离/空闲；点击不是立即开赛 |
| `challenges.respond` | inviteId, response:'accept'/'tomorrow', proof | accept只进入准备，不伪报已打；tomorrow持久化次日再访 |
| `combat.prepareSeries` | inviteId?, formatId, reserveRefs, tableId?, proof | 核对5/8等备战数、持有与锁定；高手借用只属于对方 |
| `combat.selectRound` | matchId, roundId, selections:[seatId,inventoryRef], proof | 只选自己控制阵营，本轮确认后冻结 |
| `combat.start` / `combat.continue` | matchId, proof? | 兼容旧命令；主模型通过适配转给新系列状态 |
| `dialogue.respond` | offerId, optionId, proof | 只路由已显示的合法选项；单次消费/延期，不能执行任意动作名 |
| `allies.assign` | allyId, dutyId或null, proof | 核对已解锁、岗位、人数上限，效果由后端派生 |

从点击到注册比赛采用 prepare/confirm 流程：接受对话不收费、不锁8张牌、不占满桌；选将确认后原子登记/锁卡/占桌/接受桌费，双方状态再校验。若桌费变化需要重新确认，不能悄悄用新金额替代。

## DTO与赛果证据

`formatId` 是经营赛制，`engineMode` 是noname原生模式，`nativeVariant` 是本地子规则。三者分开，必须记录profile版本/能力hash，不写死一个全局mode变量。

`RoundPlan` 最少：version、worldId、branchId、matchId、gameId、roundId、formatId、engineMode、nativeVariant、profileId、seed、reserveDigest、playerTeamId、controlledSeatId、seats。每座包含seatId、teamId、role、controller:'human'/'ai'、generalId、sourceRef或loanRef；只有一个human。斗地主3座、2v2四座；角色不能通过座位序号猜测。

可信小局结果：gameId/roundId、resultId、winningTeamId或draw、实际席位与将ID摘要、profileId、originVerified/sourceVerified、simulated:false、completed:true。这些verify字段由D/可信Host生成，不接受前端传true。重复resultId幂等；同gameId冲突结果拒绝并保留诊断；迟到旧branch/旧game的结果拒绝。

C把胜方team映射成整场mine win/loss/draw。B只消费**整场正式结果**，再检查challengeId/stageId/lockedProductId、双方阵容来源、完整2胜、未取消/未模拟。普通NPC模拟赛果保留后台统计通道，不能走解锁。D不直接调用B或做奖励。

领域事件建议：challengeVisitScheduled / challengeInviteOffered / challengeDeferred / challengeAccepted / seriesRegistered / roundSelectionConfirmed / officialRoundSettled / officialSeriesSettled / challengeCleared / productUnlocked / allyRecruited / allyDutyChanged。主模型提交世界后发布UI通知；内部业务事件/回执在同一个fork记录。

## 对话触发、暂停与NPC生命周期

E的 `DialogueOverlay` 消费只读offer，使用已有WindowManager可控无边框/底部样式或抽出的共用ModalLease，不创建第二计时器。业务与VM仍由Host处理。镜头只在当前游戏画面内，不把世界换成单独章节页。

B输出来访意图，由主模型映射到现有visits/navigation；E只把实体点击/接近请求发回。**不能由E把NPC瞬移到门口再自己宣布就绪**。B的触发记录必须包含sourceActorId、interactionKind、day/visitId与消费状态，主动邀请同日不重复。若关闭/Esc，挑战邀请等同tomorrow；普通谈话等同defer；必须防止关闭按钮又提交一次。

dialogue与玩家比赛拥有独立租约。对话→准备→挂载交接必须保证无空窗误推进、无泄漏永久暂停；路径接近与等待队列不持暂停。其他窗口已暂停则主动offer排队；页面隐藏也不弹。UI重建/读档后只有当前分支的窗口可响应。

## 版本、借用与迁移

新增progression命名空间建议version:1，含policyVersion/epoch/activeStageId/unlockedProductIds/challengers/invites/allies/receipts；C在比赛内有单独formatVersion/seriesVersion。具体完整schema由B/C候选提供，但共同ID和语义不能变。

challenge-loan单独记录loanId/productId/generalId/purpose/ownerActorId，**不是world.items inventoryRef**，普通资格接口不得把它当物理卡。只允许挑战或已招募伙伴训练席位引用，真实抽出/卖出/拾回才进市场。

幂等回执键依据稳定stageId/challengeId/matchId和effectId，不以新branchId逃过去重。未知命名空间版本保留并停用该新增能力；迁移前后世界、旧物品与旧比赛需能恢复。不能为了测试调用清档。

常见错误固定：FEATURE_UNAVAILABLE、NOT_ONSITE、TOO_FAR、ACTOR_BUSY、TABLE_BUSY、INVITE_STALE、PRODUCT_LOCKED、PRODUCT_RETIRED、INSUFFICIENT_ROSTER、ROSTER_LOCKED、STALE_OPERATION、PROFILE_MISMATCH、RESULT_CONFLICT、RECOVERY_REQUIRED。可预期失败返回玩家原因，不吃掉存档或导致整个经营页白屏。
