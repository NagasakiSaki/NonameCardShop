# 完整开发要求

## 1. 产品目标与本次范围

这是一款玩家扮演店长的卡店经营游戏。玩家进货密封卡包/卡盒、拆包收集武将、通过二级市场买卖单卡、经营牌桌并参加对战、挑战特殊高手解锁供货和伙伴。店内顾客会购物、拆包、弃卡、拾卡和打牌。经营、收藏、人物互动与对战必须在画面上形成一个完整的卡店生活体验。

这次前端重建同时包含**整个店铺的场景表现与操作界面**。只给弹窗换配色、保留空旷粗糙的店铺背景，不算完成。不得为了画面漂亮删减已有功能、卡面、技能预览、实物数量、保留一张上架、存档管理或真实对局入口。

用户追加要求：**场景设施全部重新绘制，画面整体明显细化。** 以下“保留协议”只指坐标、锚点、状态和业务能力，不是保留旧低细节贴图。详细风格、像素密度和逐设施验收以 04 为准。

保留 Phaser 世界与 DOM 操作界面组合。经营窗口可以精致、清晰、接近二次元游戏菜单；世界继续采用细致的像素俯视/轻斜俯视呈现，不需要把所有中文字和 UI 都像素化。

## 2. 风格优先级：明亮二次元为主，木纸为辅

### 2.1 最终画面应该是什么

- 像一间有阳光、卡牌海报、整理整齐的货架、展示柜和可爱装饰的二次元卡店。
- 颜色干净，轮廓清楚，细节丰富但有主次；角色头发、脸、衣服能分辨。
- 白天温暖通透；黄昏偏金橙；夜间窗外偏蓝紫、店内保持暖光和可读性。
- 奶油白/浅纸色是界面主体，浅原木是家具与边框材质，朱红、浅金、薄荷绿、淡蓝用于少量强调。
- 二次元人物与真实武将卡面是视觉重点；不是通用管理后台，也不是全屏棕色账本。
- 参考《东方夜雀食堂》的温暖店铺、人物存在感与经营反馈；参考早期宝可梦的俯视行走可读性。借鉴设计原则，不要求复制其贴图、UI 或剧情。
- 现有“黄纸卡册”概念只保留人物＋卡册的构图、纸张层次、局部木牌/印章。它早期偏暗的颜色不能成为最终默认主题。

### 2.2 建议主题令牌

以下是候选起点，允许同方向微调，交付时集中到 token 文件，不能逐页硬编码：

| 用途 | 建议颜色 | 使用原则 |
| --- | --- | --- |
| 页面浅底/卡片底 | `#FFF9EF` / `#FFFDF8` | 经营窗口主要面积 |
| 纸面 | `#F4E8CF` | 卡册、说明栏、任务纸签，不能全屏泛黄 |
| 浅木 | `#D7B88D` | 柜台、窗口边条、货架 |
| 木边 | `#96704C` | 小面积轮廓，避免厚黑框 |
| 正文墨色 | `#463C38` | 长技能说明和账目 |
| 次级文字 | `#75695F` | 不能浅到看不见 |
| 主操作朱红 | `#B95B63` | 确认、主要任务；与危险操作区分 |
| 金色强调 | `#E5BE72` | 收入、稀有卡、挑战奖励 |
| 薄荷/蓝 | `#8DBCAF` / `#94B8D5` | 辅助分区和状态 |

默认固定为明亮主题，不跟随操作系统深色模式自动变成黑紫色。夜晚改变世界光照，不自动把全部菜单变暗。稀有度色只用于边框、角标和短标签，不能整张面板铺成高饱和色。

### 2.3 不接受的表现

- 全屏黑紫/深棕背景、低对比度小字、厚重金边、破旧纸张遍布全屏。
- 人物只是小色块；地面重复噪点很多但家具没有可辨识细节。
- 大面积空地、家具过小、所有柜台长得一样、牌桌像餐桌且没有牌垫/座位。
- 页面像管理系统：很多表格和按钮，卡面却很小或没有卡面。
- 每块区域都有不同按钮样式、密集胶囊标签、反复点击确认、长篇技术术语。
- 为追求二次元而换掉用户已认可的角色行走效果或擅自重做人物身份。

## 3. 世界场景与美术：本轮首要交付

### 3.1 主店布局与设施辨识

在保留现有通行/交互逻辑的前提下，把主店设计成具有生活感的卡店。至少让下列功能在视觉上清楚区分：

| 设施 | 画面特征 | 点击后进入 |
| --- | --- | --- |
| 进货柜台 | 目录册、纸箱/到货标记、库存清单 | 进货 |
| 收银台 | 收银机、找零盘、包装袋 | 顾客收银/近期成交 |
| 拆包台 | 卡垫、剪刀/撕口工具、打开的包装 | 拆包 |
| 密封商品货架 | 成排包盒、主题包装、余量层次 | 零售货架 |
| 二级市场柜台 | 单卡展示夹、挂牌/卡册 | 单卡买卖 |
| 垃圾桶 | 有清楚轮廓的桶体，可看出有/无弃卡 | 弃卡/拾卡 |
| 对战房入口 | 开阔通道、招牌、可见内部牌桌 | 无缝步行通过 |

设施标识使用小木牌、清晰图案、简短中文，不要靠悬浮提示才能辨认。Hover/靠近时再显示交互范围和短提示，避免每件家具常驻大标签。

### 3.2 精致感从哪里来

- 地面至少包含主材质、分区边界和少量地毯；不要机械平铺一个深色木纹。
- 货架有包盒陈列、分层阴影、局部立牌；展示柜有玻璃高光和单卡展示，但高光不能挡住物品。
- 加入海报、盆栽、墙面展示、灯具、休息椅、纸箱、价签和店铺品牌等装饰。装饰为功能区服务，不挤占通行路径。
- 同一物体有受光面、侧面、接触阴影；避免所有家具只是一张平贴地面的矩形图。
- 用局部色彩和灯光引导“进货—拆包—上架—市场—对战”，而不是到处放大箭头。
- 世界画面不因为手账长期占据半屏而缩成一个小框。桌面默认保留充分可玩区域，经营摘要可折叠。
- 白天开门时应像“正在营业的店”，顾客、货架、牌桌状态有少量真实反馈，不需要持续播放强闪烁。

### 3.3 对战房

对战房既是经营设施，也是玩家参加考核的重要场所。增加可辨识牌垫、椅子、计分牌、灯光、卡组盒/小陈列，让桌子看起来确实用来打牌。

- 空桌、等人、准备中、对局中、结算/暂不可用至少能区分。
- 桌上状态来自 Host，只绘制，不自己计时模拟胜负。
- 高手挑战可以有特殊座位标识或紫色小旗；不能把普通桌全变成紫色。
- 等待匹配时保留简洁状态条；收起准备窗口后可继续在店里行动。
- 店长死亡但 AI 队友仍存活时，表现为观战/可接管，不提前展示失败。

### 3.4 昼夜光照

使用 Host 的游戏分钟驱动画面。白天不覆一层灰暗滤镜；黄昏有侧向暖色；夜晚窗外/边缘变冷，柜台、通道、角色脸和设施仍清楚。

不能靠给整个画面覆盖 70%～90% 黑色来体现夜间。人物名牌、交互提示和 DOM 菜单不应被世界滤镜压暗。灯光纹理要柔和，避免白色光斑糊成一团。预览必须有相同镜头的白天、黄昏、夜间对照。

### 3.5 人物与素材保留

- 保留用户认可的多方向行走、摆臂和角色细节；禁止退回低分辨率色块人。
- 不改名字对应外观的注册关系，不给原图凭空换衣服，不把侧脸误画成无脸正面。
- 店长皮肤入口保留，展示现有可用皮肤的预览；更换只请求现有动作，不改变身份/资产。
- NPC 头顶显示“中文姓名＋类别”；姓名较突出，类别次一级。高手使用适度紫色名字/徽记。
- 名牌重叠时可轻量避让/缩减次级信息，但不能随机改 NPC 名称或隐藏关键邀请状态。
- 立绘从项目 manifest/注册表获取；完整展示优先 `contain`，统一脚底/视线位置。卡面与人物立绘使用各自的裁切规则。
- 用户原始图源是 `C:\Users\lenovo\Desktop\OurNotes_BanG_Dream剧情\全部角色基础全身立绘`。项目内 `data/character-portraits.json` 和对应 assets 才是运行引用依据，游戏不能依赖这个外部绝对路径。
- 原图、派生图、像素行走图分开。不能把现有高质量立绘强行缩成 64 像素后再放大填满对话区。

### 3.6 分辨率与资源硬参数

| 内容 | 当前基线/交付要求 |
| --- | --- |
| 世界逻辑网格 | 当前 16 逻辑像素；主店 30×20 格，即 480×320 逻辑像素。不能为提高清晰度直接改导航单位 |
| 地砖 | 当前单格 32×32 对应 16×16 逻辑像素；候选建议细化到 64×64，关键墙面装饰可独立高密度图。逻辑网格不变，候选适配随交付提供 |
| 家具图集 | 当前单元格 192×192、artScale=2，含透明留白；所有设施重绘，建议有效原生细节约提升 2 倍线性密度，必要时更高。不能以透明画布大小冒充细节 |
| 行走帧 | 当前 96×128；保留已认可的方向、摆臂和步态。若细化至 192×256 等规格，锚点同步换算、世界体积保持一致，不强制无意义放大 |
| 像素缩放 | 世界像素尽量按整数采样，纹理关闭平滑；DOM 文字与高清立绘不要一律套 image-rendering:pixelated |
| 卡面缩略图 | 桌面可见高度约 150～200 CSS px；选将不低于 140；窄屏优先两列而非缩到不可认 |
| 卡牌详情大图 | 桌面约 300～360 CSS px 宽，原比例 contain，不拉伸 |
| 包装主图 | 每页一组，桌面高度 280～360 CSS px；包和盒显示不同包装资产 |
| UI 正文 | 桌面 15～16 CSS px，窄屏至少 14；技能正文建议 15～16、行高 1.7～1.9 |
| 触控目标 | 主要交互不小于 44×44 CSS px；桌面次要按钮也要易点 |
| 间距/圆角 | 用 4/8 px 间距体系，面板 16～24 px 留白；圆角约 8～12 px，局部纸签可小一些 |

如果当前图集协议无法表现新家具，可在候选中新增独立装饰层/图集适配，但不能改碰撞图、后端地图或正式注册表。交付必须说明实际资源尺寸与逻辑尺寸的换算，不能只写“高分辨率”。

分辨率是实现建议，验收依据是 04 中的真实可见细节与所有设施重绘覆盖率。不得用插值、锐化、噪点或超大 PNG 替代重新设计和绘制。

## 4. 全局 UI 与交互规范

### 4.1 信息层级

每个窗口先回答三件事：“这里做什么”“当前有什么”“下一步点什么”。一屏一个主要动作，次要动作减弱。不把组件调试信息、英文状态机、worldId、proof、价格版本默认展示给玩家；诊断信息可以放可展开的详情。

**每个可交互器具有自己的窗口。** 进货、收银、拆包、货架、二级市场、垃圾桶、牌桌分别进入对应主操作，不再默认打开一个塞满全部经营功能的综合工作台。允许通过轻量导航前往另一设施，但要沿用走近逻辑、保留草稿，不能假装站在一个柜台就能完成所有实物动作。

统一术语：进货、已入库、上架、撤下、拆包、我的收藏、二级市场、保护、收藏置顶、等待牌友、确认备战、确认本局阵容、开始本局。保护实物与选将收藏置顶是两种不同能力，不能合并成同一颗星。

### 4.2 窗口结构与滚动

- 标题与关闭按钮固定；正文只有一个明确的主滚动区域；主要确认操作在底部固定栏。
- 普通名单、交易列表、拆包结果、技能说明和长统计使用滚动，不恢复成原来的小分页。
- **特例一：卡包/卡盒商品，每页一组大商品**，正文内可滚动完整武将卡册，底部翻主题。
- **特例二：世界内对话使用逐页推进**，这是对话节奏，不是经营窗口分页。长选项必要时分组，关键选项不隐藏在无提示的下方。
- 选择/取消/保护/收藏/调数量/刷新后不跳回开头；键盘焦点也不能莫名丢失。
- 过滤条件或排序变化可以返回列表顶部；这是明确用户操作，不要与普通选中混淆。
- 同一世界分支内关闭再打开尽量保留草稿；读档切分支后清理旧选择、旧报价和待提交操作。
- 只有代码面板、特殊大表格允许横向滚动；普通经营页不能横向溢出。
- 不靠隐藏 overflow 掩盖适配问题；底部确认按钮、弹出的数量控件和浏览器缩放后内容都必须能到达。

### 4.3 输入与弹层

- 鼠标、触控、键盘完成同一核心流程。Esc 只关闭最上层，点击弹层不会让人物在后面走动。
- 输入框中 WASD/空格不触发角色移动；对话/窗口状态切换后不能残留移动键。
- 卡面右键统一查看技能；触屏和键盘另有可见“详情/技能”入口，不能只有右键才能看。
- 明确 hover、按下、选中、禁用、提交中、成功、失败、结果待确认状态。
- 不可操作时说明具体原因和可执行的下一步，例如“请先到拆包台”“可用收藏不足 5 名”。
- 小操作不连续弹多个确认框；付费、整场认输、覆盖/删除存档等保留必要确认。
- 切页面不丢进行中请求；重复点击不得重复扣款、开包、报名或解除保护。

## 5. 经营核心页面

### 5.1 世界 HUD 与快捷操作

- 顶部显示日期、游戏时间、营业状态、可用现金；暂停时显示“正在操作/已暂停”及明确原因入口。
- 现金、营业收入、利润、对局输赢分别表达，不能拿钱包变化当营业额。
- 显眼但不挡场景的实时流水：来源、金额正负、简短动作；可展开当日明细。
- 每日任务较简洁，完成奖励自动到账，提示“已自动领取”，不新增强制领奖按钮。
- 常用入口：进货、仓库、拆包、收藏/市场、牌桌；其他管理入口归类，不排满两行小按钮。
- 地图快捷入口触发既有走近逻辑；远处可以看，实际交易仍受柜台站位约束。

### 5.2 进货

- 每页只展示一个主题包装，包/盒切换保持当前主题，不能暗中换主题或重置数量。
- 大图、名称、当前进货价/建议售价、库存和货架余量、数量步进、金额小计为第一层。
- 当前解锁状态和下次高手挑战提示清楚；锁定商品可看图鉴，不能伪装成可购买。
- 详细区展示整盒固定张数、比例、散包小保底、卡盒大保底、完整带图武将卡册。
- 所有出率区分“单卡比例”“整盒固定张数”“每包平均”“散包至少一张”。不能把平均张数写成必出。
- 购物篮显示主题、包/盒单位、数量、逐行小计、总计；现金与授信若涉及，分别显示。
- 下单成功即显示真实“已入库”和数量，提供“去仓库/去拆包台”；不得重新引入不必要的等待签收流程。
- 旧到货订单如仍存在，作为折叠兼容项处理，不抢占新采购主流程。
- 散包档位目前约 210/360/510，进货约 150/255/360；这些只是现状说明，UI 必须读 DTO，不能硬编码价格。

### 5.3 仓库与零售货架

- 按主题、版本、包/盒聚合，`×数量` 清楚；可用量、受保护、占用和在架分别显示。
- 每页一组大商品；显示原印刷配比，不能拿今天配比覆盖旧库存。
- 上架前显示本次件数/货架容量，补不满时说明放入多少；保留一键上架/补货的已有能力。
- 店铺明面只卖密封包和盒，单卡卖出入口引导到二级市场。
- 若动作当前只改“首件价格”，必须说清楚；不能把现有单件命令包装成“所有库存统一改价”却只改一件。
- 收银页偏向顾客购买反馈和近期成交，既有自动结账不改成人工逐单点确认。

### 5.4 拆包

- 独立拆包台窗口，不与收银混在一起。支持开一包、按数量、开盒和一键开全部的既有能力。
- 显示将使用的真实库存数量和预计卡数，排除受保护/占用/未允许的货架库存。
- 开包动画可以是撕口、翻卡、光效和音效，但不阻止快速跳过；大量开包直接进入完整结果。
- 获得结果卡面为主体，SSR/SR 有适量强调；同名同印刷可合并 `×n`，原实物引用仍保留。
- 一键“每种保留一张，其余上架”展示后端预览的排除量/手续费；已挂单和受保护不会再卖一次。
- 抽卡结果不能先由前端随机、再让后端对账；动画只展示真实回执。

### 5.5 收藏与二级市场

- 收藏以大卡面网格浏览，数量清楚，支持搜索、稀有度、重复卡、保护、在售等现有筛选。
- 选中不刷新整窗；桌面旁侧展示大图、持有与可售量、参考价格、主要动作。窄屏可进入详情层，返回保持位置。
- 买卡、本店挂单、卖收藏、求购报价、行情记录视觉上分清，避免把“挂出去了”误写成“卖出到账”。
- 印刷稀有度、当前强度分级分开；受保护/已占用/在售状态不能只靠颜色。
- 金额输入限制整数，显示最终成本/费用和数量；以实际询价回执为准。
- 所有卡面右键可看技能，缺卡图时保留姓名、稀有度和详情按钮，不能出一堆裂图。

### 5.6 卡牌详情

- 卡面大图、姓名、印刷信息、当前分级、技能全文、体力/势力等真实资料有清楚层级。
- 三模式评分及全局平均分清楚；斗地主可显示地主/农民分。注明规则估算不是官方排名或实测胜率。
- 实际场数/胜率与估算分分别显示，数据不足用“暂无战绩”。
- 源码是折叠高级区，默认先让玩家读技能；源码只按需加载，允许横向滚动，不影响整个窗口。
- 切换卡牌时，迟到的旧响应不能覆盖当前卡片详情。

### 5.7 垃圾桶

- 展示真实弃卡、卡面、数量和可拾取状态；可弃自己的卡，也能拾回尚在桶内的卡。
- 提示“次日清空”，不能提供已经不存在的历史弃卡取回。
- NPC 拾走导致列表变化时保留合理位置，提示“刚被拾走”，不把库存冲突当网络故障。
- 弃卡/拾卡/流入市场均由后端决定，UI 不自行增加卡片或改流通标记。

## 6. 三模式房间与选将：不能倒退的核心

### 6.1 当前规则

| 模式 | 每方备战 | 单局出场 | UI 必须说清楚 |
| --- | ---: | --- | --- |
| 1v1 三将接力 `kof` | 3 | 双方各 1，依次接力 | 顺序重要；阵亡换将重新摸四张；不继承手牌；不是再打一套 BO3 |
| 斗地主换边 BO3 `doudizhu-bo3` | 5 | 地主方 1、农民方 2 | 先两胜；有胜负后换边；玩家主将与 AI 队友标明 |
| 2v2 BO3 `versus2v2-bo3` | 8 | 每方 2 | 玩家主将＋AI 同伴，按队伍胜负，先两胜 |

不再展示独立单将 1v1 BO3。不要因为老类型文件还出现 `bo3` 就把它重新加回来。模式入口、可用原因由 `combat.formats` 返回，不硬造第四模式。

### 6.2 房间页面

- 清晰的三张模式卡或三段选择，显示备战人数、对局结构与当前可用性。
- 房间显示对手、桌费、准备状态、固定公开备战池、当前比分和等待说明。
- 创建后先看对手整场备战池，再选自己；对手池不能被 UI 随机刷新。
- 桌费修改和原等待报名保留，旧等待报名仅是三将接力入口，不假装支持全部模式。
- “收起房间，继续经营”是收起窗口，不能等同取消报名/整场认输。
- 对方未到/持卡不足/已在别桌等情况有真实解释，不填充虚构 NPC。

### 6.3 整场备战与本局选将

- 两个阶段明确：先选满 3/5/8 名整场池并确认，再从固定池选本局阵容。
- 全部卡片连续滚动，显示卡面、姓名、技能入口、数量/占用、收藏置顶、模式不兼容原因。
- 底部固定已选栏＋确认按钮；KOF 显示 1→2→3 顺序，拖动调整如缺真实协议只能作为确认前草稿处理。
- 斗地主本局必须按实际身份选 1 或 2 名，第一名为玩家主将，第二名为 AI；不能把所有情况写死为选两张。
- 2v2 标明主将、AI 同伴，不要误导为玩家同时直接操控两个席位。
- 选中/取消不跳到列表顶部，不重新弹窗；关闭技能详情后原选择和滚动位置保留。
- 确认后显示“阵容已锁定”、实际上场姓名与身份，底部提供清楚的“开始本局”。
- 模式、阵营、选将、锁定、引擎载入、进行中、结算、下一局和中断恢复每个状态都有画面。

### 6.4 引擎与接管

- 原生引擎嵌入区域独立，不让大立绘、说明栏或装饰覆盖出牌/确认按钮。
- 保留现有队友接管/交还功能，状态说明明确；AI 同伴仍活着时可观战，不能提前判负。
- 原生模式不兼容、加载超时、技术中断有返回/重试当前小局入口，不能编造胜负继续下一局。
- 经营时间、整场结束后推进 30 分钟、比赛结算全部沿用后端。NPC 之间对局不因“在打牌”暂停世界；玩家打开交互窗口仍按窗口暂停规则处理。

## 7. 角色对话、高手与剧情承载

- 对话框在世界内底部出现，保留店铺背景，角色立绘、姓名、身份、正文、选项有层级；不再以外置章节目录充当主剧情。
- 对话默认逐页；点击/键盘继续、返回/拒绝、选项状态可读。长选项完整显示。
- 紫名高手来主动约战，显示姓名、目标主题、可选模式、胜利奖励；“接受挑战/明天再来”表达清楚。
- 正在操作/对局时，邀请排队，不强行覆盖；延期、战败再约和次日回访由真实状态驱动。
- 点击普通 NPC 可以走近、交谈/约战，目标已离店则取消旧动作并提示。
- 伙伴页显示已解锁人物、擅长岗位、当前上岗/休息和实际收益说明，调岗请求原接口。
- 本轮不创作完整长剧情；只提供可承载说话人、表情/立绘、正文、选项、条件禁用、奖励摘要的呈现组件。暂无数据的情绪/好感度不要伪造。

## 8. 存档、管理与帮助

- 游戏开始前有漂亮且易用的新建店铺、继续、存档管理；创建新档不能清空整个站点数据库。
- “回到某天开店时”和“读取精确时刻备份”分开，显示实际可读日期，不把备份冒充日初档。
- 删除某个店铺须明确确认，不使用一个模糊的“重置全部”。
- 经营管理、熟客、伙伴、任务、日报、设置按同一视觉系统统一，常用数据先于配置项。
- 日报至少分收入、成本、经营利润、对局净额、现金变化，缺失历史数据不能当零。
- 任务自动领取保留，经营建议基于真实数据；帮助页提供关键快捷键、柜台区别和玩法说明。
- 编辑配置/诊断放高级入口，普通玩家不必理解模块名、模拟器和适配层。

## 9. 扩展性与实现质量

- 主题令牌、组件和页面分离；按钮、卡面、商品展示、窗口、数值/状态标签复用。
- 世界环境、装饰与灯光使用明确配置层；未来加店外街道只新增视图/配置，不复制另一套计时和导航系统。
- 模式、主题、角色、岗位尽量由 DTO 驱动，新增内容不修改大量页面条件分支。
- 页面采取 `mount/update/getDraft/dispose` 或等效协议；销毁时释放监听、动画、计时器和观察器。
- 大卡册图片懒加载，单次更新不重建所有未变卡面；不在每帧遍历完整卡库或重读全部资产。
- 预览默认只加载当前场景/当前页面需要的资源；高分辨率角色原图按需加载，避免一次加载全部原图。
- 新增素材交付可编辑来源、生成脚本/参数及授权记录；不能只交一张压平大截图当场景。
- 文字、价格、库存、比分和任务进度是真实文本，可选择/适配；不要烘焙进图片。
