# 验收与交付清单

这份清单用于前端候选自检与主模型合并。每项标“通过 / 不通过 / 未做 / 需主模型接线”，并链接截图、测试或具体文件。没测不能写通过，Mock 通过不能写正式接入通过。

## 1. 交付前的工作基线

- [ ] 记录实际项目路径、起始 HEAD、修改/新增候选文件；确认只写 `deliverables/frontend-bright-anime/`。
- [ ] 阅读当前 `app-shell.mjs` 路由，确认默认入口与 classic/previous/mock 不同。
- [ ] 读取全部 props 登记、两个房间、角色与包装 manifest，形成覆盖表。
- [ ] 查看 04 中官方参考画面，提供借鉴点和自己的美术方向对照板。
- [ ] 以当前行为为基线，列出原先已能使用的功能；改版后不能无说明删除。

## 2. 画面与场景验收

- [ ] 主店默认白天明亮、干净、精致，二次元氛围明显；不是暗棕/黑紫大面板。
- [ ] 对战房同风格，牌垫、座位、计分/状态、通道能辨认，不像空大厅。
- [ ] 当前全部设施及已有状态完成重绘，ASSET-INVENTORY 覆盖 100%；无空白/旧图冒充。
- [ ] 主店的进货/收银/拆包/二级市场四柜台一眼可分，不依赖一串悬浮标签。
- [ ] 货架空少满、升级、展示柜购买前后、牌桌等级/状态、员工在岗/休息均有对应新图。
- [ ] 地面、墙、门、窗、植物、软装与家具一致；精细度通过有效结构体现，而非重复噪点。
- [ ] 白天/黄昏/夜间同镜头对比，夜晚店内仍能看清人物、设施和路径。
- [ ] 旧新图同尺寸对比和实际游戏缩放对比均能看到细化提升。
- [ ] 图集脚点、遮挡、人物前后关系正确，贴图没有改变碰撞/交互范围。
- [ ] 角色行走保持原有效果，正脸/侧脸、眼睛、衣服摆臂无明显退化；中文姓名＋类别可读。
- [ ] 立绘真实来源清楚，不模糊、不拉伸、不无故裁脸/脚；缺图优雅降级。

## 3. 页面适配与滚动

至少检查：1440×900、1280×720、900×620、390×680。桌面再检查浏览器 125% 缩放。先测这些代表尺寸，发现具体问题再加边界尺寸，不为每个小样式反复跑全项目。

- [ ] 标题、关闭、主要确认可到达，没有 overflow:hidden 截断操作。
- [ ] 正文一个主滚动区；滚动时不把场景一起滚走；底部操作不会盖最后一排卡。
- [ ] 卡片选择、取消、数量变化、收藏、刷新、查看详情后滚动不跳回开头。
- [ ] 异步清空再渲染也能恢复位置；关闭窗口后没有残留监听/锁。
- [ ] 窄屏不把卡面缩成图标；必要时两列/单列，按钮至少易点。
- [ ] 横向无意外溢出；源码/大表的局部横向滚动不影响整个界面。
- [ ] 键盘焦点、Enter、Esc、触控入口可用；输入框不触发人物移动。
- [ ] 经营弹窗点击不穿透到世界；关闭最上层详情不会顺带关闭主窗口。

## 4. 核心经营闭环

- [ ] 新建独立测试店铺，不清真实用户档；启动菜单能返回和管理档案。
- [ ] 进货每页一组大商品，切包/盒不串主题，数量/金额/解锁原因清楚。
- [ ] 完整武将卡册带图片、可右键技能；比例/每盒张数/散包概率标签正确。
- [ ] 下单成功用真实回执显示“已入库”，现金/授信展示正确，不额外造第二单。
- [ ] 仓库按主题/版本/单位显示，旧库存按原印刷规格，不泄露密封结果。
- [ ] 上架/撤下/改价/补货受容量、站位、保护/占用限制；明面不卖单卡。
- [ ] 收银保持自动结账，近期成交与流水金额可读。
- [ ] 拆包台独立；单包/按量/卡盒/全部开可用；跳过动画不丢结果。
- [ ] 结果合并数量准确，保留一张其余上架遵守真实预览与排除项。
- [ ] 收藏/市场的大卡面、持有量、可售量、挂单/成交区别、搜索和保护正常。
- [ ] 背包、选将、卡册、拆包、垃圾桶等所有经营卡面右键均打开技能详情。
- [ ] 垃圾桶拾回、NPC 已拾走的库存变化、次日清空提示正确；不复制卡片。
- [ ] 实时流水显眼但不遮挡，营业额/利润/现金变化各自口径清楚。

## 5. 牌桌闭环

- [ ] 正式房间仅三种模式，可选择且能说明不可用原因；没有独立单将 BO3。
- [ ] 创建后能看对方固定整场池，切回不会重抽或篡改。
- [ ] KOF 选 3、斗地主选 5、2v2 选 8，连续滚动多选不丢、不重复同一武将。
- [ ] 125% 缩放/短屏时，“确认整场备战”“确认本局选将”“开始本局”始终可达。
- [ ] 斗地主正确区分地主选 1/农民选 2，AI 队友标识正确；2v2 主将/AI 正确。
- [ ] 确认后显示实际锁定阵容，不允许继续改选但仍有明确开始入口。
- [ ] 引擎载入区不被 UI 压没，加载/失败/中断恢复完整呈现。
- [ ] 原生能力不足不会假装启动；不从前端按钮伪造胜负或跳过小局。
- [ ] 队友接管/交还、观战、下一局、换边、整场结果和取消/认输各状态清楚。
- [ ] 等候可收起并继续经营；收起与取消区分；桌费可调，不误称所有入口均支持多人模式。

## 6. 人物、对话、存档与管理

- [ ] NPC 点选、远处走近、目标离开处理正常，不瞬移/重复触发。
- [ ] 高手邀请在空闲时显示，忙时排队；接受/延期不重复提交。
- [ ] 世界内底部对话有立绘/姓名/正文/选项，长文本逐页，重要选项可见。
- [ ] 伙伴列表/岗位/休息使用真实数据，不虚构好感或收益。
- [ ] 每日任务完成自动领奖，无重复奖励按钮。
- [ ] 日初档与精确时刻备份分开；读档后旧窗口、旧报价与旧分支请求全部失效。
- [ ] 删除单个档案有清楚确认，不清全站数据库。
- [ ] 日报、管理、帮助、皮肤与设置使用统一明亮样式，边缘页不是旧暗色残留。

## 7. 必须演示的异常状态

用隔离 fixture 可演示，不能在用户真实存档中制造故障：加载中、空库存、无卡面、无技能、商品锁定、库存不足、货架已满、站位不足、卡片占用/保护、报价过期、网断/结果未知、重复点击、关闭时响应迟到、读档切分支、对手离开、原生模式不可用、引擎载入失败。

每类异常都应提供能继续操作的入口，不能留一块空白或一个永久转圈的按钮。

## 8. 性能与资源检查

- [ ] 卡册/卡面懒加载，不一次请求完整人物高清图库。
- [ ] 典型营业场景和长卡册滚动顺畅，记录机器/浏览器/画布尺寸/同时在场 NPC 数。
- [ ] 以 1080p 桌面接近 60fps 为目标；达不到时给测量、瓶颈和降级方案，不伪造保证。
- [ ] 切换窗口不不断增加纹理、监听器、定时器或后台动画；连续操作后无明显泄漏。
- [ ] 图集合理拆分，列原生尺寸、压缩大小、估计解码内存；重绘清晰度不靠超大空白画布。
- [ ] 错误控制台无本轮新增未处理异常；网络失败与业务失败均可恢复。

## 9. 最终必须交付的材料

1. 一条可运行隔离预览的命令和 URL；显著标“候选/演示”，可切换主要状态，不加载真实用户档。
2. 按目标路径组织的源码与素材、最小接线补丁，以及每个页面的 mount/update/dispose 或等效接口。
3. 全量 ASSET-INVENTORY.csv、可编辑源/绘图脚本、图集映射、状态矩阵、资源来源说明。
4. 至少这些截图：主店旧新对照、白天/黄昏/夜间、对战房、设施全状态联系表、大包装卡册、拆包结果、收藏/市场、锁定选将、角色对话、启动菜单；关键页另有短屏/窄屏截图。
5. 核心操作的浏览器验证或短演示记录，至少覆盖滚动保持、确认可见、卡面右键、数量变化和异常恢复。
6. FILE-MAP.md：新增/替换/共享文件、资源映射、需要主模型修改的正式入口，不是笼统“覆盖目录”。
7. API-GAPS.md：真实数据/类型/素材协议缺口；没有也要写明；禁止新增业务能力却不登记。
8. DELIVERY.md：逐项标完成状态，区分候选实现、Mock 通过、正式 adapter 已准备、正式接入待主模型验证。

只交图片、只交设计稿、只交一套无法接入的网页、只交 Mock，没有完成本任务。没有权限跑真实后端时可以交完整同形 fixture 和接线候选，但必须如实标明这一验证边界。

## 10. 主模型整合责任

主模型检查候选差异与素材协议，决定合入文件；连接真实 Host/引擎，检查地图几何和状态、交易原子性、日档/分支、时间与 NPC 生命周期，再做一次有针对性的正式回归。

前端模型不自行合并、提交、推送、更新 EXE 或宣布正式版本已完成。这样保证它可以连续独立产出，主模型仍保留工程最终一致性。
