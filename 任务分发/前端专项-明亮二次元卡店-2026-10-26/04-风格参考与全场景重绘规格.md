# 风格参考与全场景重绘规格

本文件补充用户最后的美术要求，优先于此前“保留旧资源协议”的保守理解：**主要风格是二次元；整个场景明亮、精致；像素画需要明显细化；场景所有设施全部重绘。**

“像素数大幅提升”不是要求机械放大所有 PNG，而是要求造型、结构、材质和人物特征有足够的真实像素去表达。不能把数值很大的模糊图片当交付。

前端模型应先看上述官方图源，制作自己的对照板：每个参考截取或链接少量对应画面，标注具体借鉴点，再给出本店的独立实现。截图仅放设计研究/验收文件，不能烘焙成游戏素材。不要只写几个作品名却没有实际视觉分析。

最终方向可以概括为：**明亮的二次元生活感＋精细像素室内＋现代卡店设施＋局部浅木/淡纸 UI。** 早期宝可梦仅用于行走和俯视可读性参考，不是让画面继续停留在低细节掌机规格。

## 2. 细化验收：哪些地方必须真的变好

同一镜头、同一缩放下对比旧版，新场景必须能直接看到这些变化：

- 柜台能看出柜面厚度、边角、不同材质和用途，而非一条双色长方形。
- 货架能看出层板、包盒排列、主题区域、标签、小立牌与空位；低库存与满库存有明确差别。
- 卡盒有盒体、开口/封装结构、陈列朝向；散包是薄包装，不与卡盒只是同图换字。
- 拆包台有桌垫、工具、打开的包装、卡片整理区域，整体一眼能识别。
- 收银台有收银机/屏幕、找零盘/扫码或包装区域；进货柜台有目录/纸箱；二级市场有单卡陈列；四种柜台不是同一个底图换标牌。
- 牌桌有桌边、牌垫、座位、牌组盒、桌号/状态细节，方向/遮挡一致。
- 垃圾桶有桶口、桶盖/桶壁和卡片露出状态，不能看起来像一个无说明黑方块。
- 墙面、窗户、入口、灯、海报、展架、植物、地毯都有完整轮廓与接触阴影，形成有层次的空间。
- 人物在场景里仍是视觉主体，细节不能全挤到背景纹理上导致脸和服装更难认。
- 装饰不是随机散点；每个功能区有明确视觉中心，通道留白，顾客走动时仍清楚。

至少提供“原图裁片 → 新图原生 1:1 → 新图放大检查 → 游戏实际缩放”四种展示。只交放大截图、不展示实际游戏效果，不算完成。

## 3. 所有设施重绘：按登记项逐一交付

### 3.1 范围基准

当前 `assets/frontend/manifest.json` 的 `props.list` 有 **76 个登记项**，含通用道具、正式设施、库存/升级状态、桌位状态与员工状态。开工时重新盘点；项目后续新增的登记项也要记录。

本包提供 `references/现有设施登记基线.csv`，只是基线清单，不代表已完成重绘。最终交付必须有对应的新资产和状态覆盖，不得删除登记项、改成透明图或悄悄保留旧粗糙图来达成“全部”。

### 3.2 具体重绘系列

| 系列 | 当前登记例子 | 必须覆盖 |
| --- | --- | --- |
| 四大柜台 | `pa_counter_procure/cashier/market/opening` | 进货、收银、单卡、拆包，功能特征完全区分 |
| 员工柜台状态 | `pa_counter_cashier_*`、`pa_counter_stocker_*` | 未雇佣/在岗/休息三状态，人物/标记不遮住实际 NPC |
| 货架 | `shelf`、`pa_shelf_empty/low/full` | 空/少/满，层板与包盒数量可辨 |
| 货架升级 | `pa_shelf_upgrade_before`、`pa_shelf_lv0..3_*` | 所有等级和空/少/满组合；升级有结构/陈列变化，不仅换颜色 |
| 包盒陈列 | `display_packs/boxes`、`pa_display_packs/boxes`、`pa_box_rack` | 散包、卡盒、盒架各自形态 |
| 收藏展示柜 | `pa_cabinet_collect`、`pa_showcase_lv0_unbought/lv1_bought` | 购买前后、玻璃/柜体、单卡展示，装饰不过曝 |
| 对战桌 | `table`、`pa_table_idle/reserved/sim/end` | 空闲/等候/进行/结束四状态 |
| 牌桌升级 | `pa_table_lv0..2_*` | 三等级×四状态，升级可识别且牌桌尺寸一致 |
| 垃圾桶 | `trash`、`pa_trash` | 桶体完整、弃卡存在状态可展示；无数据时不编造新状态 |
| 座位与休息 | `chair/bench/sofa/tea` | 与主店色彩、透视和家具尺度一致 |
| 装饰与品牌 | `board/poster/sign/trophy/clock/speaker/pa_wall_display` | 清楚且不过度抢眼；招牌/价签文字用独立文本层 |
| 灯具/植物/软装 | `lamp/plant/rug/door_mat/pa_lamp_hang/pa_rug_round` | 形状、阴影、接触点、昼夜效果一致 |
| 其他登记项 | `counter_retail/service/register/case_stack/kiosk` 等 | 全量清单中未归类的项也要交，不得漏掉 |

如果两个旧 ID 实际是同功能别名，可以映射到同一份**新绘制**资产，需在表中说明；不能把不同功能/等级/状态全部映射成一张通用图。

### 3.3 场景基础也要更新

设施重绘之外，主店与对战房的地砖、墙、窗、门、分区地毯、指示牌、光影和装饰层要一起统一。只把新家具放在旧黑暗底图上不算场景完成。

首轮尽量保留当前功能区、通道与交互范围，靠造型、陈列和装饰改善空旷感。如果提出布局重排，交可视布局和导航变更申请，由主模型统一接入，不能破坏通行。

## 4. 美术密度和尺寸：有目标，不唯数字

以下是本项目建议工作规格，**不是所参考商业游戏的原始素材规格**：

| 类别 | 当前 | 新候选目标 | 不可替代的真实要求 |
| --- | --- | --- | --- |
| 地砖/墙面基础格 | 32×32 原图/16逻辑格 | 建议 64×64/16逻辑格 | 重新绘制纹理、边角、连接与明暗；不能单纯 nearest 放大 |
| 家具统一单元格 | 192×192，含留白 | 建议 384×384；关键大设施可用 512 级独立图 | 物体有效区域有新增结构和材质细节；不能只增加透明画布 |
| 角色行走 | 96×128/帧 | 有真实改善时可细化为 192×256/帧 | 保留步态、方向、摆臂；五官、头发和服装在实际缩放下清楚 |
| 高清对话立绘 | 项目已登记的用户原图/派生图 | 桌面呈现高度约 400～650 CSS px，使用足够清晰的原比例源图 | 不重采样成糊图，不把腿/头无故裁掉，不重复低清压缩 |
| 卡包/卡盒包装 | 项目现有包装 | 建议有效高度 512～768 原生 px | 结构清楚、主题区分、包盒不同；读取真实名称 |
| UI 小图标 | 现有不统一 | 24/32 CSS px 显示，48/64原生或 SVG | 单一风格、常用图标一眼能懂 |

这是大幅细化的起点，不是禁止更高质量方案。若 2 倍线性密度仍无法表达关键设施，可再提高；如果更低尺寸已能精确表达，必须用实机对照证明，而不是为了省事全部沿用旧图。

增加像素必须对应更多有效细节。禁止只使用插值放大、AI 超分后不修边、噪点贴图、锐化光晕或摄影材质叠加。允许程序化绘制、可编辑像素工具、分层插画转像素等方式，但都须检查边缘、调色、方向、实际缩放和设施识别。

## 5. 逻辑尺寸与美术尺寸分离

美术变清晰不等于柜台在世界中变成两倍大，也不等于人物移动更慢。

- 地砖从 32 升到 64 时仍对应 16 逻辑像素；候选渲染读取 frameSize/缩放比例。
- 家具从 192 升到 384、原逻辑大小不变时，artScale 从 2 相应变为 4；实际脚点/锚点同步换算。
- 角色帧从 96×128 升到 192×256 时，原生锚点乘 2，显示缩放相应除 2；不能只改 frameWidth 导致头脚位置漂移。
- 逻辑碰撞格、站位、交互距离、出口和地图世界偏移不因高清图重算。
- 设施看起来变大/变小若确有必要，注明目标可视矩形、脚点、占地和交互提示范围，由主模型确认几何同步。

高精度源图若在游戏里仍被缩成极小色块，也不算效果完成。默认镜头需让人物、柜台和牌桌有足够屏幕尺寸；优先折叠冗余侧栏、优化相机和场景占比。必要的视图缩放调整放候选补丁，不改移动速度和后端坐标。

## 6. 风格统一与动画

- 地面、墙、家具、角色遵守同一投影方向、受光方向、描边粗细和色彩明度，不拼出互相矛盾的素材包。
- 保留偏俯视的可读性，家具的立体厚度适量；不要突然把场景改为等距斜45度导致现有移动与遮挡失真。
- 接触阴影轻且柔和，不要每个物件下放一个黑色大椭圆。
- 窗外的光、灯、短促收银/上架/开包反馈可动画化，避免整店持续漂浮发光。
- 动态只表现真实状态；有货/缺货、店员在岗、桌上进行中等从 DTO 读取。没有新的业务数据时，不为动画造新状态。
- 行走帧必须逐方向检查：正脸眼睛对称合理，侧脸正确、衣服与手臂分层，脚步与身体一致，不能衣服糊在身体前遮住摆臂。

## 7. 素材可维护性与性能

全部资源要有可编辑来源：分层文件、像素项目或可重复生成脚本之一。每次生成必须可定向输出到候选目录，不覆盖正式资产。

`ASSET-INVENTORY.csv` 至少列：原ID、功能/状态、旧路径、新路径、原生宽高、逻辑宽高、锚点、图集页/帧、重绘方式、来源/授权、预览位置、完成状态。

- 不把所有高清设施/人物塞进一张超大图；图集页建议不超过 4096×4096，低端设备可再拆 2048。
- PNG 透明边缘无白边/黑边；图集帧留合理隔离，避免缩放串色。
- 不在启动时一次性解码全部角色高清立绘；按当前画面需要加载并复用。
- 纹理缓存有上限/释放策略，不在每次开关窗口重复解码同一图。
- 交付测量实际图片尺寸、加载字节、主要图集展开内存估计（宽×高×4）和关键页面表现，不只报压缩后文件大小。
- 高分辨率带来的渲染适配完整交付，不把“主模型之后自己想办法”当完成。最终正式修改由主模型审阅安装。

## 8. 美术交付完成条件

1. 所有当前设施登记项与状态都有新图/新映射，覆盖率 100%，没有静默保留旧图。
2. 主店和对战房完整重绘后的实机画面，白天/黄昏/夜晚均可查看。
3. 设施对照图能看出结构与细节提升，不是只有色温变化。
4. 正常游戏缩放下人物、柜台、包盒、牌桌和垃圾桶均可辨识，世界不是被菜单挤小的背景。
5. 脚点、遮挡、点击、站位和通道正确；不为美术牺牲操作。
6. 资源源文件/脚本、映射、尺寸换算、预览、性能记录和未完成项完整可移交。
