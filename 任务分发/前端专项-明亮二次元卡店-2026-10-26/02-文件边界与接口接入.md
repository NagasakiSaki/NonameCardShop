# 文件边界与接口接入

## 1. 分工与工作位置

前端模型负责候选 UI、整个场景的表现、设施素材、视图组件、样式、状态呈现和适配提案；主模型负责后端规则、数据一致性、地图导航、无名杀桥接和最终工程合并。

**正式工程只读，候选只写 `deliverables/frontend-bright-anime/`。** 本约束用于避免与主模型和已有交付同时覆盖文件，不要求前端停止等待接口。缺口可以用严格同形 fixture 继续做，再登记给主模型。

建议交付结构：

```text
deliverables/frontend-bright-anime/
  README.md                       # 运行入口、实现范围、版本基线
  DELIVERY.md                     # 完成项/未完成项/正式接入状态
  FILE-MAP.md                     # 候选路径→目标路径
  API-GAPS.md                     # 真实缺口；没有就明确写无
  ASSET-INVENTORY.csv             # 每项原资源/新资源/状态/锚点/来源
  src/                           # 按计划合入后的项目相对路径组织
    frontend/...
    frontend-next/...
    assets/frontend-bright-anime/...
    tools/...
  preview/                       # 隔离预览与同形 fixture
  integration/                   # 接线说明、建议补丁、只读类型补充
  tests/                         # 本轮有价值的浏览器检查
  evidence/                      # 截图、对照、测量与日志
```

不改其他 `deliverables/` 子目录，不读取用户密钥或浏览器档案；不要删除/迁移用户存档，不启动另一个写同一真实存档的页面。不要运行 art:install、导入脚本或其他会覆盖正式素材/注册表的命令。

不改 `package.json`、锁文件和正式启动端口。候选若需独立预览服务，默认 5193，端口占用则明确换空闲端口；不得为了测试停掉 5190/5191 的游戏。直接使用现有 Node/浏览器/Playwright 和项目绘图工具，额外依赖应隔离并说明。

## 2. 真实工程入口：防止改错版本

主入口为 `frontend/index.html` → `frontend/main.mjs` → `frontend/app-shell.mjs`。`frontend-next` 不是独立另一个应用；当前正式游戏会按窗口路由加载其中一部分。

`?mode=mock`、`?tradeUI=classic`、`?tradeUI=previous` 会走旧路径。它们可用于核对历史功能，不能当当前默认版本，更不能只改这些页面后宣称正式界面完成。

| 当前功能 | 当前主要入口/文件 | 前端模型应交付 |
| --- | --- | --- |
| 应用壳与入口路由 | `frontend/app-shell.mjs`、`main.mjs`、`index.html` | 新壳样式与布局候选、最小接线补丁；不自行重写启动/Host |
| 世界场景 | `frontend/scenes/world-scene.mjs`、`world/actor-view.mjs`、`world/lighting-view.mjs` | 美术渲染适配、灯光、装饰、名牌候选 |
| 世界素材 | `assets/frontend/manifest.json`、`maps/store.json`、`maps/battle-room.json` | 新素材与候选映射；地图碰撞/交互点不动 |
| 绘图与设施状态 | `tools/frontend-art/`、`tools/frontend-art/facility-states/` | 新绘图脚本/可编辑源及状态完整覆盖 |

表中是阅读与接入定位，不是允许直接覆盖正式文件。候选对共享入口/窗口管理器的修改放 `integration/` 补丁，由主模型审阅合并。

## 3. 不允许前端改动的内容

- `modules/backend/**`：钱包、报价、库存、出货、NPC、暂停、时钟、存档、剧情、评分与赛果规则。
- `integration/**`：真实 Host 和无名杀引擎桥；尤其 `modes/`、`round-plan`、受信任消息、队友控制协议。
- `vendor/noname/**`、`desktop/**`、`dev/**`、`server.mjs`：内核、EXE、启动服务、发布和运行环境。
- 正式 `contracts/**`、`data/**`、`content/**`：业务类型、规则、注册表、地图/剧情内容。
- 真实数据库/localStorage/IndexedDB 的业务值。UI 偏好可以独立保存；不直接写库存、资金或关卡进度。
- 正式地图的 `mapId/navVersion/tileSize/width/height`、碰撞格、出口、站位、交互 ID、桌 ID 和坐标协议。

如果新美术确实需要家具移位或分图集，提交候选映射/布局变更说明和理由；主模型统一同步可见位置、点击区域、导航、交互距离与站位。不要只移动图像让玩家对着空地交互。

## 4. 权威接口与历史文档差异

依次核对：当前正式 screens 适配 → `modules/backend/runtime.mjs` 实际分发 → contracts 类型/说明 → 老交接文档。

当前有些历史说明仍提到四模式、19 主题、延迟收货、旧 bo3 字段。这些是历史记录，不得回滚当前行为。`contracts/operations-v7.d.ts` 仍有旧 `bo3` 类型字面量，本轮前端以实际 `combat.formats` 和 `docs/architecture/三赛制与定价规则.md` 为准，并在 API-GAPS 中标明类型差异，不能自行改正式契约。

接口失败必须保留失败语义，不能把 `{ok:false}` 变成空数据并假装“暂无内容”。

```js
// 现有 Host 协议示意；由正式 screen/adapter 调用。
const result = await host.query('products.list', {});
// 成功：{ ok: true, revision, data }
// 失败：{ ok: false, error: { code, message, retryable, details? } }

await host.command({
  requestId: stableOperationId,
  type: commandName,
  payload,
  // 需要时在顶层保留 quoteId / previewId
});
```

金额为整数游戏币；概率 0～1；卡牌与实物 ID 都是不透明标识。不能根据中文名字、文件名或卡图 URL 自行生成 cardKey/inventoryRef。

### 5.1 新的商品卡册查询

`products.contents({productId})` 返回 `productId/productVersion/themeName/cardsPerPack/packsPerBox/boxCounts/packAtLeastOneProbabilities/guarantees/items`。

- items 有真实卡面摘要、`inPool`、`printedRarities`、`substitution`，展示主题完整武将及真实补位。
- `boxCounts` 是当前供货规格。库存/货架如果带 `spec.boxCounts`，显示原实物印刷规格。
- 旧版实物没有匹配的散包概率时不要拿当前值顶替；明确显示“原印刷版，散包概率未提供”。
- 查询不读取密封包结果，不返回 packets/随机种子/未来出货；前端也不能解析内部世界状态窥视。
- 当前包平均不是必出，独立散包至少一张概率不是盒内每一包的固定保证。

## 6. 组件与真实接入方式

展示组件接受数据和动作，不自己创建第二个 Host、计时器或全局世界：

```js
export function mountExample({root, view, actions, draft = {}, assets, format}) {
  // view 只读；draft 只存搜索、选中、滚动、展开状态等 UI 草稿。
  // 点击通过 actions 表达意图；正式 adapter 完成询价、提交与刷新。
  return {
    update(nextView) { /* 局部更新；保留用户选中和滚动 */ },
    getDraft() { /* 返回纯 UI 状态 */ },
    dispose() { /* 清理监听器、动画、观察器 */ }
  };
}
```

可以保留现有组件协议，不为统一形式大改业务适配。展示层与正式 adapter 的差异必须在交付中说明，并提供最小接线补丁。

## 7. 暂停、分支、幂等和异步安全

1. 窗口暂停沿用 window-manager；对话沿用现有 lease。打开/关闭/失败路径均成对申请释放，不新增自己的“暂停全局变量”。
2. 开窗会暂停世界；NPC 对局本身不会申请玩家比赛暂停。不能为了让 NPC 动起来把全局暂停规则关掉。
3. 所有实际变更走现有 `performOperation/recoverOperation/retryOperation` 或等效严格封装。请求未知时保留原 requestId 与参数，不创建新交易冒险重试。
4. `worldId + branchId` 是页面有效性边界。收到 worldReset/读档时关闭或失效旧窗口、清除旧报价/预览，迟到响应不得写进新分支。
5. 点击远处设施先走近；不能点击一个按钮就改 player.x/y 或绕过 NOT_IN_RANGE。
6. 查询版本、图片、技能详情异步完成时先检查组件是否仍存活、是否仍在显示同一对象。
7. 刷新只读数据不重新计算出货、不重新抽挑战名单、不推进日期、不制造收益。
8. 网络错误、业务失败、报价过期、库存变化、能力不兼容分别显示可恢复动作，不能全变成一个 Failed to fetch。

## 8. 右键、滚动与测试定位标记

- 所有经营与选将卡面增加/保留 `data-card-key`。全局窗口管理器已通过 composedPath 捕获右键，支持 Shadow DOM；局部不要重复打开两次详情。
- 保留 `retainWindowScroll` 或更可靠的等效实现。异步整窗刷新使用统一 `ctx.refresh()`，不要清空后丢失位置。
- 需要特殊保留的滚动区给稳定唯一 `data-scroll-key`；不要以数组当前位置当作唯一对象 ID。
- 卡片 React/Vue 式重挂载不是本项目必须项；不引入新框架解决几处滚动问题。
- 尽量保留 `data-format-id`、`data-roster-key`、`data-roster-locked`、`data-product-album`、`data-result-card` 等业务定位标记。若改动，列出测试迁移映射，不用“隐藏旧按钮”蒙混测试。
- 语义化按钮、dialog 的中文 aria-label、错误状态和加载状态可读。不要靠绝对坐标测试按钮。

## 9. 交给主模型的接口缺口格式

每项填写：页面/用户动作、当前真实返回、需要新增什么、缺失时如何降级、涉及哪些接入文件。注明是展示字段缺口、正式类型滞后、真实业务缺口还是素材协议扩展。

对已有能力只是没找到入口的，先查正式 screens，不要求主模型再写一套。需要批量改价、全新活动或人物情绪等业务能力，不得用多次局部命令假装原子完成，也不得把希望新增的字段写成现已实现。
