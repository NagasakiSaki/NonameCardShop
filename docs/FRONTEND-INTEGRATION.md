## 已打通的操作

1. 顶部开门、打烊、下一天、手动暂停和 1/2/4 倍时间；所有窗口独立持有暂停令牌。关掉详情仍保留背包暂停，快速关窗也会释放尚在申请中的令牌。
2. 点击柜台或手账导航先走到可站位置，再交互；跨房间先走门、后端确认换房，再换场景。读档恢复房间与位置。移动输入使用单调序号，不再用 inputSeq=0 伪造换房。
3. 进货报价→付款→等待送达→签收→仓库；货架只卖包/盒，支持实际副本上架、改价、撤架。NPC 花自己的钱购买并持有开出的实体卡。
4. 指定数量开包与“一键开所有包”均先预览。部分拆盒保留未开密封包与原内容/成本；结果展示、技能详情与技能源码接入正式数据。
5. 背包由后端按卡种、印刷版、位置聚合显示数量；保护、出售、丢弃仍指向具体实物。单卡柜台支持单张上架、留一批量上架、买入、撤单、真实成交记录和街坊求购交付。
6. 垃圾桶选择实物丢弃，可单张/全部捡回，下一天清空。受保护、挂牌或参赛副本不能丢。
7. 牌桌支持 KOF/BO3 配队、报名、原引擎挂载、BO3 下一局、关闭视图后继续、认输与未开局取消。NPC 后台比赛保持独立控制器。整场只收一次费用、登记一次整场战绩。
8. 保存、列出、读取日档；实际下载 JSON 文件、选择文件确认导入；读取前备份并建立新分支，库存、资金、流通、战绩和垃圾桶整体恢复。
9. 日报包含密封商品/单卡销售与服务收入。采购现金流、已售成本、工资、运营费、托管和利润分开，未售估值不计收入。
10. 设施、员工、轮班、工资、补货、街坊对话/实际卡片收购与交付接通新 Host。角色外观 ID 已统一，历史 ID 显式转换，未登记资源有安全兜底。

## 模块边界

- `frontend/**` 只维护显示与输入；不抽卡、不改钱包、不计算权威价格、不执行技能代码。
- `modules/backend/views.mjs` 集中生成持仓、详情、货架、市场、日报、档案元数据。`runtime.mjs` 负责查询/命令、暂停和原子持久化。
- `modules/backend/trading.mjs` 负责实物开包/交易，`products.mjs` 负责密封内容与产品定额；显示聚合不改变实物账。
- `integration/frontend-host.mjs` 统一装配 Host，`host-battle.mjs` 与 `npc-engine.mjs` 分别管理玩家/后台原引擎视图。
- `assets/frontend/**` 和 `tools/frontend-art/**` 保留前端模型的素材及可复现生成工具，本轮没有重画素材。
- 契约要点见 `contracts/README.md`。以后新增字段或页面优先在权威视图层扩展，避免各页面复制业务算法。
