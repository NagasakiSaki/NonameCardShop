# 顾客拆包与共享垃圾桶

2026-10-23 · 开发版本，未重新打包 EXE。

## 可玩流程

1. 顾客在零售柜台购买实际存在的卡包或卡盒，立即付款；店主按原进货成本记销售成本。
2. 顾客留在柜台显示“拆卡包”，随后显示“挑选卡牌”。付款后、拆包前仍是一件密封实物，内容沿用进货时已冻结的卡片，不重新抽取。
3. 顾客优先保留较强的卡，并保留配置指定的最低卡数。默认不丢 SR/SSR；在其余卡中优先丢重复卡，再按稀有度概率挑选不要的卡。
4. 有弃牌时，顾客走到垃圾桶，把选中的原卡放进共享库存，然后离店。丢弃前这些卡仍属于顾客，不能提前从桶里拿走。
5. 店长可在垃圾桶窗口单张或全部拾取。低预算且有拾荒习惯的 NPC 也会走过去翻找；普通穷顾客、富有的拾荒顾客不参与。拾荒者优先挑没持有过且评分较高的卡，每次有数量上限和冷却。
6. 拾取原卡后登记该卡种的流通资格，可以在二级市场上架或按现有对战限制参赛。资格登记本身不创造战绩、交易额或利润。
7. 打开交互窗口会暂停时钟和 NPC 行为；关掉后 NPC 继续行动。剩在桶里的所有卡在开始下一天时清空，店长和 NPC 已捡走的卡保留。

顾客买整盒也使用同一条流程，拆出 120 张既定实物。店主提前打烊时，已付款且尚未完成的拆包/弃牌流程一次性收尾；未付款的顾客取消购物，避免第二天卡在旧路线或引用已清空的卡片。自然到 20:00 后停止新购物与拾荒安排，已付款顾客继续完成离店动作。

## 数据与所有权

- `modules/backend/trash.mjs`：共享库存、丢弃、拾取、弃牌偏好、贫穷判定和拾荒冷却。
- `modules/backend/trading.mjs`：付款、拆包、挑选、走到桶边、离店的阶段调度；所有牌来自实际购买的商品。
- `modules/backend/runtime.mjs`：公开命令串行提交、暂停、打烊和次日清空，沿用原存档机制。
- `frontend/ui/trash.mjs`：共享卡片、丢弃者来源、单张和全部拾取。
- `frontend/world/actor-view.mjs`：动态更新顾客头顶行为文字，沿用原行走动画与地图。

垃圾桶中的新卡使用 `ownerId: public:trash`，只允许卡牌、无保护且无锁，必须有有效的原丢弃者。`item.trash` 保存丢弃者、日期、时刻和原成本。旧存档中仍由店长/NPC 持有、但位置为 `trash` 的卡也可查询和拾取；无需清空旧存档。

捡自己的卡保留原持有成本；捡别人的弃卡以零成本入库。前者避免丢一下再捡回便把原进货成本抹掉，后者表达免费获得。拾取不改变现金、销售额、成本支出或胜率。卡的 `inventoryRef` 始终不变，重复领取同一张卡会拒绝；同一 `requestId` 重试返回原结果。

事件：`packSaleCompleted` → `customerPacksOpened` → `cardDiscarded` → `trashCardPickedUp`。首次获得流通资格另记 `cardEnteredCirculation`；已流通卡被拾取仍记拾取事件。次日清空记 `trashCleared`。

## 前端接口

```js
// 与旧接口名称兼容，但 location:trash 改为全店共享桶；可使用 cursor/limit 翻页。
await host.query('inventory.list', {location:'trash', limit:60});
// 每行是实际卡片，新增 discardedBy / discardedByName / discardedDay。

await host.command({requestId, type:'inventory.recover', payload:{inventoryRef}});
await host.command({requestId, type:'inventory.recover', payload:{all:true}});
// all:true 拿走桶内当时全部可拾取实物，数量不受列表第一页限制。

await host.command({requestId, type:'inventory.discard', payload:{inventoryRef}});
```

命令仍检查店长是否站在 `store.trash` 交互范围内。共享桶里的牌不算店长收藏或 NPC 阵容，不能保护、直接上架或直接参赛；必须先拾取。`grouped:true` 也支持共享桶分组，原始单张查询才有丢弃者来源字段。`owned:1` 在桶查询中表达该行的一张实物，不代表店长已拥有它。

所有路线、拆包/翻找剩余时间、待丢弃卡引用、拾荒习惯与冷却均随世界存档保存。存读档恢复同一批商品与卡片；暂停、断线、读档不会重新抽牌。

## 可调整参数

默认值在 `data/backend-rules.json` 的 `customerBehavior` 中。游戏内“设置 → 全局评分、供货与经营”可编辑，校验并应用后立即影响后续行为。缺少该块的旧存档使用内置默认值，设置界面会完整显示这些字段。已进入拆包、挑选、翻找阶段的剩余计时沿用当时记录，下一阶段采用新配置。

| 字段 | 默认 | 作用 |
| --- | --- | --- |
| `openingSeconds` | 3 | 付款后的店内拆包时长，按营业倍率加速 |
| `sortingSeconds` | 2 | 拆完后的挑牌时长 |
| `searchSeconds` | 2 | 到桶边后的翻找时长 |
| `keepCopies` | 1 | 低档卡超过保留张数时优先作为弃牌 |
| `minimumKeptCards` | 3 | 保留评分最高的至少三张现有收藏，持有不足则全部保留 |
| `discardChance` | N .65、R .25、SR 0、SSR 0 | 非保护核心卡的弃牌偏好；为 0 时即使重复也保留该档 |
| `scavengerChance` | .3 | 新顾客有拾荒习惯的概率；已有未标记顾客仅首次补记一次 |
| `poorWallet` | 400 | 当前钱包不高于此数且有拾荒习惯才会翻找 |
| `poorInitialWallet` | 200 | 新生成拾荒型顾客的基础钱包，仍受展示设施倍率影响 |
| `pickupLimit` | 2 | NPC 每次最多拾取数量，优先不同卡种 |
| `pickupCooldownMinutes` | 90 | NPC 完成翻找后到下一次翻找的游戏分钟间隔 |
| `names` | 12 个预设姓名 | 新顾客姓名池；外观、顾客类型与姓名相互独立 |

贫穷 NPC 仍可正常买卖、上架单卡、参加符合资格和余额要求的牌局。每日收入或卖卡使其变富后会停止拾荒；属性不自动抹除。修改 `scavengerChance` 影响新生成或尚未赋予习惯的 NPC，已有习惯不反复抽签。当前是原型偏好模型，后续可在 `unwantedCards()` 替换为阵营、收集目标和阵容需求评分。
