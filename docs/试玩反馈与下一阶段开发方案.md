# 卡店经营游戏：试玩反馈与下一阶段开发方案

日期：2026-10-23

对照基线：当前源码 v0.8.1

文档状态：需求整理与设计草案，未实施

> 本轮只编写开发文档，不修改游戏规则、代码、素材或安装包，不下载工具。本文中的接口、数值和新文件名均为后续开发建议，不代表已有实现。用户明确提出的需求与本文补充的方案分别标注；补充方案可以独立调整。

## 一、目标与范围

目标是把目前的“开包、收藏、经营、对战”整理成一款以像素 RPG 操作为基础的卡店经营游戏：玩家经营店面，采购并销售密封商品；自己开包后收藏或出售单卡；顾客购买和交易使卡牌进入本地市场；玩家与 NPC 使用流通中的卡组在对战房比赛；比赛表现、市场供需与收藏价值共同影响单卡行情。

需要形成下面的循环：

```text
采购卡包/卡盒 → 正店零售 → 顾客开包 → 卡牌进入流通
        ↓                         ↓
店主自己开包 → 收藏 / 二级市场交易 → NPC 实际持有与构筑
                    ↑                    ↓
                行情与需求 ← 有效战绩 ← 对战房
                    ↓                    ↓
                 单卡成交          开桌费、抽水、店主参赛
                    └──────── 资金再投入 ────────┘
```

自己开到的牌不自动等于市场上已经存在的牌；进入流通的判定见第五章。对战、收藏和商业价值应互相关联，但不能共用一个“稀有度越高就必胜”的简单数值。

### 1.2 本文建议的补充边界

- “全局”第一阶段指**同一存档世界内**的全店、全 NPC 与玩家共享数据，不接入跨玩家联网市场。
- 下注只使用现有游戏币；不增加充值、提现或真实货币系统。
- 保留已有 KOF 三将接力与 BO3 赛制；扩建房间不重写无名杀核心引擎。
- 保留散包小保底、实体整盒固定配额与大保底。四档稀有度改造须同步重做配方与价格。
- 正在履约的采购订单、已生成的实体盒、库存成本和按天存档需要迁移方案，不能靠清档解决。
- 先完成规则与经营闭环，再扩大 NPC 数量和美术内容，避免同时修改所有系统。

## 三、美术与 RPG 操作改造

**来源：U01、U02。此部分只记录后续需求，本轮不制作素材，也不下载工具。**

### 3.1 风格方向

“早期宝可梦”还需要区分 GB/GBC 的低色数风格与 GBA 的彩色俯视风格。建议先以 **GBA 时期的彩色、俯视、格子地图 RPG 观感**制作样板，风格最终由用户看样后决定，不复制宝可梦角色或地图素材。

先完成一间样板店、一个店长、两类顾客的风格验收，再批量绘制。重点是整体一致，而不只是把现有画面降低分辨率。

| 项目 | 建议规格，待样板确认 |
| --- | --- |
| 地图 | 16×16 基础瓦片，家具可由多个瓦片组合 |
| 地图角色 | 约 16×24 或 24×32 原生像素，统一脚底锚点 |
| 走路 | 下、左、右、上四方向，每方向至少 3 帧，另定义待机帧 |
| 对话立绘 | 与地图角色对应的独立头像或半身像，建议从 80×80 样板起步 |
| 渲染 | 整数倍缩放、关闭平滑插值；统一轮廓、光源和阴影 |
| 场景变化 | 早晨、白天、黄昏、夜间调色与灯光，保留室内物件可辨识度 |

“立绘”与“地图行走图”是两份关联资源：有头像不代表已经有四向动画；不能用头像整体平移代替行走。

### 3.2 角色与动画

- 店长有独立服装、发型和配色，不能与随机顾客只差一个染色值。
- 顾客至少区分新手、收藏家、竞技玩家、常客等类型；轮廓、衣服、携带物和立绘相互对应。身份类型不强制决定年龄或性别。
- 通过统一角色模板复用身体结构，保留不同发型、服装和配饰，控制素材工作量。
- 行走帧按移动距离或速度推进；开始移动、转向、停下时正确切换，避免脚一直走但人不动、滑步、斜移速度过快。
- 碰撞按脚底占地计算；支持柜台前交互、门口通行、桌椅遮挡、顾客排队和寻路避让。
- 店长手动操作与点击寻路应使用同一套移动、朝向和碰撞规则。

### 3.3 代码绘制工具调研任务

后续调研“脚本生成像素素材 + 可人工修整的像素编辑器”组合。可以从项目现有 Canvas 绘制方式、图像脚本库、支持脚本或命令行的像素编辑器中比较，**暂不指定安装某个工具，也不假定其授权和功能已经核实**。

选型交付物：工具来源与版本、安装方式、授权、离线可用性、一张可复现的四向行走图集、一套地砖与柜台样板、生成参数和原始文件。必须验证：

1. 能按像素精确绘制并导出透明 PNG 与图集。
2. 能通过代码或脚本重复生成，固定随机种子后结果一致。
3. 调整色板、身体比例或角色配件时，不必逐张重新画。
4. 导出的尺寸、锚点、帧序和动画名能由资源清单统一读取。
5. 工具安装与素材生成不进入玩家安装步骤；玩家运行时不依赖绘图工具。

建议资源清单包含 `characterId / archetype / portrait / sheet / frameSize / anchor / animations / paletteVersion`。美术替换只换资源与映射，不修改顾客交易逻辑。

## 四、所有交互统一暂停

**来源：U03。** 交互期间暂停的是经营世界；玩家应有足够时间阅读、比较和操作。

### 4.1 暂停范围

| 场景 | 经营时间 | 可继续的内容 |
| --- | --- | --- |
| 角色自由走路、普通逛店、没有打开面板 | 按玩家设定运行 | 顾客、配送、营业流程 |
| 柜台、进货、签收、定价、背包、收藏、垃圾桶 | 暂停 | 当前面板的操作和反馈 |
| 单卡详情、技能代码、任务、日报、图鉴、对话 | 暂停 | 阅读、选择、切页 |
| 单包/批量开包、批量上架及确认框 | 暂停 | 动画、事务处理、结果展示 |
| 二级市场浏览、挂单、买卖、行情详情 | 暂停 | 报价确认、交易反馈 |
| 配队、下注、参赛、玩家牌局、赛后结算 | 暂停 | 玩家牌局自己的引擎时序 |
| 设置、编辑器、存读档、离开窗口或切后台 | 暂停 | 必要的界面与保存任务 |

配送计时、顾客等待、NPC 后台对战进度、桌位租用时间和定时任务都依附经营时钟，不能在面板打开时偷偷推进。昼夜背景也保持在暂停时刻。

玩家牌局使用独立的战斗时序。暂停店铺时间不能连带冻结玩家正在进行的出牌、技能选择和战斗动画。纯 NPC 后台牌局则应随经营世界暂停；若后台计算已异步完成，结果先等待，恢复后在确定的事件边界提交。

### 4.2 实现约束与验收

建议使用带原因和拥有者的暂停令牌：打开窗口申请，关闭或销毁窗口释放。多个窗口嵌套时，必须等所有暂停原因解除后才能继续；不再由每个界面随意写同一个 `paused = false`。

- 关闭卡牌详情后，如果背包还开着，时间仍暂停。
- 交互前玩家手动暂停，关闭交互后仍保持手动暂停。
- 交互前 4 倍速，关闭全部面板后恢复原倍率，不跳过暂停期间的真实时间。
- 加载失败、取消确认、窗口异常关闭都不能留下永久暂停或意外恢复。
- 任一交互持续 60 秒，营业分钟、配送剩余时间、顾客耐心、后台桌费计时不变；无延迟补算。
- 一次商品成交可以在暂停期间完成，但不得借此额外触发一轮后台客流。
- 暂停状态有清晰标识；自动暂停不要求玩家再手动点一次继续。

## 五、正店、二级市场与卡牌流通

**来源：U08、U10；以下给出建议的完整交易规则。**

### 5.1 三个业务区域

| 区域 | 商品/服务 | 玩家收入 |
| --- | --- | --- |
| 正店零售柜台与货架 | 密封卡包、密封卡盒 | 已付款的商品销售额 |
| 二级市场柜台 | 店主单卡出售、收购、NPC 寄售、NPC 间撮合 | 自营单卡销售额；寄售只计服务费 |
| 对战房 | 开桌、打牌、游戏币下注 | 开桌服务费、对局抽水；店主参赛盈亏另列 |

单卡不能继续混入正店货架。旧单卡货架迁移时转入二级市场待上架区或退回库存，数量、保护标记与成本不变；不能静默消失或按零成本重新生成。

二级市场柜台是店内另一个明确交互点，有单卡出售、收购、寄售和行情页面。店主自营与 NPC 寄售需要区分：卖出自己的卡是商品收入，代卖别人的卡只能将佣金计入店铺收入。

### 5.2 “进入流通”的判定

建议按存档世界维护一份**只增不减的已流通卡种记录**，每条有来源事件、营业日和规则版本。这里的卡种以“武将技能版本”为基础；不同角色不能因为同名合并。

满足以下任一条件即符合用户的 OR 规则：

1. **本店已售出：** 本店确实收款交付过该单卡，或售出的包/盒所包含的该卡在顾客实际开包后被登记。
2. **进入过二级市场：** 该卡的有效挂单被市场接收并锁定实物，或已经在该市场完成交易。

第 2 条建议以“有效挂单”作为进入市场的时点，撤单后仍保留历史；这是对“进入过市场”的拟定解释，尚需最终确认。仅打开上架面板、看报价、失败挂单、编辑器预览都不算。

密封包/盒购买成功时登记商品出售事件，顾客开包时再登记具体卡种。虽然系统可以预先固定内容，但玩家不能通过流通记录提前看到他人未开商品的隐藏内容。若以后允许买家延后开包，其卡种要等实际开包后开放。

以下情况**不单独产生流通资格**：店主私下开包并留在收藏、浏览完整图鉴、垃圾桶丢弃与捡回、抽样测试、战斗生成的临时武将、尚未付款的顾客购物篮。

### 5.3 流通资格与实体所有权分开

流通记录回答“这个卡种是否已经出现在本地环境”；实体库存回答“谁现在持有几张、哪些被锁定”。拥有市场资格不等于所有 NPC 都能无限拿出这张牌。

- 每张实体卡或可追踪批次有稳定身份，保留开包来源、印刷稀有度、版本、成本和所有者。
- NPC 用自己购买、开到或交易获得的卡构筑。缺某张卡时应收购、购买或调整阵容，不能凭资格记录凭空生成。
- 第一阶段建议玩家参战也遵守相同资格，并实际持有自己的参赛卡；这是对“对战的人”的统一解释。
- 同一张卡被挂单、预约交付或参赛锁定时，不能同时卖掉、丢掉或交给另一场比赛。
- 技能生成的临时角色属于引擎效果，不变成经营库存或新的印刷卡，也不自动开放市场资格。
- 建议永久拥有者使用一个统一所有权层；背包、二级市场、参赛区和垃圾桶只是持有位置与锁定状态。

### 5.4 冷启动与退货

新世界没有历史流通牌，必须提供明确启动路径：首批顾客买包并开包，店主也可将自己开出的牌有效上架，使少量卡逐步进入环境。可选的开店种子市场需要固定预算、实体库存与来源事件，不能默认开放全部 2563 位。

建议已完成真实交付的卡种保留流通历史，即使后来退货或撤单也不抹去。作废、未交付订单不产生资格；具体退货支持可以后置，但语义先固定。

市场资格是卡种级，实际占有是实体级：同卡种首次进入市场后，其他持有者的同版本卡可参赛，不要求每一张实体都曾挂牌。印刷变体共享技能战绩、独立计算收藏溢价；不同技能版本保留独立记录。

## 六、四档稀有度与卡盒经济

**来源：U09，并承接已确定的“散包小保底、整盒大保底、整盒配额固定”。**

### 6.1 四种概念分别维护

| 概念 | 含义 | 是否随行情改变 |
| --- | --- | --- |
| 印刷稀有度 N/R/SR/SSR | 商品出货与收藏层级 | 已印出的实体不自动改变 |
| 设计强度分 | 按牌差、伤害、防御、控制等估算能力 | 校准或技能版本变化时更新 |
| 实战表现 | 指定模式与规则下的出场、胜负等记录 | 有效比赛结束后积累 |
| 市场价格 | 稀有度、表现、成交、供需和收藏需求形成的报价 | 按行情规则变化 |

稀有度不能在每次胜率波动时反复升降。可以出现低稀有度强将和高稀有度收藏将；NPC 会受稀有度影响，但战斗引擎不能给 SSR 额外伤害或血量。

四档划分要重新审核，不能仅把 UR 改名 SSR，再把其余档位机械合并就宣布完成平衡。建议沿用现有强度模型作为起点，补充高影响、低可信武将校准，记录收藏性等人工分级理由。

### 6.2 卡包与整盒

- 展示、筛选、任务、NPC 偏好、报价、开包动画和编辑器统一使用 N/R/SR/SSR。
- 散包建议保留“每包至少一张 R+”的小保底；不追加跨包累计必出的暗保底。
- 新卡盒暂沿用 24 包、每包 5 张，共 120 张，整盒固定四档数量；具体配额另行经济模拟。
- 整盒至少一张 SSR 作为建议的大保底；更高商品档可以增加配额，但不能承诺尚未配好的数值。
- 配盒算法要同时满足“120 张总量、四档固定数量、每包 R+ 小保底”；不能先随机塞满再破坏配额补卡。
- 主题缺档须明确补位来源，不能偷降档或突然提高高稀有度概率。
- 实体盒内容在生成后冻结，拆卖、读档、换日、批量开包均不能重抽。
- 散包与盒内包的出货方式分别说明；“买 24 个独立散包”不等于购买一盒。

### 6.3 进价、售价与市场脱钩边界

建议保留现有“按印刷配方与基准卡值计算商品报价”的方式，新增行情不直接逐帧改动所有进货价。

```text
卡包基准卡值 E = Σ（各档平均张数 × 各档印刷基准价）
卡盒基准卡值 E_box = Σ（该盒各档固定张数 × 各档印刷基准价）
采购建议价 = 按目标拆包价值比与供应商成本计算，再按规则取整
零售建议价 = 采购建议价 / (1 - 目标商品毛利率)，再按规则取整
```

各档基准价、目标毛利、拆卡回报比、顾客预算需要一起模拟。新价格必须保证初始资金能完成首轮进货，基础顾客买得起入门产品。拆出卡的“参考总值”不代表立刻能全部卖掉；交易速度、买家预算、费用与滞销风险都要计入。

供应商新报价可按日或补货周期更新；已下单的采购价、已确认的顾客价与密封内容继续冻结。避免某张卡短时涨价后，所有卡包同步暴涨造成循环放大。

### 6.4 旧版迁移

建议采用“新印刷版本四档、旧实物保真”的办法：

1. 迁移前完整备份存档与配置，记录迁移版本，重复启动不再次迁移。
2. 旧版 C/U/R/SR/UR 实体盒与已冻结订单保留原内容和数量；在商品详情中标注旧版配额。
3. 新目录用四档分级。旧实体保留原印刷档位与旧版标识，可附新版目录对应档，但不能把旧 120 张盒重抽成新配方。
4. 旧的未冻结散包按其能确认的来源版本处理；不明来源单独标记，给出一次性迁移说明，不虚构其内容或成本。
5. 所有权、收藏数量、保护标记、成本和既有订单价格守恒。未知成本继续标未知。
6. 任务、报价、NPC 偏好等五档配置通过显式映射迁移；旧配置留备份，无法无歧义转换时提示复核。

这是存量兼容例外，不继续发行第五档新品。若最终要求界面绝不出现旧档位，则应在不改变实际卡内容的前提下另定历史显示映射，不能悄悄修改老盒承诺。

## 七、一键开包与“留一上架”

**来源：U07。所有批量操作期间自动暂停营业。**

### 7.1 一键开所有包

入口放在仓库与开包柜台。建议默认打开玩家持有、可用的所有散包与已拆盒余包，支持按主题筛选；密封整盒另设明确选项“同时拆盒并全部打开”。顾客已付款待交付、预约、寄售和保护库存不得被当作玩家可开库存。

确认前展示总包数、涉及盒数、预计卡数、消耗范围及保护库存。打开后：

- 提供完整动画、只看 SR/SSR、直接看汇总三种展示选项；跳过动画不改变实际出货。
- 按“武将 + 印刷版本/稀有度”汇总，显示新增收藏、重复张数与本次获得数量。
- 支持从结果直接使用“保留一张，其余上架”，并允许手动取消个别卡。
- 大量开包可以分批落盘，但要有操作 ID 和已处理位置。中断后从已确定结果继续，不能重复扣包、重复发卡或重掷未展示的固定内容。
- 全部展开一盒后，汇总必须与盒的原定配额相同；包成本分配到卡后的总额保持一致。

### 7.2 保留一张，其余一键上架

这里的“上架”统一指**二级市场挂单**，并非立即获得现金。

建议保留规则：按“武将技能版本 + 印刷变体”分别保留一张，玩家可选择合并变体按武将保留；系统默认保留已有收藏保护的那张，没有保护则保留收藏价值较高的一张。具体默认分组需最终确认。

- 统计玩家自己持有的收藏与可用库存；在售副本不重复上架，NPC 寄售不参与。
- 同一张卡如果兼有收藏保护和参赛锁定，只算一张实体，不能双扣数量。
- 参赛、预约、任务交付保留、收藏锁定、玩家明确保护的副本优先保留，即使因此超过一张。
- 显示“当前拥有 X、计划保留 Y、已在售 Z、本次上架 Q”，明确无法上架原因。
- 支持按参考价、参考价倍率、玩家统一价格模板挂单，预览手续费与预计净额。
- 上架库存被锁定；撤单后返回原所有者，不重复制造库存或重计成交。
- 成交时才计收入；未售出的估值不能计为营业额或现金。

典型验收：同版本曹操 5 张，其中 1 张收藏保护、1 张额外参赛锁定，当前无在售，最多上架剩余 3 张；不得因“只留一张”把参赛副本也卖掉。

## 八、取消专用对战池与扩建对战房

**来源：U04、U05。**

### 8.1 对战准入

目标是取消独立的“单挑专用卡表/卡池”概念，玩家围绕真实流通和持有的收藏牌构筑。原 25 将名单不再承担经营玩法的准入规则。

需要分清两种“牌”：可收集与交易的是武将牌；牌局内的杀、闪、锦囊、装备等行动牌仍由无名杀赛制规则组织。取消武将专用池不等于删掉对局所需的行动牌堆。

新的准入检查建议为：

```text
卡种已进入流通
  + 当前参与者实际持有足够副本
  + 副本没有被其他交易/比赛占用
  + 所选模式的技能规则能够执行
```

最后一项是需要完成的全卡适配工作，不应演变成另一个隐藏白名单：

- 对所有目录武将做技能能力扫描，并保留公开、具体的错误诊断。
- 多人目标、主公技、额外座位、变将、特殊胜负、死亡遗产与 KOF 换将需要明确适配规则。
- 正常无目标的技能可以按模式自然不发动，并在详情解释；不能把技能存在性当成必然可用。
- 已确认会破坏流程的武将暂时显示具体故障及修复状态；不拿稀有度或所属扩展作为禁止理由。
- 不同武将的相同名字、不同技能版本必须稳定区分。
- 在发布“全收藏可对战”之前，先完成适配报告与真实引擎回归，不能把 2563 个 ID 填进数组就视为完成。

### 8.2 对战房

建议扩建为相邻独立房间，保留零售动线。初期少量桌位即可，后续用设施升级扩容。

- 有门口、等候区、桌位、下注/报名交互点，桌椅与角色遮挡正确。
- NPC 流程：到店 → 购物或找对手 → 使用持有卡构筑 → 确认费用与下注 → 入座 → 对战 → 结算 → 离店或返回市场补卡。
- 玩家可以经营桌位、查看牌局，或亲自入座参赛；不能同时操作多个需要本人出牌的牌局。
- 顾客可能只买包、只交易、只打牌，或组合消费；不强迫每个 NPC 完整走一遍所有业务。
- 桌位状态可见：空闲、预约、等待对手、进行中、待结算；中断后有明确恢复/取消入口。
- 首版建议按场收开桌费，易理解且少依赖时长；计时租桌作为可选后续规则。
- 后台 NPC 对局并发量受性能预算限制；不能为每位顾客无限创建引擎实例。

### 8.3 赛制与营业时间

继续保留 KOF 三将接力和单将 BO3。KOF 阵亡后手牌继承，BO3 每小局重开；整场结果只结算一次。

玩家参与对战时店铺自动暂停。建议该场用自己的战斗进度完成，桌费按场处理，不能为推进营业时间而强制快进。NPC 后台对局在没有交互时随经营时间推进，交互期间冻结提交进度。

打烊时建议停止新开桌，已有 NPC 桌可以在关店前流程中结清或明确延至次日；不要把未结赌注直接当收入。此规则需要和“开始下一天”一起验收。

## 九、游戏币下注与 NPC 决策

**来源：U05、U06。以下倍率、上限和费用均为可调建议，不是当前游戏参数。**

### 9.1 把“下注倍数”和“赔率”分开

用户要求稀有度差距影响 NPC 下注倍数。建议首版把倍率定义为**双方同意的基础赌注放大倍数**，而不把它直接解释成庄家承诺的高额赔付赔率。

```text
稀有度分：N=0，R=1，SR=2，SSR=3
BO3 阵容分：所用武将的稀有度分
KOF 阵容分：三位主战武将稀有度分的平均值
稀有度差 Δ：自身阵容分 - 对手阵容分
NPC 提议倍数：按 Δ 查询可编辑的分段表，再结合性格与预算
```

示例表：明显劣势（Δ≤-1）偏好 0.5 倍，接近（-1<Δ<1）偏好 1 倍，明显优势（Δ≥1）偏好 2 倍。它表达 NPC 的稀有度偏见，不代表真实胜率，也不要求所有 NPC 作出完全相同的选择。

- 双方同意一个最终倍数，赌注金额相等并提前托管；不同意可降注或无赌注开桌。
- 实战经验、性格、近期输赢和资金决定是否接受，但稀有度差距必须仍是可观察的决策因素。
- 比赛开始前冻结阵容、稀有度版本、倍数和金额，不能下注后换成另一套牌。
- 有明确的最低注、单场最大注与钱包占比上限；不允许负余额下注或用赊购额度支付赌注。
- 不以店主的实时隐藏手牌影响下注；下注发生在开局前。

如果以后要做真正的非对称赔率或旁观者投注，须另建奖池/承兑规则，先验证全部赔付有资金来源。首版建议只做参赛双方等额下注，不引入无限赔付庄家。

### 9.2 开桌费、抽水与托管结算

建议首版按场收固定开桌费，抽水按双方托管赌注总额乘费率；具体谁支付开桌费在确认页列出。

示例仅用于说明账：双方各押 100，奖池 200，抽水 5%，店铺收 10，胜者领 190；开桌费另计。190 包含胜者自己的本金，因此胜者的下注净收益是 90，不能记作赚 190。

- NPC 对 NPC：店主收入是开桌费与抽水，奖池本金不归店主。
- 店主亲自参赛：建议免除对自己征收的服务费与该桌抽水，独立记录参赛盈亏，避免内部转账虚增营业额；NPC 仍可按约支付自己的场地费。
- 若将来采用店主参赛仍抽水的规则，必须合并检查店主钱包，内部费用冲销，不能当成额外凭空收入。
- 服务费何时确认、对局何时视为开赛需固定；建议入座时托管，双方成功开局后确认开桌服务收入。
- 整场平局或系统未开局失败：原则上退还未消费费用与双方本金；BO3 小局平局继续比赛，不提前结算。
- 开局后的主动退赛按整场落败处理；系统异常不自动认输，应恢复或按记录退款。
- 重复结果、刷新、读档后重放消息只能结算一次。交易、托管、支付、收入记录要在同一事务里成功或回滚。
- 店主的托管负债单列，不能用于进货、还债或发奖励；NPC 下注同样先扣实际可用余额。

### 9.3 防止经营失衡

NPC 必须有连续的钱包、购买预算与止损倾向，不是每次进门都刷新成无限资金。可以有每日外部收入，但必须作为明确的经济来源配置并记录。

竞技玩家、收藏家、谨慎新手可使用不同策略；低稀有度强将仍可能获胜。店主能通过理解环境获利，但不能靠反复拉同一个无资金 NPC 下注形成无限收入。

常规开桌与无赌注比赛仍可使用，店铺经营不强制依赖下注收入。原有赛事赞助奖金与赌注奖池分开，不能把托管资金当作任务奖励来源。

## 十、全局战绩与单卡价值模型

**来源：U11。以下为本游戏拟定的定量规则，不是三国杀官方强度标准，也不是已经采集的真实战绩。**

### 10.1 统计范围

第一阶段“全局”是同一个存档世界及其当前分支，涵盖玩家和 NPC 的有效牌局。不同存档不互相污染，测试环境不写入正式世界。

统计键建议至少包括：`generalId + skillVersion + mode + rulesVersion`。不同印刷图案可共用同技能版本的表现记录，收藏溢价单独处理。技能修订或重大赛制改变后建立新统计赛季，不把旧数据无条件当作新能力。

| 指标 | 记录口径 |
| --- | --- |
| 整场出场次数 | BO3 整场一次；KOF 仅实际登场者各记一次，未轮到的后备不记 |
| 整场胜/负/平 | 参战武将随其队伍整场结果记录，每个参赛方的同一卡种最多记一次 |
| BO3 小局记录 | 单独保留，不能与整场场次相加 |
| KOF 辅助表现 | 击破数、上场位置、存活回合、接手手牌、对手等；与整场队伍胜率分开 |
| 对局上下文 | 双方阵容、先后手、AI 等级、参与者、赛制、版本、开局与结算 ID |

KOF 的“出场队伍胜率”受队友与上场顺序影响，不称为武将独立真实胜率。初期可较低权重参与估值，逐步加入位置、对手和队伍的校正；不能仅凭一位武将跟强队赢了就断言其单体无敌。

去重键包含比赛 ID、参赛方和卡种。双方镜像使用同一武将时，分别记录一方胜、一方负，即两次出场，不把其中一边误当成重复消息丢弃。

只计规则完整、结果有效的正式对局。未开局、中断未恢复、取消、测试、开发作弊场不计。重复结算消息按比赛 ID 去重；同一对手高频重复比赛可限制价格权重，但真实比赛记录仍保留供查看。

### 10.2 NPC 比赛结果的数据可信度

优先用同一无名杀引擎运行有实际阵容的 NPC 牌局，限制并发并保存结算摘要。不能用“设计评分比较后随机判胜”生成一批记录，再把它们显示为实际实战胜率。

如果性能暂不足：

1. 先只采集玩家牌局和有限数量的真实 NPC 牌局。
2. 后台估算可驱动非正式娱乐表现，但标为模拟，和有效战绩、价格依据分开。
3. 样本不足的卡继续使用基准价与明确的“样本不足”标记，不能补造对局。

### 10.3 平滑战绩与价格加成

单看“1 胜 0 负 = 100%”会让偶然结果毁掉价格。建议同时考虑胜负表现与有效样本量，先使用易解释的平滑模型，再逐步加入对手强度校正。

对每种赛制分别计算：

```text
n = W + L + D                       # 有效加权场次
s = (W + 0.5×D + 10) / (n + 20)      # 向 50% 收缩的战绩得分
c = n / (n + 40)                     # 设计用样本权重，不是统计置信度
G = clamp(1 + 2×c×(s - 0.5), 0.70, 1.40)
```

这里的 W/L/D 可以按近期程度、对手重复度等折扣为加权值，原始整数场次另存。10/20/40、2 与上下限均为待测试参数；此公式是定价启发式，不声称能识别武将真实因果强度。

示例：

| 无平局的原始记录 | 平滑得分 s | 样本权重 c | 战绩倍率 G，约 |
| --- | ---: | ---: | ---: |
| 0 场 | 50.0% | 0 | 1.000 |
| 7 胜 3 负 | 56.7% | 0.200 | 1.027 |
| 50 胜 50 负 | 50.0% | 0.714 | 1.000 |
| 70 胜 30 负 | 66.7% | 0.714 | 1.238 |
| 30 胜 70 负 | 33.3% | 0.714 | 0.762 |

这满足“优秀胜率且有足够场次，价格更高”，同时避免“输得再多，只因总场次多也涨价”。相同高胜率下，样本增加使正向加成更充分；低胜率的大样本则支持下调。

KOF 与 BO3 各自得到 G，再按公开的模式需求权重组合；没有样本的模式保持 1，不伪造场次。初期 KOF 权重建议低于 BO3，以减少队友带来的混淆。对手、先后手、AI 水平的进一步校正应作为后续可替换模块，保留原始数据便于重算。

### 10.4 最终参考价与真实成交

```text
目标参考价 = 印刷基准价
             × 战绩倍率
             × 供需倍率
             × 收藏/版本倍率

今日参考价 = 对目标价平滑后，应用单日涨跌幅与绝对价格上下限
实际成交价 = 买卖双方接受的挂单或收购价
卖家净得 = 实际成交价 - 明示的交易费用
```

建议供需使用近期有效成交、活跃买家需求、真实在售量与流通量，限制因子范围；不能只靠“挂了一个天价卖单”就上涨。稀缺但无人想买，不等于一定高价。

设计强度分可作为冷启动的解释信息或较弱的先验因素，不填成实际胜率。稀有度提供收藏基准，市场让强力低稀有度卡具备流动性与合理溢价。

建议约束：

- 单场对局先更新统计，价格在固定营业时点或次日统一公布，避免每条战斗消息触发全市场改价。
- 默认日涨跌幅、买卖价差、交易费、买家预算、挂单容量均可配置；不把具体数值写死在界面。
- 顾客已接受的报价、已撮合订单、已确定赌注保持快照，不被随后行情改写。
- 店主与 NPC 互相倒手、同主体左右手交易、反复取消挂单不形成有效成交量。
- 收购并非无限回收。二级市场现金、卖家库存、买家意愿必须真实存在。
- 商品采购仍用印刷配方与供应商报价，避免战绩与卡包采购价无限互相抬升。
- 行情页面显示样本量、原始战绩、模式、统计版本和主要价格因素，让玩家看懂上涨原因。

## 十一、资金、库存与按天存档

**本章为补充建议，服务于 U05、U10、U11，防止新系统破坏已有按天存档。**

### 11.1 分清收入与资金搬运

| 项目 | 现金流 | 店铺收入处理 |
| --- | --- | --- |
| 店主自营包、盒、单卡成交 | 顾客付款入账 | 商品销售收入，另扣已售成本 |
| NPC 寄售成交 | 收到成交款，欠卖家应付款 | 仅佣金是收入 |
| 收到参赛押注 | 进入托管账户 | 不计收入 |
| 奖池支付 | 托管账户转给胜者 | 不重复计经营成本或商品收入 |
| 开桌费、对局抽水 | 按完成条件确认 | 服务收入 |
| 店主参赛胜负 | 本金返还与净盈亏分离 | 单列参赛净盈亏 |
| 未售库存/未成交挂单涨价 | 没有现金流 | 只显示估值，不算已实现利润 |
| 任务与赞助奖励 | 外部奖励入账 | 与销售、服务收入分列 |

日报建议分别展示商品营业额、商品毛利、服务收入、参赛盈亏、营业费用、现金与托管负债。“日营业目标”是否包含服务收入需要重新定义；建议商品与服务经营收入可计入，赌注本金、中奖回款本金、任务奖励不能计入。

现有 `daily.revenue` 依赖任务较多，实施时不要直接改含义；新增分项指标，并显式迁移旧任务。不要把进货总额简单当作当日已售成本。

### 11.2 保存与读取

新增以下状态与当前进度一起归档：

- 流通资格与来源事件；所有 NPC 钱包、持卡和预约。
- 单卡实体/批次、持有者、位置与锁定关系；旧盒版本与未开内容。
- 挂单、寄售、成交、手续费与应付款。
- 有效战绩、统计季、价格版本与当日报价。
- 桌位、比赛、托管、下注快照和已结算 ID。
- 新配置版本、任务状态与市场随机种子/事件位置。

读回某一天时以上状态整体回到该世界的那个时间点，继续游玩创建独立分支。不能回滚玩家现金，却保留未来市场涨价、NPC 卡牌或战绩。派生索引可重建，不能跨分支重复消费事件。

当前按天存档不保存无名杀完整运行事件栈，新增下注后必须避免通过刷新重开同一局反复选择盈利结果。建议第一阶段沿用完整战斗期间禁存读档，在正式开赛前和最终结算后做可恢复的持久事务；进程异常恢复时不立即退款重抽，而是保留阵容、完整随机源、操作日志和托管状态恢复或确定性重放同一场。只保存起手发牌种子不足以重放含随机技能的牌局。若无法确定性恢复，则进入明确的异常处理状态，不能同时发奖金与退款；恢复能力通过验证后再开放下注桌，此前可以先开放无赌注桌。

垃圾桶仍在开始次日时清空。只有玩家自己的可丢弃库存能进入垃圾桶；挂单、寄售、参赛、押金相关物品不能丢弃。清空减少实物供给，但不会抹掉曾经流通过的历史资格。

未来若接入跨玩家联网市场，应另立项目设计服务器权威数据与不可回滚结算，不能直接沿用本地读档规则。

## 十三、补充的经营与体验建议

以下为本文补充，不视为用户已经确认全部制作。

### 13.1 给各条业务留下价值

- 买包顾客提供稳定零售需求；收藏家偏爱版本、稀缺与图鉴；竞技玩家追求实战表现与阵容搭配。
- 对战环境变化会带来补卡需求；缺少实物时 NPC 去市场找卡，形成真实的买卖原因。
- 低稀有度卡也可因玩法、套装或新手需求成交，避免 N 卡只有垃圾桶一个去处。
- 未售库存有周转压力，但不建议首版增加大量腐坏、强制折旧或复杂税费。
- 初期开桌数量和下注规模有限，升级、客流、声誉带来扩大经营空间，而不是一天赌赢后跳过所有采购。

### 13.2 新手流程

建议用短主线逐步开放：进一批货 → 卖出首包 → 自己开包 → 留一上架 → 看到顾客补卡 → 开第一桌 → 查看战绩和次日行情。尽早说明“挂单还没卖出”和“奖池不是营业额”。

任务必须基于实际经济能力，避免要求尚无流通牌时先赢比赛、还没有桌位时先收抽水。允许无赌注体验对战。

### 13.3 反馈与可理解性

- 商品、市场与对战房分别有清晰入口，柜台名称与人物动线一致。
- 每张卡显示数量、可售数量、保护数量、市场资格和报价原因。
- 开包汇总显示新增与重复，批量行为提供结果清单，不连续弹出几百个窗口。
- 单卡详情保留技能原文与代码查看，新增模式注意事项和统计样本说明。
- 价格变化、成交通知、对局结果进入可回看的营业日志，避免忙时错过。
- 支持键盘关闭与返回、明确焦点、文字缩放；像素场景保持清晰，技能正文不必强行使用难读的像素字。

### 13.4 经济观察与测试

在开发环境提供可导出的日报：商品毛利、服务收入、净下注盈亏、交易周转、滞销、各稀有度库存、NPC 钱包、奖池负债、价格波动、流通卡种数。

正式实施时需要可复现的固定种子模拟与真实引擎抽检。观察长期是否出现：无限回收套利、倒手推价、罕见卡垄断、NPC 破产后无人消费、过量抽水导致货币枯竭、下注收益压过全部经营。模拟结果和真实战绩分开保存。

## 十四、开发顺序与交付边界

本轮仅交付本文。后续实施建议按以下顺序，每阶段单独提交，达到验收后再进入下一阶段；美术可先独立做样板，但最终房间素材应等动线确定后完成。

| 阶段 | 工作 | 交付与通过条件 |
| --- | --- | --- |
| A：规则收口 | 确认本文默认方案、四档含义、市场准入与统计口径 | 一份无冲突规则表；明确迁移与资金口径 |
| B：基础体验 | 全交互暂停；批量开包；批量操作事务 | 不漏暂停、不重复扣发物品；现有存档保持可读 |
| C：卡牌与渠道 | 四档新产品、旧版兼容、所有权/锁定、零售分柜台、二级市场最小交易 | 库存与成本守恒；自营/寄售区分；留一上架可用 |
| D：真实流通 | 顾客开包、NPC 卡库与钱包、流通登记、对战准入替换 | NPC 不凭空用牌；没有专用经营将池；技能不兼容有明确诊断 |
| E：对战房 | 场景扩建、寻路、桌位、NPC/玩家入座、按场收费 | 购物与打牌动线成立；牌局和开桌费只结算一次 |
| F：战绩与行情 | 有效统计、平滑估值、供需、每日发布与任务接口 | 价格原因可解释；小样本不暴涨；测试数据隔离 |
| G：下注闭环 | NPC 稀有度倍率、双方确认、托管、抽水、异常恢复 | 无资金缺口；店主内部转账不虚增收入；重放不双结算 |
| H：美术完成与稳定化 | 样板确认后的角色/地图/动画批量替换，长期试玩与回归 | 四向行走、不同顾客、昼夜效果统一；稳定后再评估 exe |

批量上架在 B 阶段可先完成通用库存筛选能力，但正式交易出口应随 C 阶段二级市场一起交付，避免先做一套马上废弃的正店单卡上架。

战绩与行情 F 先于下注 G，是为了先验证比赛结算与数据可信度；下注本身仍保留用户要求的稀有度决策，不改成只看胜率。

### 14.1 版本与运行方式

- 优先双击根目录 `开发启动.cmd` 使用浏览器源码开发；需要桌面行为再用 `桌面开发.cmd`。
- 保留原有试玩与正式安装版进度隔离；测试使用临时或开发进度。
- 继续用 Git 与现有私有 GitHub 仓库管理开发版本，按模块提交并记录迁移说明。
- 暂不开发 exe 更新器，不新建安装发布流程，不把每次测试调整打入安装包。
- 稳定标准建议是：关键闭环验收通过、旧档迁移通过、连续多日试玩无库存/资金/存档阻断，再单独讨论可携带版本或安装包体验。

## 十五、实施前需要定稿的选择

这些选择不阻止本轮文档交付，也不表示现在需要下载工具或修改游戏。后续开始对应阶段前再确认即可。

| 选择 | 本文建议默认 | 另一种选择及影响 |
| --- | --- | --- |

## 十六、整体验收清单

以下为后续实施的验收用例，不是本轮已经执行的测试。

1. **美术与移动：** 店长及至少两类顾客有不同地图形象与立绘；四方向朝向、待机、行走与碰撞正确；整倍缩放无糊边。
2. **暂停：** 逐个打开所有交互 60 秒，营业、配送、顾客、后台桌计时均不变；嵌套窗口和手动暂停恢复正确，玩家战斗仍能出牌。
3. **渠道：** 正店只接受包/盒上架；单卡从另一柜台交易；旧货架单卡迁移后数量和成本不变。
4. **开包：** 一键开包正确跳过锁定库存；完整开盒固定配额吻合；中断恢复不重发、不重抽。
5. **留一：** 已保护、在赛、在售、预约副本正确扣除；上架不提前发钱；撤单、重复点击均守恒。
6. **四档：** 新产品只使用 N/R/SR/SSR；所有任务、筛选、NPC 偏好与配方同步；旧盒承诺保留且有明确标识。
7. **流通：** 私人开包留藏不自动开放资格；有效市场进入或已售商品实际开包会开放；未付款和预览不会开放。
8. **所有权：** 流通资格不制造 NPC 实物；NPC 买卖后钱包与卡库变化可追溯；同一副本不能一边出售一边参赛。
9. **对战：** 不再用原 25 将作为经营规则；随机抽取不同技能类型跑真实引擎；KOF 继承、BO3 小局与整场结算保持正确。
