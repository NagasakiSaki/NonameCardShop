## ART-03：必须修正的两项

### 1. P1：原图头部坐标仍然错误

`presets/presets.json` 将头框命名为 `headRectSource`，但实际数值没有正确落在 1100×1400 原图的头上。最明显的是乐奈：

| 项目 | 值 |
| --- | --- |
| 交付声明的原图头框 | `[242,98,462,308]` |
| 原图上部 y<350 可见 alpha 的包围范围（仅用于定位对照） | `[442,144,637,350]` |
| 交付自己计算的 384×672 头框 | `[-32,16,79,122]` |
| 交付记录的 96 头像头中心 | x=23 / 裁切框宽192（与中点96明显不符） |

声明框多数覆盖透明空白，只扫到头发左边缘；后续又把裁切起点 clamp 到 0，无法按正确头部中心构图。当前乐奈头像右偏、边缘紧；灯的声明框 `[374,126,572,322]` 也明显左偏，实际头像反而头部贴近右侧。祥子虽比上轮好，仍须统一重新核对头框，不能沿用“全部定位完成”的验收结论。

上部 alpha 范围包含头发、颈部等，只是可复查的坐标证据，**不要直接把它当作精确人脸检测或最终头像裁切框**。

返工方法：

1. 在原图原始坐标上逐人标出真实头框；若看缩放图，明确乘回缩放比例并扣除预览留白。
2. 交一张原图叠加头框的诊断图，能直观看到框覆盖头部；重新导出 96/128 头像。
3. 检查实际图像的居中、头顶/下巴、两侧裁切与留白；必要时允许透明补边，避免 clamp 悄悄移动构图。
4. 增加坐标/安全区告警：负数框、框大部分落空白、声称居中而中心离中点过远，必须报告异常，不能只验证 alpha={0,255}。

### 2. P1：新记录格式导致正常重跑命令崩溃

`results.json` 已改为 `{meta,final,history}`，但 `pixelate_portraits.py` 的 `convert` 分支仍调用：

```python
report["runs"].append(rec)
```

在隔离副本中复制交付的新版记录，运行与文档相同的单人 convert 参数，实测返回码 **1**，报：

```text
OK bd-tomori/retouch/256x448/c64 ...
FAIL bd-tomori/retouch: KeyError: 'runs'
...
report["runs"].append(...)
KeyError: 'runs'
```

这说明转换本身能完成，但记录更新流程已经断开。异常处理里再次访问同一个不存在的键，还会使整批直接退出，不能兑现“单人失败不影响整批”。

修成统一的历史日志读写：兼容旧 `runs` 与新 `history`，转换后保留/更新 `meta/final`；不要在多个子命令之间来回切换不兼容结构。转换失败应记录一条失败后继续下一项，命令末尾才按失败数量返回非零。`avatars` / `export-editable` 也应在发生失败时返回非零，避免只打印 FAIL 但返回成功。

验收只需两步：在已有当前 `results.json` 的副本里正常重跑一次；再混合一个缺失输入和一个有效输入，确认有效项仍生成、历史保留、最终退出码明确。无须重装 PixelOE、重下载原图或全量转换。
