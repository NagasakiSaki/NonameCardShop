## 4. 至少追踪的端到端场景

1. 购物篮报价 → 扣款/赊购 → 到货 → 单次签收 → 货架/仓库 → NPC 支付、拆包与流通；报价过期/无钱/重复请求/丢响应不能半成交。
2. 散包/整盒选择 → 开包预览 → 指定实物结算 → 结果保留 → 重复卡留一上架 → 成交/撤单；保护/锁定/版本/配盒配额保持。
3. 自己丢弃/买家弃牌 → 共享桶 → 店长/NPC 拾取 → 次日清空；一张卡不能同时归两人，来源/成本/流通不因窗口刷新改变。
4. NPC 访问与比赛从进店走到最终离场；技术离场与经营未成交分开；模拟只结一次费、真实牌局事件不能串到新比赛。
5. 日常自动奖励、日结成本、升级/雇佣、熟客请求/活动 → 日初重读/即时恢复；无重复奖励、追溯改价或残留预留。
6. 双窗口暂停 → 关闭一窗 → 手动/后台暂停共存 → 页面重载/销毁；世界、顾客耐心、模拟时间冻结一致。
7. 查询/提交未返回时关窗或读档 → 旧 Promise 返回；旧世界操作不能覆盖新分支，原操作补查不能再扣款。
8. 默认/previous/classic/legacy、启动档案与桌面运行路径；明确共享与隔离边界，不用“只是测试页面”解释实际触达玩家档的问题。

可补更多实际发现；没有实现的下注/完整引擎恢复列为已知功能边界，不凭未开放功能报 Bug，除非入口错误承诺或确有资金/数据影响。

## 6. 问题格式与分级

每个问题一个稳定 ID，例如 `AUD-001`，写：标题、严重度/置信度、影响入口、**已核对的文件与行号**、触发前提、重现步骤、预期/实际、最小证据、调用链与原因、修复建议、回归建议、基线。相似症状同根因合并，不按代码行拆数量。

- P0：常规可触发的不可恢复坏档/重大钱卡错误/核心路径完全阻断等紧急问题。
- P1：明显影响经营或对战的错误、重复结算/状态错配、恢复或关键操作失效。
- P2：有真实影响的局部功能/统计/生命周期/性能问题。
- P3：较低影响的可用性/维护问题，或单独标记“建议”。不将纯重构偏好列成缺陷。

上述只是排序依据，按实际触发/损失说明，不按猜想抬级。结果分四组：**已复现缺陷、代码证据充分但未动态复现、待证实线索、已知未完成功能**。没有发现也如实报告，无最少问题数指标。
