# 武将强度、稀有度与卡包经济 v0.7

本版把评分、稀有度、出货配方、价格和库存成本分开。修改其中一层不需要重写对局引擎、NPC 或任务。默认启动原有项目，刷新页面即可使用；旧收藏 ID 和数量保留。

**卡盒机制更新：** 后续已新增24包实体封盒、固定五档配额与整盒大保底，完整规则见 [BOOSTER-BOXES.md](BOOSTER-BOXES.md)。本文的2%/5%/12%和120/150/230等报价专指独立散包。

## 修正的根因

旧实现按每张武将的稀有度权重抽样，最后强行补一张该包最高稀有度。有 UR 的卡包因此每包必出 UR；UR 数量还会改变总抽样权重。旧分级按扩展出处、技能数量、称号排序，神势力直接 UR。这两种做法均已移除。

现在先抽五个稀有度槽位，再在该槽的候选武将中均匀抽一张。增加十个 UR 武将只改变各武将的占比，不改变出 UR 的概率。

## 定量模型

这是为本游戏建立的设计模型，不是三国杀官方发布的统一强度标准。没有把官方游戏售价、技能字数、AI threaten 参数或武将称号当作强度。实装技能以本项目无名杀 v1.11.6 的卡表及技能代码为准，不能混用其他版本的技能。

环境：中立双方单将对战，正常摸牌为2，四个自己的回合作为估计窗口；另计算 KOF 换将时的手牌/死亡收益。主公技收益为0，多人技按一个对手的有效目标限制，不把身份局八人收益移植到单挑。每回合是自己的一个回合加对手的一个回合，不是八人局一轮。

每个技能的收益按 `可触发机会 × 实际发动概率 × 每次净收益` 折算。限定收益摊到四回合；觉醒和启动按可达性折扣。互斥分支按对手择优或合理混合估计，不能将多个分支全额相加。自动初估的环境默认：受伤事件0.6、造成伤害事件0.65、用牌相关事件1.2、额外条件系数0.55。低可信语义结果乘0.65，单技能各维度上限2.5，武将各维度上限5。逐将校准向量覆盖自动结果，不再乘一次条件系数。

| 维度 | 单位与计算规则 | 分数权重 |
|---|---|---:|
| cards | 每回合相对正常流程的己方资源减对方资源变化；摸1为+1，免费偷1为+2 | 10 |
| damage | 每回合额外实际命中的伤害期望，已扣未命中概率 | 16 |
| guard | 每回合避免伤害的期望，按触发条件折算 | 14 |
| heal | 每回合实际可实现的回复，不能把满血溢出计入 | 13 |
| control | 限制有效行动的回合等价，考虑解除及条件概率 | 12 |
| quality | 筛选、转化与信息改善的牌等价；不作为新增手牌 | 5 |
| cost | 额外耗牌、资敌、跳阶段等机会成本的牌等价 | −10 |
| hpLoss | 技能额外主动失血/上限反噬的每回合等价 | −16 |
| burst | 有限爆发对短局的修正指数，避免与常驻伤害重复记账 | 3 |
| carry | KOF 继承与死亡接力的修正指数，只计入 KOF 分 | 3 |

`BO3分 = max(0, 50 + 10×cards + 16×damage + 14×guard + 13×heal + 12×control + 5×quality − 10×cost − 16×hpLoss + 6×(min(起始体力,6)−4) + 3×burst)`

`KOF分 = 同一公式 + 3×carry`；综合分为两者平均。大于6体力的特殊武将明确打复核标记，四回合模型只给前6点体力底盘分，不能让105体力线性产生六百多分。此规则不改引擎真实体力。分数不是百分制胜率，未来可以超过100。

不要重复记账：普通一牌换一牌不是免费+1；偷牌+2时还要扣发动成本；制衡弃摸等量净牌差0；苦肉摸2失1血为 `20−16=4` 分的资源差，再加有限爆发修正；正常被动受伤已在对局环境中发生，卖血奖励只计算条件收益，额外主动卖血才另扣 hpLoss。

示例校准：曹操奸雄按0.6受伤×0.75实体伤害牌=0.45牌/回合；标准张辽单挑偷1牌相对正常摸2牌净增0，再计关键牌干扰；貂蝉离间需要两名其他男性，单挑计0，闭月仍+1。神曹操只偷一人且有翻面代价，不能照搬多人归心收益。原文与代码线索可以从卡牌详情展开核查。

### 初版数据边界

2563 位均有评分与稀有度；93 位有逐项规则校准估算，2470 位是低可信语义初估，保留解析证据和复核项。代码存在性与描述模式不等于完成了技能程序的语义执行分析；涉及 X、技能获取、使命、随机变身、特殊回合、分支接收者和多技能组合时尤其需要复核。自动识别未理解的效果不按技能数量补分。

可信标记0.75/0.55/0.35等表示数据来源等级，不是正确率或统计置信区间。当前没有声称完成2563位的实战强弱验证。实际 KOF/BO3 合法将池仍由 combat.json 单独管理，评分不会自动开放未验证武将。

## 稀有度

统一分数线，不按各个扩展强行各分一份 UR，也不因“神”或★前缀晋级。

| 档位 | 综合分 | 本版张数 |
|---|---:|---:|
| C | <52 | 1337 |
| U | 52—<57 | 574 |
| R | 57—<65 | 429 |
| SR | 65—<78；或达到UR线待校准 | 209 |
| UR | ≥78 且已逐将规则校准 | 14 |

这是固定门槛产生的分布，不是强行切百分位的配额。2111位的分级相对v0.6改变，原始分级备份在 rarity-before-balance-v1.json。UR晋级需校准的规则可通过 legendRequiresReview 编辑。后续应先补充高分/低可信/对局敏感条目的校准，再重建卡表。

## 商业卡包

借鉴实体 TCG 的固定槽位、基础牌与稀有槽分工。以下概率、五张规格与三档商品为本游戏设计，不能当成宝可梦或万智牌的官方出货率。

| 商品档 | 固定槽 | 最后R+槽：R/SR/UR | 每包平均C/U/R/SR/UR |
|---|---|---|---|
| 常规 | C、C、U、50%C/50%U | 80% / 18% / 2% | 2.5 / 1.5 / 0.80 / 0.18 / 0.02 |
| 进阶 | C、U、U、50%C/50%U | 65% / 30% / 5% | 1.5 / 2.5 / 0.65 / 0.30 / 0.05 |
| 典藏 | U、U、R、50%C/50%U | 45% / 43% / 12% | 0.5 / 2.5 / 1.45 / 0.43 / 0.12 |

每包至少一张R+。独立散包只有末槽可出UR，所以每包至少一张UR的概率为2%/5%/12%，不是每张卡的UR概率。独立散买平均50包/20包/8.33包出一张UR是长期均值，不能保证个人在该包数内抽到。完整卡盒使用后续新增的固定配额，不能将散包概率直接套在盒内余包上。

26个源扩展仍是主题。某档优先抽本包；本包缺该档，依次使用同谱系、全卡池的相同档位补位，不降档、不悄悄提高UR概率。供应商、开包目录标出实际缺档与补位范围；翻出的卡标注补位及原始扩展。各候选池明细在 balance-report.json 和 pack-economy.csv。

商业档位由 balance.json 的 packGrades 明确配置，未指定用常规。默认经典神将采用典藏，神话再临/始计篇/兵势篇采用进阶，其余常规；商业档可以调整，不等同于源扩展tier，更不直接修改武将强度。

## 定价与经营

单卡参考价：C=8、U=16、R=48、SR=160、UR=480。售价继续受到行情、店主倍率、顾客预算与需求影响。参考价不是供应商承诺的无限回收价；收卡与委托仍是每日限量报价。

`E = Σ各档每包平均张数 × 该档单卡参考价`

`进价 = 向上取整到5(E / 1.05)`；`建议整包售价 = 向上取整到5(进价 / (1−30%))`。

1.05是拆卡参考总值/进价的上限，不是105%保证回款；取整后回报可能更低。期望略高于进价，为拆单经营留空间，但需要占用多次交易、时间和货架。整包毛利尚未扣每日营业费、员工工资与库存损失。行情/手动降价可能令实际毛利低于目标。

| 档位 | 卡值期望E | 进价 | 建议售价 | 参考整包毛利 | 拆包价值中位数 | 低于进价比例约 |
|---|---:|---:|---:|---:|---:|---:|
| 常规 | 120.8 | 120 | 175 | 31.4% | 96 | 80% |
| 进阶 | 155.2 | 150 | 215 | 30.2% | 104 | 65% |
| 典藏 | 240.0 | 230 | 330 | 30.3% | 248 | 45% |

这揭示了均值与风险：常规包大多数开出的参考价值低于采购价，少数高稀有卡拉高均值。不能把“期望120.8”显示成“每包赚0.8”。普通路客预算180仍可买常规175；更贵产品依赖更高预算顾客。首日1200资金买3包常规只支出360，不改任务奖励或每日目标来掩盖价格问题。

旧藏数量、仓库和货架保留。原来的订单单价、客户报价、账本采购成本不追溯重算，新单按新规则；混入同名未知成本旧库存仍标未知。首次升级备份存档到 noname-packer-before-balance-v1；旧默认单卡价格的浏览器覆盖配置升级并另存备份，用户自定义价格保留。已持有的未拆卡包采用新出货规则，不再沿用旧必出最高档的错误算法。

## 修改接口与重建

- `data/power-model.json`：权重、环境频率、分数线、逐将 vector/confidence/notes；schema补全及构建时校验。vector 是已经折算好的每回合期望，负面填cost/hpLoss，不填负收益来绕过校验。
- `tools/power-model.cjs`：只负责解析证据及评分，纯函数，可替换更准确的逐技能估值或对局数据模型。
- `data/balance.json`：五个槽位、概率、每个主题的商业档、拆包回报上限和整包毛利目标；经营手账→模块编辑器可以直接调整、校验和导出。旧 wholesaleByTier/retailPackByTier 保留兼容字段，当前正式运行采用这里计算出的价格。
- `modules/balance.js`：前端与离线模拟共用的抽样/补位/报价规则，NPC、供应商和UI使用同一报价入口。下单后冻结单价，编辑不会改历史订单。
- `data/business.json`：单卡参考价、顾客预算、营业费用；改参考价会同时改变新卡包进售价。
- `data/power-audit.csv`、`pack-economy.csv`：全卡表与26包的可核查输出；勿直接编辑生成的 cards.json 来长期维护强度。

修改强度后在项目目录执行：

```text
node tools/build-balance.cjs
node tools/test-balance.cjs
node tools/test-business.cjs
node tools/test-modules.cjs
```

然后刷新页面。修改槽位/经营参数可以直接使用浏览器编辑器；只在本浏览器生效，导出并替换对应项目文件才成为默认值。生成器保留手动packGrades，不会因重新评分偷偷改变商品档位。重新导出源武将数据时也会调用同一构建器，避免旧复杂度算法再次覆盖分级。

## 研究参考

- [三国杀官方武将技能与特点](https://www.sanguosha.cn/index.php/pc/index)：核对技能按不同条件形成的收益；官方介绍不是本模型的数字权重来源。版本差异以本地代码为准。
- [Mark Rosewater：Common Knowledge](https://magic.wizards.com/en/news/making-magic/common-knowledge-2011-04-18)：普通牌承担基础体验与有限赛环境，高稀有牌可提供更大的局面变化。没有据此声称稀有度完全等于强度。
- [Pokémon 官方补充包构成](https://support.pokemon.com/hc/en-us/articles/360000981613-What-can-I-expect-in-a-Pok%C3%A9mon-Trading-Card-Game-booster-pack)：固定普通/非普通/闪卡槽及至少一张稀有以上的组合。仅借鉴结构。
- [WPN：Introducing Play Boosters](https://wpn.wizards.com/en/news/introducing-play-boosters-the-best-of-two-worlds-combined)：参考稀有槽与可变槽的产品设计。这是2023年介绍，不能当成所有万智牌产品的统一配比。

已完成：每包10万次、26包共260万次模拟，检查概率偏差、至少一张R+、补位不降档、卡池扩容不改变档位概率、期望值和参考毛利。另在独立浏览器存档中验证旧存档/价格迁移、冻结旧订单、实际开包、实际NPC付款、编辑器即时改概率与报价、非法配置拒绝、刷新和手机布局。完整实测数据见 balance-simulation.json；这些经济测试不等于全武将对局胜率验证。
