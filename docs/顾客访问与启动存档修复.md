# 顾客访问、NPC 自然对战与启动存档修复

2026-10-24。在真实交易前端基线上修复经营状态与存档入口。用户交给其他模型的美术/界面候选仍在独立交付区，本批没有合并那些候选，也没有重建 EXE。

## 实际使用

使用现有一键启动器打开游戏地址，先进入**卡店存档管理**：可以命名新建、继续现有进度、按日期读档、重命名与删除指定存档。不同卡店拥有独立的资金、卡牌、顾客、行情和日档。启动菜单不推进营业时间，准备画面期间也持有临时暂停令牌。

原来的进度原地保留，自动显示为“原有卡店”。默认旧库仍为 `noname-card-shop-world-v2`，没有复制后删除旧库或清空整个浏览器存储。新建存档不会覆盖旧档。游戏内“存档 → 返回主菜单 / 管理卡店存档”可以切换卡店。

游戏中刷新页面会继续当前选中的卡店；重新打开启动器的无 profile 地址进入菜单。`?profile=legacy` 保留为兼容旧进度和隔离测试的直接入口，不用把它设成新的启动器默认地址。

## 按天回退已经与即时备份分开

- **按天回退：** 选择第几天，读取该天 **08:00 开店前**的完整世界。当天已经发生的采购、成交、比赛和行情变化会回退。
- **即时备份：** 保留原“保存当前进度”、打烊、读档前备份和文件导入/导出，精确恢复所保存的时刻，不再冒充当天开始。
- 第 1 天在世界初始化后保存日初档；开始下一天时，在清桶、日账切换、供货和价格更新等步骤完成后自动保存该天日初档。
- 多次读档产生分支后，日档优先对应当前分支及其祖先，避免意外选中另一条经营路线的同一天。
- 读取日初档会先备份当前世界，再建立新分支并保存新分支自己的日初档。旧报价、预览与操作号不能跨分支重放。
- 保留容量内优先保护日初档，避免反复手动备份把仍在保留期内的每日起点全部挤掉；容量很小时仍受总数量限制，至少为新备份留空间。
- 旧档缺少某一天的日初状态时明确提示，不把中午的快照强改时间为 08:00。今后开始新一天会正常生成。

接口为 `saves.days` / `saves.loadDay`，原 `saves.list` / `saves.load` 保持兼容。具体字段见 [契约说明](../contracts/README.md)。

## 顾客真正进出店

NPC 的持久身份与临时访问分离。钱包、持卡、挂单、关系和战绩一直保留，`presence` 只表示是否在场。

新局只显示店长，固定常客仅有档案，不再自动站进店里。营业中按节奏到访，购物、拆包、弃牌/拾牌之后可以短暂停留找牌友，再走向门口并真正离场；离店者不渲染、不占当前客流容量。之后可以使用同一身份再次来店，资产不会凭空重置。

普通访问的默认停留为 18 秒、上限 120 秒、路径停滞 12 秒；参数放在 `backend-rules.customerBehavior`，旧档缺字段沿用默认。门口保留作通道，柜台/垃圾桶使用可达且分散的停留点，避免所有人都以同一坐标为终点。

打烊、没买到东西、路径异常和比赛离席都有有限收尾。路径异常不会让整个经营时钟因抛错而停止。已付款商品会按原有收尾规则处理；离场本身不删除或赠送卡牌，不制造额外资金。旧存档里无进行中业务的闲置人群迁移到店外，有效购物和比赛保留。

主要模块：`modules/backend/visits.mjs`、`trading.mjs`、`npc-tables.mjs`、`management.mjs`、`world.mjs`。

## NPC 对战与可观察性

后台继续运行原无名杀 AI，未改成按评分判胜。保留暂停、加载/停滞超时与回合上限；新增阶段、轮次、行动者/技能和活动耗时诊断。心跳只是诊断，不用来重置“没有实际进展”的判断。

后台专用展示等待参数在原引擎载入后设置，避免配置载入重置其值；不修改牌序、技能、体力或伤害，也不影响玩家桌的手动操作。NPC 注册函数支持 BO3/KOF 阵容，日常自动调度仍保持原 BO3 默认，不在本次改动中突然改变经营赛制。

牌桌界面明确提示“因交互暂停，关窗后继续”。异常作废显示原因，释放桌位、卡锁并按既有规则处理费用，不计正常战绩。路径无法入座也会取消预备桌并退款，不再永远占桌等待。

旧短测保留其桥接/结算用途；新增自然完赛检查没有强制阵亡、改血或直接调用结束。隔离测试中：

| 模式 | 实际结果与用时 | 同时核对 |
| --- | --- | --- |
| BO3 | 原 AI 自行打完 2 小局，约 134 秒 | 暂停恢复、一次桌费/整场战绩、清锁、离场 |
| KOF | 原 AI 自行打完一场并发生接力，约 177 秒 | 继承/换将流程、整场结算、清锁、离场 |

这是固定种子和基础阵容的验证，不能据此宣称全部特殊技能已经兼容。新诊断用于继续定位具体武将/技能的卡住问题。完整事件栈/随机状态恢复、实际下注仍未开放。

## 验证与维护入口

- `node tests/customer-visits.mjs`：新局空店、常客档案、暂停、到离店、再次到访、分散停留点、钱包/实物守恒、迁移与读档。
- `node tests/day-starts.mjs`：08:00 整体回退、即时备份拒绝冒充、分支来源、日初档保留和容量。
- `node tests/profile-menu.mjs`：新建/继续、独立世界、重命名/指定删除、菜单不走时、按天读取、手机布局、旧库接入。
- `npm run test:npc`：访问检查与原引擎自然 BO3/KOF，属于较慢的针对性检查；默认普通后端组继续使用短桥接测试。

本批还通过共享垃圾桶、员工/经营、异常边界、档案存储、移动、换皮肤、开发刷新、真实交易入口及原版玩家 BO3 集成检查。没有重新运行人物绘制或全量卡池压力测试。
