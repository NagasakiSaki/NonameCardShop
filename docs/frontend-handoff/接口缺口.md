# 接口缺口

依据：交接文档第 9 章契约 `card-shop-ui/1.0`，以及本工作区里主模型正在进行的 `integration/frontend-host.mjs` + `modules/backend/**`。
下表只描述**前端需要什么、用在哪里、现在怎么兜底**，不改后端。凡是已确认与文档示例不同的形状，前端已在 `frontend/host/normalize.mjs` 里归一，业务值一律不自行推导。

## A. 形状与文档示例不一致（前端已归一，建议契约写死）

| # | 查询/事件 | 文档示例 | 工作区实现 | 用在哪 | 前端兜底 |
| --- | --- | --- | --- | --- | --- |
| 1 | `tasks.list` | `{ items: [...] }`，进度字段 `goal` | 裸数组，字段 `target` / `completed` | 手账、任务面板 | `normalize.mjs` 转成 `{items}` 并补 `goal/progress/completed` |
| 2 | `saves.list` | `{ items }`，含 `source/status` | 裸数组，字段仅有档案元数据 | 存档面板 | 缺字段显示「—」，不可读档禁用「读取」 |
| 3 | `snapshotUpdated` / `actorsUpdated` | `event.data` 为统一负载 | `data` 直接是快照 / 直接是数组 | 全局 | 两种都接受（见 `app-shell.mjs` 订阅段） |
| 4 | `management.upgrades` / `management.orders` | 设施/订单列表 | `{ items: [], available: false, message }` | 经营面板 | 显示「该入口尚未接入正式接口」+ message |
| 5 | 受控玩家标识 | 未写 | `player.actorId = 'player'`（Mock 用 `actor:owner`） | 相机跟随、交互距离 | 按 `player → actor:owner → 首个角色` 顺序解析 |

示例（正式实现）：

```js
// tasks.list 实际返回
[{ taskId: "first-order", title: "第一次进货", target: 3, progress: 0, completed: false, claimed: false }]
// 前端归一后
{ ok: true, data: { items: [{ taskId: "first-order", title: "第一次进货", goal: 3, progress: 0, completed: false, claimed: false }], total: 1, nextCursor: null } }
```

## C. 前端自行承担、但需要后端确认的约定

- **卡图 URL**：直接使用 Host 返回的 `imageUrl`（Mock 用 `/img/<file>`，与根 `server.mjs` 的 `/img/` 规则一致）。缺图时前端显示「缺图」占位，不阻断列表。
- **地图版本**：地图文件与 `navVersion` 由本包提供；主模型加载时应校验 `navVersion` 与 `walkable` 长度，不一致就拒绝进入该房间，而不是让角色穿墙。
- **NPC 外观**：前端按 `appearanceId` 取 `manifest.characters` 里的图集；未登记的 id 会退化成首个角色并记录警告，**不会**静默用店长染色冒充。
- **暂停令牌**：前端在打开窗口时申请、关闭时释放；正式 Host 若在会话失联时保持暂停，前端不会自行改回运行。
