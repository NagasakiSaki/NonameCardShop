# 卡包配盒与角色第三版

日期：2026-10-23。适用于正式 Host 的 `/frontend/index.html`。本轮只更新源码，未重建 exe。用户更正后的问题是 **N 太多**。

## 本次可见变化

- 不再发行、进货或零售 DIY、怀旧、Key、联动卡、四象封印、OL 专属、限定专属七个主题。供应商保留 19 个主题，当前发行卡种 1840 个。
- 人物原生帧从 48×64 提升为 96×128，立绘提升至 256×256。增加发束、挑染、发饰、领口、裙褶、围裙、钥匙和随身物品。正面、背面、侧面分别绘制轮廓，侧面有单眼、鼻尖与窄身轮廓；左右采用镜像侧面。四向朝向配合三帧步态，斜向自由移动保留，斜向优先横向朝向。
- 设置顶部新增“店长换装”，七套外观免费选择。店长姓名、身份、资金、卡牌、NPC 性格和玩法不因换装变化，外观跟随世界存档读写。
- 盒配额从主题卡池数量加权改成独立卡槽配方，降低 N，避免某主题几乎抽不到 SR。全局评分与 N/R/SR/SSR 强度边界继续统一，卡片不会为了填满某包的稀有度被单独升降档。

## 真实 TCG 参考及适用边界

参考的是“先定卡槽，再决定槽内稀有度，最后抽卡种”的结构，并非把真实游戏的标记直接对应本游戏强度。

1. Pokémon 官方当前说明：10 张游戏牌包含 4 普通、3 非普通和 3 闪卡，其中至少一张稀有或以上；官方同时明确不承诺整盒特定高级卡比例。由此采用每包 R+ 槽，但**本游戏的整盒固定数量是自主经营设计，并非 Pokémon 官方出货标准**。[Pokémon Center 原文](https://support.pokemoncenter.com/hc/en-us/articles/360028979571-What-can-I-expect-in-a-Pok%C3%A9mon-Trading-Card-Game-Booster-Pack)
2. MTG Foundations 的 Play Booster 分开设置普通、非普通、稀有/秘稀、非闪任意稀有度和闪卡等槽，并公布各槽的内容与概率。这支持把“某稀有度有多少卡种”和“实际能抽几张”分开处理。[Wizards 官方配包说明](https://magic.wizards.com/en/news/feature/collecting-foundations)
3. ONE PIECE OP01 官方列出 45 普通、30 非普通、26 稀有、10 SR、2 SEC 等，指的是系列的**卡种数量**，不能直接理解成一盒出货张数。[OP01 官方产品页](https://en.onepiece-cardgame.com/products/boosters/op01.php)

## 当前自主配盒规则

每盒 24 包，每包 5 张，共 120 张；允许同名重复。

| 稀有度 | 基准盒张数 | 配置允许范围 | 当前 19 个主题实际范围 |
| --- | ---: | ---: | ---: |
| N | 60 | 54～66 | 54～62 |
| R | 42 | 剩余张数补足 120 | 41～44 |
| SR | 15 | 14～18 | 14～18 |
| SSR | 3 | 2～4 | 3～4 |

每包 4 个 N/R 基础槽、1 个 R/SR/SSR 进阶槽。整盒先生成 24 个进阶槽和 96 个基础槽的固定稀有度清单，分别打乱后装包。SR/SSR 只来自进阶槽，因此不会出现全 N 包，也不通过虚假保底跨过同盒剩余库存。

散包单独按对应主题的槽位概率制造，每包同样至少 1R；散买 24 包没有累计整盒大保底，可能偏离整盒配额。盒中的 SR/SSR 张数固定，但具体卡种仍可重复。

主题差异：以主题内武将平均全局评分相对全部在售主题平均评分的差值，除以 `themeScoreSpan=12`，截断为 -1～1 的影响值 t。

```text
N   = clamp(round(60 - 6t), 54, 66)
SR  = clamp(round(15 + 3t), 14, 18)
SSR = clamp(round(3 + t), 2, 4)
R   = 120 - N - SR - SSR
```

高评分主题适度提高高级卡数量，同时提高采购成本。某主题缺少对应档位卡种时，仅从**在售主题**的全局同档卡池补位；供应商仍显示补位说明。停产七主题不会通过补位重新发行。

当前首日示例（游戏币，后续市场变化可能影响新报价）：

| 主题 | N/R/SR/SSR | 散包进价/建议售价 |
| --- | --- | ---: |
| 标准 | 59 / 43 / 15 / 3 | 270 / 390 |
| 神将 | 54 / 44 / 18 / 4 | 330 / 475 |

价格根据各档配额乘以该档实际抽卡池的平均发行价值计算期望卡值，再按 `openingReturn` 求进货价、按 `retailMargin` 求建议售价，金额按 `roundTo` 取整。市场价格对新供货报价的影响限制在单卡发行价值的 ±15%。换日发布新报价，已经付款的订单保留原版本与成本；零售改价仍由店主选择。

## 旧档与实物兼容

- 启动或读取旧日档时，将旧商品目录升级为新发行配方。保留 2563 个历史卡种的身份、卡图、技能、详情和实物引用，避免删除旧收藏或破坏历史牌局。
- 停产主题的在架密封商品退回仓库，不返款、不删除。手动和批量补货、员工补货、NPC 购买均阻止它们重新上架。
- 停产前已付款订单仍可签收；其产品快照与原内容保持。已有卡包/卡盒不因本次改配方重新随机，原盒拆出后仍保持原配额。默认“一键开所有包”跳过停产主题，显式指定旧实物引用仍可拆开。
- 已持有的历史单卡仍可收藏、二级市场交易和按原流通资格参赛。停产限制针对新发行与密封零售。
- 新版皮肤会随手动档、日档、导出与导入一起恢复。浏览器个人字号和缩放仍属于本地前端偏好。

## 模块与修改入口

| 文件 | 职责 |
| --- | --- |
| `data/backend-rules.json` 的 `distribution` | 停产主题列表、120 张基准配额、各档边界、主题浮动幅度 |
| `modules/backend/distribution.mjs` | 配置校验、启售判断、主题配盒公式 |
| `modules/backend/catalog.mjs` | 全局强度评分与档位、历史完整目录、在售发行目录及同档补位池 |
| `modules/backend/products.mjs` | 槽位概率、整盒制造、既定内容、价格计算 |
| `modules/backend/runtime.mjs` | 旧档目录升级、换肤命令和库存/采购事务 |
| `modules/backend/appearances.mjs` | 允许店长选择的外观 ID 和显示名 |
| `tools/frontend-art/characters-v3.mjs` | 原生角色、独立侧脸、步态、立绘绘制；复用 v2 的外观配色定义 |
| `tools/frontend-art/build.mjs` | 生成清单和正式 PNG，清单声明帧尺寸、落脚点、显示比例 |
| `frontend/world/actor-view.mjs` | 帧动画、朝向、实时换装、头顶身份标签 |
| `frontend/ui/settings.mjs` | 换装界面，调用 Host，不修改业务数据 |

生成正式素材：`node tools/frontend-art/build.mjs`。预览：`node tools/frontend-art/export-preview.mjs`，输出到 `.local/frontend-v3/art/`，不会覆盖原交接截图。外形只参考动画角色的视觉特征，顾客行为不绑定相关人设。

`rarityWeights` 保留以兼容旧规则文件，当前新盒配额由 `distribution` 控制。修改配置后次日发布的新商品生效，已制造实物与冻结订单不变。

接口增量：查询 `player.skins` 返回 `{current,items:[{appearanceId,name,selected}]}`；命令 `player.setSkin` 输入 `{appearanceId}`，使用普通 requestId 幂等和原子持久化。`products.list` 新增 `collationVersion`。`catalog.list` 默认显示在售目录，`includeRetired:true` 可查询历史完整目录，`catalog.detail` 继续识别所有旧 cardKey。
