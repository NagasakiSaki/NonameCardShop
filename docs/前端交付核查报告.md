## 已复现的阻断项

| 优先级 | 问题与影响 | 代码位置/修复方向 |

| P1 | **零售页无法读取货架。** 页面调用查询 `retail.list`，后端只实现同名上架命令，查询报 `UNSUPPORTED_QUERY`。 | `frontend/ui/supplier.mjs:211`；`modules/backend/runtime.mjs` 的查询/命令分支。补只读货架视图，明确上架命令与货架实体引用。 |

## 静态对照确认的后续接口问题

这些问题来自参数与响应代码直接对照；本次没有为逐项触发它们而反复运行整套回归。

1. **开包结果接法仍不一致。** UI 使用 `response.data.opening`，后端返回 `{operationId,cards,packs}`；修复请求号后仍不能正确展示结果。结果未知补查使用 response，而后端 operations.get 保存的是 result。留一上架的统计字段也不一致。
2. **存档导入/导出仍是演示占位。** UI 导入传 `{file:'placeholder'}`，没有文件选择；导出只 toast，没有下载 content；读取传 saveId，后端需要 archiveId；保存成功提示读取 `data.save.saveId`，后端只有 archiveId。日档数据层已存在，但前端整条操作链未接通。
3. **营业日缺少开门和打烊操作。** 前端没有调用 `business.open` / `business.close`。正式世界会在准备阶段推进到 09:00 后停住；nextDay 又要求先打烊。需要基于 allowedActions 提供按钮和结算流程。
4. **零售改价/撤架参数不一致。** UI 使用 shelfId/unitAmount，后端操作 inventoryRef/amount；前端也缺少实际上架库存的闭环。
5. **真实持仓与卡牌详情显示不完整。** 正式 inventory.list 是每个实物一行、owned=1；前端没有聚合成“×几”，缺 imageUrl/globalScore 等展示字段。详情把缺失 holdings 兜底为零、referencePrice 兜底为零；后端 price 为数值、stats 为数组，因此有误报零持有/零参考价/零战绩的风险。需要返回真实视图数据，不能猜价格或用零伪装成功。
6. **市场多页签未形成真实分流。** 前端发送 tab/search/rarity，但后端 market.list 只按 status/ownerId 筛选；“我的出售”等视图不能仅靠 tab 字符串成立。收购报价、行情记录和降注也仍有明确缺口。下注目前后端主动关闭，不属于这次新发现的前端退化。
7. **少量交接说明过期。** 接口缺口文档仍称 upgrades/neighbors 未实现、player.actorId 为 player；当前已实现且使用 actor:owner。素材清单也有旧尺寸描述。最终交付应按集成后的真实版本更新。
