## 1. 问题与证据

### 1.1 OPT-06：异步超时根本不经过新分类链路

复核已经指出：`mountNativeRound` 挂载后立即返回句柄，超时由计时器异步 `onEvent({type:'error',code})` 报出；
`host-battle` 收到后只把**文字**传给 `runtime.interrupt`，`v7-room` 的 `catch` 不会触发，界面只能显示一行 reason。

实测（本轮修复前）：

```json
{"phase":"interrupted","reason":"原引擎载入超时；阵容与比分保留，可重试或取消尚未开始的比赛。","code":null}
```

修复后用真实 `createBattleMount` + 真实计时器（等待预算缩到 300ms）复现同一条路径，得到：

```json
{"phase":"interrupted","code":"ENGINE_TIMEOUT"}
```

并验证了房间层面的行为：分类卡片出现、重开不清比分、不重复扣费、放弃释放卡锁、全程无残留暂停租约。

### 1.2 OPT-10：各环节有覆盖，但没有一条“同一天连起来”的闭环

逐项盘点后确认：购物→收银→店内拆包→弃牌→拾牌已有 `tests/customer-trash.mjs` 的强断言（成本守恒、购买不提前拆包、
拾取不可重复）；NPC 牌桌有 `tests/three-formats.mjs` 的“三将阵容、结算一次、付费一次”。缺的是：

- 模拟比赛的**桌费各半**与**日账服务收入**是否对得上；
- 结算后**牌桌释放**、**离桌回店门再离店**是否干净（trip / currentMatchId / reserved）；
- **关店清场**、**跨日无隔夜队列/行程/预留**；
- **存读档**后实物与资金是否一致。

这些正是新测试补的部分。

### 1.3 OPT-11：短屏下的“确认可达”没有证据

既有 `trade-workspace-scroll` 覆盖 1440×900 的千行滚动、搜索焦点、选中后滚动保持；`pack-roster-browser` 覆盖跨包多选、
模式排序、右键详情与 390×680 窄屏确认。**短屏高度**（560/480/420）没有覆盖。

实测发现：在 1280×560 时“确认单卡上架”按钮初始位于视口下方（`bottom=589 > 560`），但在 `.window__body` 的滚动范围内
（`scrollHeight 1007 / clientHeight 483`），滚动后完整可见且可点击。**这属于可接受行为，不是缺陷**，因此没有改样式，
而是把“窗口体可滚动 + 滚入后完整可见 + 能真实提交”写成回归断言，避免以后被改成 `overflow:hidden` 或固定高度裁掉。

## 3. 兼容影响

- **存档**：`series.interrupt` 多一个 `code` 字段；旧存档没有该字段时房间回退到“牌局已中断”中性文案，不报错。
- **失败语义**：不改变任何结算规则；`RESULT_CONFLICT` 仍不记为胜利，`MOUNT_CANCELLED` 仍不算失败。
- **经济**：`interrupt` 不碰钱包、不改比分、不释放卡锁（测试已断言）；桌费只在结算或取消时按既有规则动。
- **界面**：interrupted 面板文案更具体，按钮与命令不变。
- **适配器**：`battle.mount` 新增可选 `loadTimeoutMs`，不传时行为与之前完全一致（默认 60000）。

## 5. 未覆盖范围

**OPT-06**
1. 只验证了 `ENGINE_TIMEOUT` 这条异步路径；`ENGINE_ERROR`（引擎页主动报错）与 `RESULT_CONFLICT`（同局不同赛果）在房间里仍走同一条 interrupted 分支，但没有单独的自然复现。
2. 没有在真实安装版 EXE 里验证（未重打包）。

**OPT-10**
3. 顾客因预算不足放弃购买、路径不可达（`NPC_ROUTE_TIMEOUT` / `trash-unreachable`）导致的技术中断没有覆盖。
4. 跨日用的是纯函数推进时钟（`w.clock.day+=1`），没有走 `business.nextDay` 命令链；玩家侧日初回退由 `tests/day-starts.mjs`、`tests/operations-v7.mjs` 覆盖。
5. 存读档在 Node 侧用 `createRuntime` + 内存仓库验证；浏览器真实 IndexedDB 的跨日读档由 `tests/storage-archives-browser.mjs` 覆盖存储层，但没有把两者合成一条浏览器端到端。
6. 自然对局（真实引擎跑 NPC 牌）由 `tests/npc-natural-browser.mjs` 单独覆盖，本轮未运行。

**OPT-11**
7. 短屏只覆盖交易工作区的上架确认；选将/备战确认在 560 高度下未单独测（390×680 由 `scroll-and-album-browser` 覆盖）。
8. 触摸长按打开卡面详情没有单独验证（现有入口是右键与“卡面与技能”按钮）。
9. 未做真实移动端设备验证，只用 Chromium 视口模拟。
