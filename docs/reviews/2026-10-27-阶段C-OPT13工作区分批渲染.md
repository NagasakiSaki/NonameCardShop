日期：2026-10-27。范围只限交易工作区的收藏列表，查询缓存、存储与模块拆分未动。
同一脚本、同一夹具、同一环境（AMD Ryzen 7 8845H / 逻辑处理器 16 / node v22.22.2 / Chromium 156.0.8078.4）。

> 后续复核：首屏提速成立，但首批底部会同步补齐全量、旧滚动 rAF 在筛选后仍会污染草稿；滚动性能样本又复用了已加载全部行的窗口，不能归因为批次追加。第一项尚需补修，详见 [分批交付复核](2026-10-27-阶段C-OPT13分批交付复核.md)。本文件与原始数据保留。

## 1. 计时口径先补正

复核指出的三处口径问题，本轮先修脚本再改实现：

| 问题 | 修正 |
| --- | --- |
| `allRowsReachableMs` 是第二段等待 | 两个终点都从**同一次 `openPanel`** 起算，`allRowsReachableMs` 是累计值 |
| “首批可交互”只测可见 | 现在会**真的点一下**第一行，并要求 `aria-pressed` 变 `true` 才算成立 |
| “完整可达”只看 DOM 最后一行 | 现在要求出现 `data-row-index = total-1` 的**最后一条逻辑数据**并点中它 |
| 搜索超时被吞掉 | 超时记为 `applied:false` / `valid:false`，打印失败并让脚本返回非零 |

另外新增两项检查：快速滚动（连续大跨度跳转后仍要到达末行）、缩放（视口变窄后仍可达）、关闭清理（组件移除、DOM 回落、窗口栈清空）。

## 2. 实现

`frontend-next/components/workspace/collection.mjs`：

- 列表按 **120 行一批**渲染，滚动接近底部再追加下一批；
- 用户落在**硬底部**时贴住底部继续补，直到真正渲染到最后一行——否则一次跳到底只补一批，内容变高后又不在底部，永远到不了末行；
- `state.chunkRows` 记住已渲染行数：世界刷新触发整体重绘时按原数量恢复，**不会把滚到一半的玩家扔回第一批**；
- 筛选/搜索/排序变化时重置为第一批；
- `dispose()` 移除滚动监听，避免关闭后仍在追加；
- 网格新增 `data-total-rows`、`data-rendered-rows`，每行新增 `data-row-index`，用于验证“逻辑行”与“已渲染行”的区别。

**没有做定高虚拟化**：卡名可能换行、缩放会改列数，定高窗口会带来错位与“串卡”风险。分批渲染保留原生布局、连续滚动和所有行可达，代价是滚到底时仍要补齐 DOM。

**诚实结论**：

- 首批可交互 3.4×（1,000 行）/ 4.2×（2,563 行），打开窗口 7.8× / 14.8×，首批 DOM 从全部降到 120 行。
- 末行可达只是小幅改善（863→831 ms、3,722→3,004 ms）。**因为分批只减少“先画多少”，不减少“要画多少”**；要真正压低末行可达时间必须做定高虚拟化或换行策略，本轮没做。
- **1,000 行滚动期长任务反而多了一次**（803→912 ms）：追加批次发生在滚动过程中。这是分批的代价，不隐藏。
- 5,000 行的滚动帧数没变（5 帧），长任务从 2 次 2,210 ms 降到 1 次 1,899 ms。

## 7.1 一次性补齐全表 → 每帧一批 + 预取

`fillToBottom` 原来在同一个 rAF 里 while 追加并把 `scrollTop` 贴到新的 `scrollHeight`，
下一轮仍满足“距底 8px”，于是一次回调就把剩余行全部画完。

现在：

- 每帧**最多追加一批**，追加后不碰 `scrollTop`（当前可见卡与滚动位置不变）；
- 预取阈值 600px：滚到距底 600px 就开始追加；
- 仍在底部时**下一帧**继续，而不是同帧 while 到底；
- 批次大小：首批 120 行，之后按已渲染量翻倍并按列数取整（避免批次边界出现半行）。

## 7.2 失效的排队回调 → 代次 + 连接校验 + 取消

- 每次重绘 `gridGeneration += 1`；
- 异步回调必须通过 `generation === gridGeneration && grid.isConnected` 才能追加或写 `state.chunkRows`；
- 清理时 `cancelAnimationFrame` 并再递增代次，双保险。

**负向对照**：把实现退回“只检查 `disposed`、不取消 rAF、无代次”，新增回归立刻复现复核现象——
`旧网格不能再被追加：240 → 1000`；恢复修复后通过。

## 7.3 滚动样本按阶段拆开

`tools/perf/browser.mjs` 现在分四段，各自记录起始 DOM 行数与视口位置：

| 阶段 | 起点 | 说明 |
| --- | --- | --- |
| A 首批可交互 | 全新打开 | 点中第一行（`aria-pressed`） |
| B 首批跨批边界 | **重新加载页面后**全新打开 | 只滚到“追加发生”，记录追加行数、帧数、长任务 |
| C 末行可达 | 与 A 同一次打开 | 滚到 `data-row-index = total-1` 并点中；不再与 B 混算 |
| D 已加载重复滚动 | 全量已渲染 | 标注 `stage` 与 `rowsAtStart`，不再冒充“批次追加滚动” |
| E 快速跳转 / 缩放 / 关闭清理 | — | 各自记录可达性与清理结果 |

## 7.5 新增回归

`tests/workspace-virtualization.mjs` 增加：

1. **普通滚轮跨批边界**：连续滚轮，每次追加不超过一批，且不会一次补完全表；
2. **排队回调 + 立即筛选**：同步派发 `scroll` 让监听器排队 rAF，同一任务里改搜索词；
   旧网格 `data-rendered-rows` 不得增加、必须脱离文档，新网格只渲染自己的首批；
3. **排队回调 + 切页签**：同样的保护对页签切换生效；
4. **共享状态不被污染**：清空筛选后最多再追加一批（批次翻倍），不会变成整表。

原有断言未放宽：末行仍要 `data-row-index = total-1` 且可点中，选中不跳顶，焦点保持，缩放可达，关闭清理。
