# 常驻旧服务导致新模式不可用

日期：2026-10-26。用户实际打开的是 5190/5191 开发服务和当前新档，并非旧 EXE。

## 根因与现场

昨天启动的 `dev/launch.mjs` 进程仍占用端口。它能从磁盘读取新前端文件，但 Node 已加载的旧引擎 HTTP 路由未更新。现场 `/shop-integration/modes/capabilities.json` 返回 404，因此正式 Host 得到空能力列表，斗地主和 2v2 显示“原生模式适配尚未通过探测”。

旧一键启动只检查开发服务标记、runtime.ready 和 entry.js，误判为已经就绪并复用。此前临时测试服务从新源码启动，未覆盖实际运行环境，导致报告可用而用户无法选择。

## 修复

- 开发服务启动时保存后端来源指纹，并在状态接口返回实际加载的指纹、进程 ID 和项目路径。
- 一键启动同时核对源码指纹、两个原生赛制能力接口、引擎入口和 bootstrap 路由。指纹不同或缺少接入路由的服务不能被判为新版就绪。
- Windows 下仅自动替换命令行入口精确匹配本项目绝对 `dev/launch.mjs` 路径的 Node 进程。不能确认归属、候选不唯一或端口属于其他程序时，明确报错，不终止其他进程。
- Host 的能力读取失败不再静默吞掉。界面提示重新运行一键启动及刷新；真实内核不兼容报告依然保留，不绕过能力检查强行启用。

## 验证

`node tests/service-health.mjs`、`node tests/server.mjs` 通过。覆盖当前服务、指纹过期、404 能力接口、精确进程归属、伪装参数及多进程拒绝、友好错误与真实不兼容原因保留。健康检查加入 `test:dev` 和 `test:rooms`。

实际执行 `node dev/start-game.mjs --no-open`：成功识别并替换旧常驻服务。第二次执行复用当前进程，无重复启动。实际服务两种 native profile 均返回 supported:true。

通过 Edge 的用户原存档页面验证：现金仍为 1610、第 1 天 09:32、原手动暂停状态保留。斗地主换边 BO3 和 2v2 BO3 均显示可用，分别点击后都成为选中模式。未创建房间、未改库存或结算比赛。现场截图：`.local/live-mode-repair.png`。

本轮没有清档、改引擎版本或更新 EXE。
