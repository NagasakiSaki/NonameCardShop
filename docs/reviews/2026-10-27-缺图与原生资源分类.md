## 3. 原生对局资源错误（C-04）

### 3.1 复现方式

```powershell
npm run audit:native-resources -- --scenarios landlord,versus --out test-results/native-404
```

脚本用随机端口启动服务，在 `/experiments/native-modes/index.html` 上依次挂载斗地主与 2v2，
记录所有 `>=400` 响应与请求失败，按 `resourceType` 分类为 blocking / optional / aborted。

### 3.2 结果

```json
{"distinct":40,"blocking":0,"optional":1,"aborted":39,"occurrences":42}
```

| 类别 | 条数 | 说明 |
| --- | --- | --- |
| blocking（脚本/文档/fetch 失败） | **0** | 没有任何资源阻断原生载入 |
| optional（图片/音频缺失） | **1** | `engine:/audio/card/male/tao.mp3` → 404 |
| aborted（`net::ERR_ABORTED`） | 39 | 拆帧时仍在预加载的引擎模块被取消，属正常收尾，不是缺失 |

唯一真实缺失是出牌音效 `audio/card/male/tao.mp3`：`vendor/noname/audio/card/male/`
共 79 个文件，没有 `tao.mp3`（只有 `taoyuan.mp3`），属上游资源本身缺项。
影响：打出「桃」时没有该音效，引擎继续运行，不阻断对局、不影响赛果。

### 3.3 关键发现：引擎首次载入会弹 GPLv3 确认框

排查过程中定位到一个会伪装成“加载超时”的真实机制：

`vendor/noname/noname/entry.js` 在 `localStorage.gplv3_noname_alerted` 为空时执行
`confirm(...)` 显示无名杀 GPLv3 声明，用户点“确定”后才写入该标记并继续 `boot()`。

- `localStorage` 属于**引擎 origin**（含端口）。桌面版固定 51741、开发版固定 5193/5191，
  所以正式游玩只在首次出现一次，之后不再打扰；玩家侧不是 bug。
- 但**任何用随机引擎端口的自动化**（测试、诊断脚本）每次都是“首次”。如果不注册
  `page.on('dialog')`，载入会一直等到 60 秒挂载超时，然后报
  `ENGINE_TIMEOUT 原生牌局载入超时`，并伴随 26 条 `ERR_ABORTED` 的引擎脚本。
  这些 aborted **不是**缺失资源，很容易被误判成 C-04 的 404。
- 现有 `tests/native-modes-browser.mjs` 已注册 `page.on('dialog',d=>d.accept())`，
  所以一直是 PASS；本次新增的诊断脚本最初漏了这一步，因此复现了假超时。

处置：诊断脚本补上 dialog 处理，并把 dialog 记录进报告（`engineDialogs`）。
未改动 vendor，也未在运行时自动替玩家接受许可声明。

### 3.4 未覆盖

- 只跑了 `landlord` 与 `versus` 两个场景、每场约 20 秒，不是完整三局系列，也不是全武将。
- 只覆盖玩家侧原生挂载；NPC 后台引擎（`integration/npc-engine.mjs`）的 404 未单独采集。
- 未按武将维度统计“哪些技能触发缺图/缺音效”。
