# 明亮前端与全设施重绘接入

日期：2026-10-26。当前源码开发版，不更新 EXE、不清存档、不修改经济/胜负/时间规则。

## 候选核查

交付位于 `deliverables/frontend-bright-anime/`。已核对 DELIVERY、FILE-MAP、API-GAPS、绘图源、图集和对照截图。

- 76 个设施/状态登记项确有新绘图源、图集和单品；地砖帧64、家具单元384。与原 manifest 逐项比对，世界宽高、footY、遮挡及地砖 ID 顺序相同。
- 候选界面主要是 CSS 与五类静态演示，不是已绑定真实 Host 的完整替代前端。其正式接线、真实对局区、逐页管理/存档适配并未完成，未按“整包覆盖”安装。
- 候选人物稿仅为原行走图调色，不是五官/服饰重画。本轮保留已认可的原行走帧、动画协议及用户立绘，没有把调色冒充精修完成。

## 正式接入与补做

1. 新资源独立放 `assets/frontend-bright-anime/`，原资源保留；manifest 只替换渲染引用与采样规格，不改导航、地图 JSON 或角色协议。
2. 正式入口加载明亮令牌和候选主题；补 `bright-panels.css`，覆盖候选未处理的设施、交易、三赛制、世界对话、经营手账、启动存档及旧等候控件。卡牌详情的 Shadow DOM 也加载同主题，避免只让外框变亮。
3. 保留既有真实查询/事务、报价/预览、日档、暂停租约、滚动保持、右键详情、原生 iframe 和队友控制；原生引擎自身 UI 不被站点样式穿透。
4. 灯光按 Host 分钟变化，白天关闭暗层；夜间限制压暗并增加柔和暖光。光晕与脚影使用明确世界尺寸，不因源图变大而扩大四倍。补墙脚阴影、窗光和浅底中文名牌。
5. 包装通过稳定 productId 映射到七组新绘制配色，供所有已有主题读取；名称、价格、出率仍来自 Host，未按中文名猜主题，未新增业务字段。
6. 补可重复构建的 `tools/frontend-art-bright/`。`art:bright` 生成资源，`art:bright:install` 校验几何兼容后更新美术映射；运行不依赖交付目录。图集展开约45MiB，压缩约388KiB，两者没有混作一个指标。
7. 调整默认字体、补控件对比度、简化交易副标题；临时提示最多保留两条，可点击关闭，避免连续操作堆满右侧。
8. 更正 operations-v7 的 CombatFormatId 类型，去掉已删除的单将 bo3 字面量；没有重新加入第四种赛制。

- `node tests/scroll-and-album-browser.mjs`：通过。1280×720 / 390×680 的固定确认、长列表与异步刷新滚动、右键技能、旧盒配比及真实斗地主载入。
- `node tests/bright-frontend-browser.mjs`：通过。真实 Host 隔离存档下的场景、夜间、名牌/脚影、收藏、任务、日报、日档、设置、顾客、伙伴、垃圾桶与 Shadow DOM 详情。对话截图单独用展示 fixture，不冒充一次真实高手事件。
- `node tests/operations-v7-browser.mjs`：通过。真实卡店→备战→逐局选将→原生引擎→整场胜利，覆盖 KOF、斗地主和2v2；含接管/交还与真实高手邀请、延期和暂停租约。

证据位于 `.local/bright-integration/formal/`、`regression/`、`three-formats/`，未读取或覆盖用户真实卡店。测试中的资金与场景是隔离夹具，不代表新档赠礼或开局金额。
