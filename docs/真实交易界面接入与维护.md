## 接口补充

完整接口和类型见 [契约说明](../contracts/README.md) 与 [类型文件](../contracts/card-shop-host.d.ts)。本批为 v1 的兼容扩展，没有实现或宣布启用规划中的 v2。

1. `supplier.basketQuote({lines})` 冻结 1～38 个不同商品/单位行，每行严格整数 1～20。返回整篮总价、逐行供货/价格版本、现金和授信预估。
2. `supplier.placeBasketOrder` 使用顶层 `quoteId` 和空 payload。所有行在一次事务内下单；任意行变价、停产、过期或资金不足，全部拒绝。返回普通订单及实际现金/授信扣款。
3. `inventory.sealedSummary` 按 productId/productVersion/kind 聚合，仅返回数量、可用实物引用和公开规格，不能携带预制卡牌内容。
4. `inventory.list({grouped:true})` 新增 `availableRefs` 和 `referencePrice.amount`。只允许使用 `availableRefs` 选取未保护、未锁定的可售收藏。
5. `retail.list` 行新增 productId；其 unitAmount 指第一件在架商品的价格。批量补货实际命令为 `retail.listAll`，没有 `retail.refill` 命令。
6. `market.list` 增加玩家 holdings。买入/自营挂单筛选印刷稀有度；街坊求购和成交记录筛选当前全局强度，界面分别标注。

页面草稿只在当前 app 内存中保存，含购物篮、筛选、滚动和待确认操作。关闭窗口后可恢复，刷新整个页面则不承诺恢复草稿；已提交的订单、开包结果和实物仍由正式世界保存。

## 结算与异步约定

- 预览/报价不扣款、不产生订单，不展示密封结果。签收不自动开包，开包不重复收费，上架不提前产生收入。
- 每笔业务保留原 requestId、quoteId/previewId 和完整参数。响应丢失后先补查或原号重试，不生成新号再次扣款。
- `operations.get` 原响应在 `data.result`，业务数据在 `data.result.data`；不能把操作状态本身当作交易结果。
- 请求返回后复核 worldId/branchId。读档后旧分支操作标记失效，旧报价、预览、选中的实物引用需要重新核对；购物篮数量可以保留。
- 已关闭面板忽略迟到的查询结果。关闭前已提交的交易仍可能结算；重新打开后保留同一操作的补查入口。
- 内嵌详情独立持有暂停令牌，关闭详情不会让父交易窗口下的世界继续走时。前往柜台会关闭旧窗口，再完成自动行走。
- 搜索防抖不能刷掉已出现的批量确认。Shadow DOM 输入框使用 composedPath 的真实输入节点判断快捷键。

## 验证与维护

`npm run test:trading` 运行采购业务、收藏/市场、开包、大图源码和正式入口五套相关检查。它们使用隔离的内存/浏览器测试世界，不操作当前玩家存档。

开发服务已监听 `frontend-next/` 和新包装图目录。交易页的 Shadow DOM 样式修改会在关窗且玩家牌局结束后刷新页面，避免只更新外层 link 而交易页仍使用旧样式。

本批还检查了后端视图、连续移动和原集成路线：

- 混合包/盒整篮采购、现金与授信、任一行失败全部回滚、持久化幂等、跨日和读档后报价失效。
- 人为丢失已成交的采购/买卡/开包响应后，原号重试不重复扣款、不重复制造卡牌。
- 实际签收、保护商品排除、部分拆盒与成本守恒、开包结果重开保留、原画/技能源码与嵌套暂停。
- 实际挂单和留一批量上架、印刷与全局分级差异、按容量零售补货、首件售价、输入快捷键和 406 像素布局。
- 连续斜向行走、同场景跨房、柜台自动寻路；兼容路线的原无名杀手动 BO3、日结、档案导出/读取/导入。
