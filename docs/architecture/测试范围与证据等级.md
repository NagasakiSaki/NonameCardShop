# 测试范围与证据等级

可执行文件仍只登记在 `tests/groups.mjs`；`tests/check-map.mjs` 把 OPT-01～22 关联到现有检查、报告、诊断命令和人工条件。任务测试通过不自动表示任务完成，尤其性能测量、备份恢复、跨机器素材、上游升级与阶段 D 方案。

```powershell
node tests/run.mjs --task=OPT-13 --list --details
node tests/run.mjs --task=OPT-13
node tests/run.mjs all --list --json-list
npm run test:all
node tests/run.mjs --failed-from=test-results/某次运行/summary.json
```

单项改动先按任务选测。`--task` 会跨组找齐相关检查并去重；原组名与默认 `all` 保持可用。没有执行检查的任务只能列出人工/测量要求，直接运行会非零退出，不能输出“零项全部通过”冒充验收。

跨结构改动完成后跑一次默认完整回归；失败补跑读取原结果，仅执行失败文件，保留原别名组信息。原失败若位于默认组之外也不会消失，旧入口所需的服务仍会启动。日志和 JSON 保存本次来源 `rerunFrom`，原记录不覆盖。完整/补跑范围必须同时写入交付。

结果条目附 `tasks`、`evidence` 和 `estimatedCost`。成本 low/medium/high 是按导入和原生场景作的执行前估计，实际 `seconds` 才是耗时；标签不代表测试已经执行。一般浏览器检查仍使用受控夹具，不能称自然用户全过程。

| 证据 | 能证明什么 | 不证明什么 |
| --- | --- | --- |
| component-or-host-fixture | 组件/Host 在指定夹具下的断言 | 真实店铺长期营业、真实磁盘性能 |
| browser-controlled | 浏览器 UI 在隔离上下文的行为 | 玩家存档、真实低端机/触摸设备 |
| native-controlled-fixture / native-controlled-death | 原生引擎启动和指定事件/死亡/结果边界 | 自然完成局数与自然胜率 |
| native-ai-autoplay-natural | 原生 AI 自然运行且无注入胜负的相应场景 | 全技能、全赛制、长时间稳定性 |
| asset-hashes-and-dimensions | 登记素材的字节和尺寸符合基准 | 视觉美观与跨机器像素一致 |
| runtime-dto-not-dts-compilation | 运行时 DTO 样本符合测试预期 | `.d.ts` 编译一致性 |
| legacy-entry-not-current-gameplay | 历史入口的组件或兼容行为 | 当前正式玩法支持旧模式 |

`native-modes-browser` 同时含四场景启动、受控死亡/接管和两场自然 AI 结果，标为混合证据、高成本，不能把其中受控部分计作自然场次。`native-modes-series` 是受控系列。`npcNatural` 是非默认历史后台引擎路径，当前 NPC 默认模拟，不能拿它验收当下客流逻辑。

历史规格的归档理由和替代覆盖在 `docs/archive/test-specs/README.md`，继续保留原失败和旧记录。`.d.ts` 未引入 TypeScript 编译检查；触摸、EXE、低端机、双标签并发和真实 IndexedDB 长跑仍有独立缺口。
