## 参考与取舍

参考 [Yarn Spinner Dialogue Runner](https://docs.yarnspinner.dev/components/dialogue-runner) 将流程、表现与状态服务分开，参考 [Ink StoryState](https://github.com/inkle/ink/blob/master/ink-engine-runtime/StoryState.cs) 保存完整执行进度，参考 [Transactional Outbox](https://learn.microsoft.com/en-us/azure/architecture/databases/guide/transactional-out-box-cosmos) 将业务变更与事件在同一事务内持久化。

这些是架构参考。本项目继续使用 JSON 制作源、Phaser 世界、HTML 窗口与现有 Host/IndexedDB；没有引入 Yarn/Ink、数据库或消息队列。轻量等待回执与业务世界一起提交。

前端只使用 Host 查询/命令，不能签发奖励或判断资格。内容作者只改制作源，不能改生成包或存档。业务扩展复用领域助手，不在剧情里重写采购、结算或引擎。

## 内容制作和版本

```powershell
npm run story:validate
npm run story:build
npm run test:narrative
```

validate 执行结构校验与 5 个文本预演；`preview-fixture` 不证明真实销售或引擎。build 使用 `runtime.json.contentRevision`，核对外形在现有 manifest 中存在，输出 `data/story/*.storypack.json` 和索引；制作流程里的修订号被正式修订号覆盖。

运行包 `card-shop-storypack/1`、API `card-shop-narrative/1`、持久状态 `world.narrative.version=1` 与 Host UI 合同、无名杀 profile 分别维护。r2 为当前版本，r1 为历史兼容包。索引 `active` 按战役选择新会话版本；`current` 为旧工具保留单个默认入口。

**campaignId + contentRevision 已发布后不得换内容。** 修改台词、出口、条件或动作参数前提升修订号再构建，保留旧包。新会话用活动版本，已有会话继续绑定完整 contentHash。禁止改 hash、清游标或硬套最新节点来恢复旧档；删除历史包需另做迁移政策与可恢复备份。

## 正式 Host 接口

查询 `narrative.available` 返回入口、当前会话、能力与诊断；`narrative.session` 返回当前会话，也可指定 sessionId。业务快照新增可选 narrative 摘要，旧前端可忽略。

命令有 enable/start/advance/choose/defer，前缀均为 `narrative.`。每次带稳定 requestId 和 worldId/branchId；推进、选择、暂缓携带查询给出的完整 proof，不能拼装旧游标。

```js
const queried = await host.query('narrative.session');
const request = {
  requestId: crypto.randomUUID(), type: 'narrative.choose',
  payload: {...queried.data.proof, choiceId: 'c01_opt_collection'},
};
const result = await host.command(request);
```

结果未知时查 operations.get({requestId})；需要重试则重发原请求。游标修订号属于会话，不随营业时钟每次更新变化。读档前分支的迟到请求会被拒绝。narrativeUpdated 只在提交成功后通知查询，不能当作重复执行命令。

窗口关闭必须核对 world/branch/session；同 ID 会话读档后属于新分支，旧窗口不能暂缓它。界面显式点击“故事”进入，不在自然经营中强制弹窗。

## 节点、等待和时间

基础节点 line/choice/wait/action/end；扩展内建 branch/cue/transition。未知节点拒绝，连续解释最多 128 步。条件树 all/any/not 与 predicateId 有深度/容量上限，内建 metric.atLeast、flag.equals、chapter.completed、world.phase、world.dayAtLeast、event.occurred。选项条件展示和提交都检查。

wait 的 historyPolicy 区分：include-prior-actual-business 允许指标使用此前真实累计记录（首章首单）；since-wait-entry 固定进入时指标基线，读档不重设。事件条件只订阅进入等待后的真实提交，不回查最近 1000 条展示日志。每个会话保存独立命中证据，包括世界、来源分支、序号与时间。

同一事件的 actual-business 与更严格的 actual-player 证据分开；玩家证据检查已完成、非后台、非模拟且未取消的对应真实牌局。这个来源检查不等于某个牌技资格已实现。闭店默认走 onDeferred；跨天等待明确设 dayEndPolicy:'continue'。

阅读时由 WindowManager 暂停；等待交回经营时只释放剧情自己的租约。NPC 对战不暂停；玩家比赛的暂停与整场结算时间仍归现有比赛生命周期管理，剧情不再加时间。

## 原子副作用与存档

动作同步执行于现有世界 fork，不可嵌套 await/调用 Host.command，不可请求网络。异常回滚外层命令。需要正常业务失败出口时声明 handledErrors，先恢复动作前快照再走 onFailure；未知异常仍回滚整次事务。

效果幂等键为 sessionId|effectId，保存签名、内容 hash、结果与时间，不能把当前 branchId 放进键。游标、回执、钱和世界一起提交；提交失败不单独到账。回到效果之前的日初档时，资金与回执一起倒回，可以正常重放。

正式首章只有受限 narrative.setFlag，不能改真实销量、战绩、卡牌或资格。practiceQuestUnlocked/fridayEventPlanned 只是剧情意向，不等于已训练/开桌/承办。

扩展动作必须声明 authorityEffects；非空默认需要玩家确认，describe 为纯函数，返回不超过 8000 字符的玩家说明。经审查的自动奖励可显式 confirmationRequired:false。注册代码是受信任源码，声明不是安全沙盒，必须核对实际副作用。

新档默认开启；旧档默认关闭、玩家主动开启，没有重发赠品/奖励。手动档、日初档、导入档保留整个剧情命名空间。未来未知状态版本整体保留且暂停解释。

启动时加载当前世界与全部本地档案引用的历史包；导入外部档时在恢复前按需校验、安装本地保留包，无须重载页面。安装不激活旧包为新会话版本。缺内容/节点时保留进度、暂停该剧情，经营继续；补齐正确包后显式续读。不会从任意网络地址下载代码。

## 新玩法的接入方法

createHost({storyExtensions}) / createRuntime({storyExtensions}) 可追加 actions/predicates/nodes/eventTypes，不能覆盖内建 ID。使用领域前缀，描述符当前 version:1，内容 requires 明确声明能力版本。

```js
const storyExtensions = {predicates: {
  'shop.dayThree': {
    version: 1,
    validate: p => p && Object.keys(p).length === 0 ? [] : ['no parameters'],
    test: ctx => ctx.world.clock.day >= 3,
  },
}};
const registry = createRegistry(storyExtensions);
const pack = await compileStoryPack(payload, {registry});
```

CLI 当前构建内建首章；自定义能力用公开编译 API 传相同注册表，并为构建入口增加显式配置。JSON 不允许函数、import URL、eval 或脚本路径。自定义节点提供 validate/step，可选 present/advance；前端 openStory(app,{presenters}) 注册表现，缺表现保留进度、允许暂缓。条件/描述/present 必须纯查询，重复查询不改变 RNG、钱或游标。

经济动作复用同步领域助手，在同一 fork 内校验成本、持有权与资格，生成真正领域事件。新赛事先做好比赛接口，剧情等待其真实结算。更新无名杀由原适配层维持稳定领域事件，台本不引用其内部对象或上游路径。

transition 目前只提供旅行协议边界；没有 world.travel 时走失败出口，不移动人物。未来先实现路线/地图注册、旅行助手、离店经营政策与旧档迁移，再开放旅行。cue 只是可继续的演出标记，没有镜头/音频系统。

## 范围和证据

序章、第一章与三条支线复用立绘，以联系人对话展示。实体剧情 NPC、六章完整台本、GUI 编辑器、完整考核线、店外街区仍未实装；历史内容包恢复也不代表通用卡身份/引擎存档迁移完成。

tests/narrative-runtime.mjs 覆盖真实成交、请求重试、提交失败、回执、日初恢复、条件确认、日志截断与旧包；tests/narrative-browser.mjs 用隔离 Chrome 操作正式 UI，包含自然购买和三种视口。测试信用动作、丢失响应、旧版本导入是明确标识的受控样例，不冒充玩家历史存档或真实牌局胜利。
