# 长线经营与高手挑战（当前规则 v2）

日期：2026-10-26。适用于源码开发版；不更新旧 EXE，不清空现有卡店。

本文件路径保持不变以保留已有链接。v2 将原来的一次性账务核对改为海玲的开店借款主线，并将高手来访改为逐日顺延；下文为当前有效规则。

## 已接入的玩家流程

### 高手约战

- 第一位高手第 2 天到访。顺利每天获胜时，后续为第 3、4、5……天；同一时间只有一位待通关高手。
- **当前高手通关的次日**才来下一位。例：第 2 天输了约第 3 天，仍输了约第 4 天；第 4 天获胜，下一位第 5 天来访。取消旧日历中的固定预约，不补发积压高手。
- 落败后的结算窗口提供「再战一局（重新选将）」和「明日再战」。重新约战会建立新的挑战、房间和整场备战，比分归零；支持三种现有赛制。
- 同一次约战中，关闭后重开房间不会刷新已公开的对手备战池；真正落败再战才开启新一轮。
- 选择明日再战后，同时记录阶段延期与角色离店状态。当天不能重新接战，也不会被来访调度器重新召回。
- **当天落败后**选择明日再战，获得对应高手主题的密封卡包一包，零成本入库。相同阶段同一天只发一次。初次尚未交战就延期不发包；关闭对话沿用延期，不另设一份关闭赠礼。
- 赠包不解锁对应主题进货资格。实际通关、解锁供货和收服伙伴仍由可信引擎整场胜利触发。

### 伙伴管理与菜单

顶部入口收为「营业操作、卡册、高手伙伴、店铺菜单」。菜单再分经营、卡牌、人物与挑战、记录与设置；时钟暂停和倍率在菜单首页。

高手伙伴窗口包含：

1. **伙伴排班**：肖像、名字、加入日、当班状态、岗位与个人效果；直接切换招呼顾客、协助收银、联系供货、约战赚钱或休息。约战岗位的本金、输赢与流水见[伙伴约战与场景移动](伙伴约战与场景移动.md)。
2. **高手来访**：已通过阶段数量、主题名单、当前挑战与最早到访日期。
3. **经营目标与借款**：海玲的总借款、当前分期、截止日、已还款/牌局抵扣、分次还款按钮、未来功能状态。顶部钱包区直接显示本期目标入口。

最多三位伙伴当班，不收工资。岗位效果合计上限沿用引客 30%、收银减时 40%、批发优惠 15%。休息不会丢失伙伴。

### 长线设施

保留已购买等级，扩展为七条升级路径。下一等级的解锁日为 `minDay + 当前等级 × daysPerLevel`，默认每级间隔两天；同时保留金币成本。窗口显示升级前后实际参数和员工工资变化，场景中的主要设施显示真实等级。

| 路径 | 等级 | 每级/递进效果 | 满级效果（不含伙伴） |
| --- | --- | --- | --- |
| 陈列架 | 10 | 密封商品容量 +18 | 基础 36 → 216 位；整盒占位沿用配置 |
| 展示柜 | 8 | 新顾客资金及到访预算系数 +0.25 | 最高 ×3；仍不能超过其实际可用资金 |
| 牌桌服务 | 8 | 建议桌费 +4 | 建议费比基础 +32；店主自定桌费优先 |
| 收银 | 8 | 同时购物名额 +2；递减结账耗时 | 名额受 `maxNpcs` 限制；结账最快 0.12 秒 |
| 补货 | 8 | 缩短补货周期、每主题目标增量 | 默认每约 8.7 游戏分钟补货、每主题目标 17 包 |
| 宣传与装饰 | 8 | 到店吸引力 +12% | 单独满级 +96%，实际到访间隔缩短 |
| 市场经纪柜 | 8 | 可接受单卡溢价系数 +0.08 | 最高 ×1.64；仍受预算、实际卡源及需求约束 |

员工每级日薪：收银 35、补货 50；休息日照合同支付。升级成本逐级增加，满级并非第三天即可买完。经纪柜不凭空拉高市价、不制造成交，也不减少店主的代售佣金。

配置：`data/backend-management.json`。上表是默认配置投影，修改默认值后应复查实际 `management.upgrades` 输出。旧自定义配置覆盖不强行覆盖。

### 二级市场收紧

- 只准 **SR、SSR 实物印刷卡**交易。当前重新计算的全局强度等级不覆盖实物印刷等级。
- 规则同时覆盖手动挂单、一键多余上架、NPC 代售、市场买入、街坊求购与收卡报价。
- N、R 继续保留在收藏、开包、对战、垃圾桶和拾卡流程中；不删除或补偿性卖出。
- 旧存档的 N/R 活跃挂单取消并退回收藏；旧低稀有度未结街坊订单取消、退还托管并解除锁定。已完成交易历史保留。
- 玩家使用自己拥有的武将不要求曾流入市场。普通 NPC 的流通限制不变；高手和伙伴的主题借用牌不成为可售实物。

### 开局剧情与分期经营目标

海玲是债主，使用 `bd-umiri` 外观与立绘；游戏内姓名按用户指定写作“海玲”。新局先在场景底部对话框说明借款与首期目标，确认后开始经营，不再以供应商是否存在欠款来决定主线是否成立。

总剧情借款 **20,000**，首期第 **7** 天还 **5,000**，由用户确定。后续暂定每 7 天一期、每期 5,000，配置可调整：

| 阶段 | 截止日 | 本期目标 | 核对后进度 |
| --- | --- | --- | --- |
| 让卡店站稳脚跟 | 第 7 天 | 5,000 | 完成首期，记录户外前置资格 |
| 建立稳定的经营收入 | 第 14 天 | 5,000 | 进入下一期 |
| 壮大店铺与牌友圈 | 第 21 天 | 5,000 | 进入最后一期 |
| 还清开店借款 | 第 28 天 | 5,000 | 借款主线完成 |

- 借款是装修和开业筹备的剧情义务，不另往现有钱包注入 20,000；现金、赠盒与已购设施保持原状。
- `wallet.debt` 仍是进货等经营欠款；剧情借款存于 `longTerm.loan`，二者分账。卖货、领奖等收入不会被剧情借款自动吞掉，进货信用额度也不受它挤占。
- 可以在目标面板提前、分次还款；每笔从真实可用现金扣除，计入当期和总已还本金。不能超付、越过当前阶段、在已结算日继续付款，或重放旧分支扣款。
- 在约定日期营业时，海玲主动来访。即使提前付完，也要在该日期起与她核对，才正式完成当期并进入下一阶段。
- 截止日未完成不会删档或清空进度，可延期并继续经营；高手挑战排期与这条债务主线独立。
- 若迟到多个分期，后续来访至少隔到次日，不在同一天反复离店再进店催收。逾期迁入的旧档在补完开局对话后也至少留一天准备。

### 打牌减免与户外前置

- 三种现有赛制均可争取减免，失败可重新选将再战，或约明天。
- 减免公式改为 `min(本期剩余目标, 5000, max(500, floor(本期剩余目标 × 30%)))`。首期尚欠 5,000 时，赢一场抵扣 1,500；还需经营并付清另外 3,500。
- **每期最多领取一次牌局减免**。奖励金额在可信整场胜利时按本期实际剩余计算，绝不生成现金或改写供应商欠款。
- 总借款守恒：`尚欠 = 初始本金 − 现金已还 − 牌局已抵扣`；每期也分别守恒。
- 赢牌推进当前目标，不直接跳过剩余还款。首期全部付清/抵扣，并在海玲处核对后，才设置 `outdoor.status='unlocked-planned'`。户外地图尚未开放。
- 收支流水分别记录现金、进货欠款与剧情借款的变化；本金还款不混入进货、营业额或经营利润。

## 代码边界与接口

| 文件/模块 | 职责 |
| --- | --- |
| `data/long-term-policy.json` | 高手初访/通关次日排期、市场可售等级、借款本金与分期目标、减免参数、未来系统状态 |
| `data/lender-dialogue.zh-CN.json` | 债主开局/分期/减免对话模板；金额和日期由已冻结的存档条款填入，不在文案里另写一套数值 |
| `modules/progression/` | 普通阶段的排期、延期、通关和伙伴派工；无 UI 和库存副作用 |
| `modules/backend/operations-v7.mjs` | 事务内组织邀请、赠包、房间、引擎结算与普通阶段奖励 |
| `modules/backend/debt-challenge.mjs` | 开局场景对话、债主来访、牌局减免、目标核对和户外前置资格；不改上游引擎 |
| `modules/backend/campaign-loan.mjs` | 剧情本金、分期目标、现金还款、减免、进度守恒及查询投影；不调用渲染或上游引擎 |
| `modules/backend/market-policy.mjs` | 实物印刷等级准入和旧挂单迁移 |
| `modules/backend/management.mjs` | 等级效果、购买费用、工资、补货和经营配置迁移 |
| `modules/backend/card-finishes.mjs` | 实物工艺元信息、分组及未来交易标的身份 |
| `frontend/ui/partners.mjs` | 伙伴/挑战/账务呈现与派工意图 |
| `frontend/ui/more.mjs` | 分类菜单；不自行结算任何经营数据 |

新增/扩展查询均只读：

```js
host.query('progression.status') // 新增 schedule；保留原字段
host.query('allies.list')        // slots, allies, effects
host.query('longTerm.status')    // debt, loan（含 currentGoal）, outdoor, futureSystems, marketRarities
host.query('management.upgrades') // 当前效果/下级效果、等级、成本、解锁日、日薪
```

新增动作沿用 Host 统一事务、操作去重和回滚，不让前端写世界对象：

```js
host.command({ requestId, type:'challenges.rematch', payload:{ matchId, proof } })
host.command({ requestId, type:'challenges.defer', payload:{ matchId, proof } })
host.command({ requestId, type:'allies.assign', payload:{ allyId, dutyId } })
host.command({ requestId, type:'debt.repay', payload:{ milestoneId, amount, proof } })
// 场景对话统一使用：
host.command({ requestId, type:'dialogue.respond', payload:{ offerId, optionId, proof } })
```

`proof` 携带当前世界/存档分支。重赛/延期只接受当前最近败局，旧按钮不能覆盖新邀请；同一 requestId 重放返回原结果。每次挑战固定一份对手卡池；取消重开房间保持同次邀请的卡池。账务约战新增 `challengeKind='debt-challenge'`，沿用现有原生赛制、免费桌费与借用牌资格验证。

前端不能提交“赢了”来发奖励。只有后端可信引擎通道产生的已完成、非模拟、来源确认的整场胜利，才允许高手通关或借款抵扣。债主会谈的 `settled` 只接受本期剩余为零且已到期；取消、认输、中断和关闭页面均无胜利奖励。

## 镀层与炒卡系统的扩展约定

### 参考与取舍

宝可梦官方对 Scarlet & Violet 的说明区分平行闪、全图插画和特殊插画，并将插画/闪面作为卡片呈现与收藏维度。可参考其工艺与美术区分；本游戏的出货率仍由自身经济需要决定，不能把社区估计出率冒充官方保底。[官方说明](https://www.pokemon.com/uk/news/pokemon-tcg-scarlet-and-violet-revamps-pokemon-tcg-card-aesthetic)、[官方卡表图例](https://assets.pokemon.com/assets/cms2/pdf/trading-card-game/checklist/svi_web_cardlist_en.pdf)。

《ONE PIECE CARD GAME》官方规则将 rarity、card number 和对战参数分别定义。这里借鉴“印刷标识与规则身份分别管理”的接口结构，不宣称它与本游戏的 N/R/SR/SSR 强度分档一一对应。[官方综合规则](https://asia-en.onepiece-cardgame.com/pdf/rule_comprehensive.pdf?20250221=)。

据此，本项目采用三层独立身份：

1. **规则身份**：`generalId/cardKey`，决定技能、模式评分、NPC 可用流通资格。
2. **印刷等级**：`printedRarity`，出生时冻结，决定当前二级市场准入。
3. **实物版本/工艺**：`finishId`、`artVariantId`、`editionId`、可选 `serialNumber`。未来可规划普通、闪面、纹理、异画、编号等工艺；均不能额外增加武将战力。

当前缺少工艺字段的旧卡等价于 `finishId='standard'`、`artVariantId='base'`，保留原印刷版本。聚合及多余上架已按实物工艺身份分组，避免将未来异画/编号副本当作普通重复卡。现在没有发行任何新镀层，没有暗加价格倍率或重抽旧盒。

`physicalGroupKey()` 用于收藏和保留副本；`exchangeAssetKey()` 预留未来订单簿标的键。交易所真正开发时还需：

- 将标的现货和可用金币托管，撮合在后端事务内完成，取消/过期退回。
- 区分可成交买卖盘、最近成交、参考估值和流动性；无成交不能伪造“成交价”。
- 日度行情快照、持仓成本、已实现/未实现收益、资金与卡片供给审计。
- 以稀缺供给、收藏需求和有样本量约束的对战统计定价；设置涨跌幅与成交深度约束，防自买自卖抬价。
- 用新版本的发行政策生成工艺出货，不修改已封装包盒；公布当前出率和包/盒保底。
- 扩展时明确 N/R 高工艺版本是否允许交易；本版仍严格只交易 SR/SSR 实物印刷等级。

户外开发应新增地图/区域路由和内容条件，读取已有 `outdoor` 前置资格。剧情文本通过内容系统管理，世界、存档和营业时钟继续由 Host 持有；不要在场景脚本中另建钱包、时钟或背包。

## 存档迁移与验收

- 现有通关、伙伴、实物和金币保留；旧高手日程迁移为通关次日，尊重已有延期与正在店内的邀请。
- 既有设施等级保留，默认旧设施配置升级为新深度；主动覆盖的自定义配置不覆盖。
- 新增借款与目标状态随整个世界保存、备份与回到当天开始。旧档补上 20,000 剧情借款和开局说明，保留旧账务核对的审计记录；旧供应商减免、现金和已取得的户外资格不回滚。
- 初始借款与分期条款在生成目标时冻结入档，改配置不重算已有本金或已还款。读取不会额外发包、减债或重复注入借款。
- 未知未来版本保留记录并停用对应新功能，不重置世界。

执行 `npm run test:long-term` 可验证开局对话、四期本金守恒、提前/分次还款、牌局单期抵扣、延期、旧档迁移及真实页面。另通过 `tests/three-formats.mjs`、`tests/day-starts.mjs`、`tests/operations-v7.mjs`，覆盖三模式结算、按天读档与既有经营流程。

测试使用隔离存档和受控可信引擎事件，不写入玩家真实卡店；这不等于已验证 30 天自然游玩的经济曲线或所有武将技能。接下来实际试玩重点：每日高手强度、首次 5,000 目标的压力与回本节奏、伙伴岗位收益、SR/SSR 市场成交量和后续分期难度。
