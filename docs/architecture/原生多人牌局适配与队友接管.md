# 原生多人牌局适配与可选队友接管

2026-10-25，V7-D 主模型实现。底层适配已运行，正式卡店的系列赛/约战/新开桌界面待其余候选统一接线。本文件不宣称整个V7玩法已经上线。未改vendor，未更新EXE。

## 实现入口与边界

- 公开模块：`integration/modes/index.mjs`；独立类型：`contracts/native-round.d.ts`。
- 原生适配：native-engine/bootstrap/profiles；浏览器挂载与消息校验：mount/round-plan；可选接管：ally-control；Node源码版本探测：capabilities。
- 本地验证页：开发服务下 `/experiments/native-modes/index.html`，明确隔离样例，不扣卡店钱、不产生胜利奖励/解锁。
- 验证：`npm run test:native`。单测、真实浏览器、三局串联fixture、旧模式回归分开报告。

底层 mountNativeRound 接受**已由Host核准的计划**，本身不校验库存、招募、店铺费用或挑战资格。正式接线时必须从C比赛记录生成计划，不能直接信任用户表单/URL后注册为官方比赛。原Host.battle目前仍走既有KOF/BO3；拟新增battle.control不等于当前Host已实现。

## 锁定的原生profile

| 经营格式 | 原生模式/子模式 | profile |
| --- | --- | --- |
| doudizhu-bo3 | doudizhu / normal（本地休闲） | noname-1.11.6-doudizhu-normal-shop-1 |
| versus2v2-bo3 | versus / two（本地2v2） | noname-1.11.6-versus-two-shop-1 |

斗地主保留原生start、gameDraw、跋扈/OL飞扬、地主体力加成（尊重noZhuHp/noZhuSkill）、手杀农民遗产与dieAfter/checkResult。只替换chooseCharacter入口，直接使用店铺计划，不再随机选其他将或重新叫地主。

2v2保留原生start、phaseLoop、首轮少摸、dieAfter和阵营结果，只替换chooseCharacterTwo入口；替补、整队autoswap、尾位额外起手牌等额外开关明确关闭。人控单席，主将死而AI同伴存活时原生规则继续打。AI与卡牌效果仍来自无名杀，不是随机胜负模拟。

两个原生模式公开的同阵营手牌可见规则保留，不等于可以操控队友或偷看敌方。自由更换到敌方视角入口关闭，可选同阵营接管走专用校验路径。

capabilities探测核对模式文件、player/content/game核心文件SHA-256，并报告source-pinned及runtimeHandshakeRequired。hash不符明确不可用，不能重新生成一套hash自动接受上游。浏览器还检查实际版本、钩子、座位、武将加载与就绪控制状态。未来上游更新需审查profile后再开放，不覆盖vendor或拖累旧模式。

## 计划与可信消息

RoundPlan包含独立world/branch/match/game/round/profile/format、reserveDigest、seed、初始主将、席位及物理/借用引用。原生模式名与系列格式分开，3/4座和阵营关系严格验证。5/8将备战池与跨局归约属于C，不由底层重复选整个备战池。

挂载前规范化、复制并冻结计划，计算SHA-256。postMessage核对来源origin、当前frame.contentWindow、随机token、所有世界/比赛/版本身份及planHash，忽略未知/私有字段。ready包含完整初始席位；结果按teamId映射，不把主将死亡当整队失败。

父桥只在匹配ready后接受结果，生成originVerified/sourceVerified；这些字段不能由UI自行签发。相同resultId重复不重复通知，不同合法结果冲突中断并保留错误。dispose清理frame/listener/timer/Abort监听和租约；同窗口只能挂一场原生玩家局。计分、卡锁、桌费、整场一次30分钟和解锁全部留在Host业务层。

## 接管：可选而非自动

计划可选controlPolicy:'optional-ally'（缺省）或'ai-only'。controller是**初始声明**，controlled为当前视角，初始主将与playerTeamId始终不改。

```js
const mounted = await mountNativeRound({container, plan, signal, onEvent}, {
  engineOrigin,
  acquirePause: input => host.pause.acquire(input),
  releasePause: leaseId => host.pause.release(leaseId),
});
mounted.control({action:'takeover', seatId:'mine-ally', requestId:'control-001'});
mounted.control({action:'release', requestId:'control-002'});
await mounted.dispose();
```

外部前端最终通过主模型接入的Host.battle.control适配，不直接发未经校验的iframe消息。控制请求同样验证token/完整比赛身份，只能接管己方存活席位；同ID参数冲突拒绝，重复请求返回状态，最多256条本局回执。一次只排一个切换意图。

切换在下一次phaseBefore边界执行，不取消当前人类正在选择的牌/目标/响应。UI须提示先完成当前操作，controlPending不代表已经切换；controlChanged才更新操控标记。若目标在排队期间死亡则controlRejected，不跳到其他人。保留原生swapPlayer处理牌区/视角，不改阵营、手牌或将池。

主将死亡后可以接管存活队友继续打；交还AI则回原主将的观战视角，不复活。整个过程不增加桌费、时间或奖励。新小局默认回到其计划里的主将。尚未支持完整中局精确存档恢复；后续C的恢复UI必须明确无赌注当前局重开，不伪称还原控制/牌堆全随机状态。

## 已发现并处理的运行边界

内核版本在preload阶段尚未初始化，版本校验放在onload2；不能误把undefined版本当不兼容。异步录像列表尚未载入时快速结束对局，原生game.over会读未初始化的lib.videos；原生独立局明确video:0，停止持久录像，避免竞态和多局frame积累。店铺业务战绩仍由Host保存，不受此设置影响。没有吞掉game.over异常、伪造赛果或给lib.videos硬塞空数组。

ready在原生gameStart的优先通知阶段发布，座位/身份已初始化且原生模式技能已设置；不能等到第一回合才ready，否则合法开局技能提前决胜会被误当技术错误。此时不承诺手牌已发完，表现层等待原生画面显示即可。

seed用于初始席位顺序；原生牌堆与完整随机调用没有实现可复现记录，profile明确seedScope/exactMidRoundResume，不能据此开启有赌注重放。

武将预检报告not-loaded/native-config-disabled和具体将ID；测试扫描了现有卡库的加载资格，输出未加载/被禁名单，但**不是全技能逐将兼容认证**。当前未追加全局武将封禁，复杂技能仍需后续组合回归。正常变身技能的当前name可变化，权威参赛generalId仍绑定原计划。

## 验证证据类型

- engine-real-ready：斗地主两种玩家身份、2v2两个玩家阵营、原生座位/规则/人控状态。
- engine-real-ai-autoplay：各模式一场自然完整AI操作，没有注入死亡或赢家。
- engine-real-controlled-death-fixture：主将死后继续、接管/交还、接管后按原队伍获胜；两个模式3局2:1串联、地主换边、重复/冲突结果。
- unit-real：计划/来源/回执、队友限制、边界切换与目标死亡。
- lifecycle：载入超时、重复dispose与暂停释放一次；旧BO3启动、KOF原新将摸4回归。

三局串联是桥接试验，C的正式系列赛/卡锁/经营结算尚待接入。自然对局与受控死亡的结果分别记录，不能互相冒充。原始截图/日志在忽略的test-results，轻量摘要见本轮review。
