# 上游内核升级暂存流程

当前唯一运行源仍是 `vendor/noname`，已导入版本 1.11.6。新工具只提供独立暂存和报告原型，不负责下载、安装、更新 profile 或迁移玩家档。

```powershell
npm run engine:stage -- --source D:\Downloads\noname-candidate --out .local/engine-review-new
```

必须明确提供源码目录。输出必须是新目录，工程内仅允许 `.local`；真实路径校验拒绝覆盖工程、输出/输入嵌套及 junction 绕过。源中的符号链接报错；不读取或复制根 `Home`、`.git`、`.cache`。候选 JS 不执行、不导入、不提供网页服务。

输出包含 `engine/`、逐文件 SHA256 的 `candidate-manifest.json` 和 `report.json`。逐文件复制后复核哈希，原始目录和正式运行目录均只读。报告给出新增/删除/变化；另将本机已安装文件与冻结 `data/engine-manifest.json` 对照，报告已有漂移，避免把本机改动归因上游。

## 能力与证据

斗地主和 2v2 逐项比较包版本、已审核 profile 版本与 pin 文件哈希，报告 profile 自身哈希。即便得到 `pinned-files-match`，也只是静态资格，`approvedForInstall` 始终 false。运行握手、受控夹具、自然对局分别记为 `not-run`，不自动引用旧版本测试替新版本背书。

KOF 由现有独立桥接实现，未冒充使用多人模式 profile；始终列为 `adapter-review-required`。暂存工具没有发布开关，不能以模拟结果代替玩家真实局。

## 旧内容影响

报告独立列出以下项目：

- **卡牌身份**：保留 `noname-1.11.6:*`，不原地改旧 cardKey。按变化的 `character/包.js` 或包目录保守标记可能受影响的卡牌；不是完整 AST 技能分析。
- **技能**：列出受影响包和登记技能 key；共享内核变化可能影响所有技能，不能只验证名单里的技能。
- **印刷**：记录现行发行配置版本和哈希；不重建旧包盒、旧印刷或已付款订单。
- **存档**：不打开玩家档。列出实物、技能版本、包盒内容、订单快照、比赛游标和日初档待核查项；新版本应使用复制的旧档做验证。
- **资源**：图片、音频、主题、布局差异只作静态提示；动态路径需单独跑资源检查。

升级流程应是：核对上游来源/许可 → 审查报告和 profile → 在隔离端口接入候选 → 分开提供握手、受控和自然证据 → 复制旧档验证 → 人工批准发布及回退版本。原 `tools/import-engine.mjs` 会写正式目录和 manifest，**不作为审查暂存命令**。

本轮用当前完整引擎复现：15,876 文件、版本 1.11.6，新增/删除/变化均为 0，正式安装漂移为 0；这是“同版本暂存工具可用”的证据，不是一次真正升级认证。新版本自然长局、动态技能及旧档迁移仍待对应候选验证。
