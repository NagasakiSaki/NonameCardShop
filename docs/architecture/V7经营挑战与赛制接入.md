更新：2026-10-26。A/B/C/E/F 的候选已核查，正式实现以本文件列出的入口为准。候选目录保留原样，不直接作为运行时源码。

后续房间流程与四模式平均定价见 [对战房间与四模式评分](对战房间与四模式评分.md)。正式 UI 已改为先创建房间、公开对手固定备战池、再确认我方名单；下文的 `combat.prepareSeries` 保留为旧调用兼容接口。

## 数据和事务

`modules/backend/runtime.mjs` 继续独占命令队列、世界 fork、存档提交和事件发布；`modules/backend/operations-v7.mjs` 编排进度、世界角色、备战与可信结算。候选模块不自行访问数据库、扣费或调用其他 Host 命令。

- `modules/economy-v7/`：价格、分层预算、配盒纯策略；正式采购/交易仍在 backend 中提交。
- `modules/progression/`：三日排期、邀请、伙伴和挑战归约。存入 `world.progression.version=1`，不放 localStorage。
- `modules/combat-formats/`：四种赛制、整场备战、逐局选择和系列赛归约；存入 `match.series.seriesVersion=1`。
- `integration/modes/`：原生斗地主/2v2 的引擎适配；不拥有钱、库存、解锁或店铺时钟。
- `frontend/v7-dialogue.mjs`、`frontend/combat/v7-room.mjs`：正式前端胶水。复用 E 的对话分页、覆盖层、赛制描述、卡牌网格和控制状态推导。原采购、仓库、开包、单卡交易窗口保留。

UI 命令不能提交 `verified` 胜利；只有来源、窗口、token、计划摘要和完整身份经过检查的引擎桥能调用 `trustedEngineEvent`。整场挑战胜利、供货解锁、伙伴招募、回执和释放占用一起进入同一个存档事务。

## 经济参数

默认散包建议售价 **210/360/510**，进货 **150/255/360**；平均全局强度 `<53`、`<57`、其余对应三个档位。整盒 24 包，进货和零售分别乘 `24×0.95`，向上取整到 5：

| 档位 | 散包进货/售价 | 整盒进货/售价 |
| --- | --- | --- |
| 基础 | 150 / 210 | 3420 / 4790 |
| 进阶 | 255 / 360 | 5815 / 8210 |
| 旗舰 | 360 / 510 | 8210 / 11630 |

价格可通过 `backend-rules.strengthPricing` 的 `strength-tiers-4` 三档配置修改，明确填写 `packRetail`，不再倒推利润率。伙伴进货优惠在新报价中应用；已有订单、密封商品成本及手工零售价不重算。报价版本包含供货、日期、评分和折扣；旧报价不能跨过解锁/折扣变更继续执行。

顾客分层与预算在 `data/v7/economy-policy.json`：普通客 70%、爱好客 20%、整盒客 5%、贫穷客 5%。新普通客钱包 900～1800、爱好客 1800～4500、整盒客 12000～18000；每次访问还有独立预算，预留桌费不能拿来购物。每日补充按天去重。实际成交扣钱包并记本次花费，不为促销凭空补款。普通客、爱好客、整盒客优先挑相应价位，整盒客优先买盒；贫穷客仍保留拾牌路径。

新档只有 `yijiang` 可进货，赠一盒。没有已解锁 SSR 时固定 `60N/42R/18SR/0SSR`，每包至少 R；有合法 SSR 池后为 `60N/42R/15SR/3SSR`。缺档只从已解锁主题同档补位。内容在制造时冻结，解锁不会改写旧盒。停产 `newjiang/offline/standard`，普通 `yijiang` 不停产。

## 角色、约战和伙伴

新档第 3/6/9…45 天，15 个阶段依次排队；最多一位当前高手，当天通关后不会再派下一位。旧档首次启用从当前日+1起，随后间隔三日，不补刷此前所有高手。

NPC 从店门实际出现，走近店长后提出邀请；不以名单或门口固定角色代替。姓名紫色，沿用已有立绘/四向行走素材。与店长和其他顾客的落脚点错开；店长在另一个房间时先在店内等候。

`actors.interact({actorId})` 先校验同房间、距离和忙碌状态；`dialogue.offer` 只读。`dialogue.respond({offerId,optionId,proof})` 支持接战、延期、约战、安排伙伴、关闭。挑战关闭/Esc 等同次日再来；输了不解锁，可以手动重新交谈或延期。普通顾客接受约战后暂留 90 游戏分钟；准备系列赛时退出原等待队列并释放对应卡牌、桌费预留。

高手的 `challenge-loan` 从目标主题兼容武将中按存档种子抽取，不是世界物品，不计购买/流通、不入垃圾桶。仅已招募伙伴的免费训练可使用对应已通关主题的训练借用。普通 NPC 必须实际持有已流入市场的卡；店长没有流通门槛。

通关后默认在有空位时安排工作。最多三位同时值班；引客、收银、供货的累计上限为 30%、40%、15%，直接作用于到访间隔、收银用时、新进货报价。伙伴和高手不占普通顾客客流名额，不参加购物/拾牌/自动排队循环，也不领普通顾客的每日预算。

## 比赛与引擎边界

四种模式都从正式牌桌选择。整场备战需要每方 1/3/5/8 名不同武将，锁定实际副本至整场结束。每局从固定备战池选择主将和 AI 队友；对面由存档种子选择。KOF 按备战顺序接力，换将重新摸四张，不继承。斗地主有胜负后换地主阵营；平局不换边、重开当前局，连续三次可取消。2v2 以整队胜负结算，主将死而队友还活着不会直接判负。

`combat.formats` 返回能力与原因；`combat.eligible({formatId})` 返回持卡；`combat.prepareSeries` 提交备战；`combat.selectRound` 一次确认全部我方席位；`combat.start` 准备挂载；`host.battle.mount` 进入引擎。整场普通约战仅收对手一次冻结桌费，高手/伙伴训练免费。

`host.battle.control({matchId,action,seatId?,requestId})` 保留可选接管。默认 AI，不自动接管；只能选己方存活队友，在安全回合边界切换；按钮显示待切换/已接管状态。主将死亡后仍可接管存活队友。控制变化不改变阵营、备战或胜负归属。

只有玩家实战占用比赛时间，整场结束推进 30 游戏分钟且只记一次；NPC 之间继续用原有后台模拟并付费，不自行暂停世界。交互窗口和场景对话仍使用成对 Host 暂停租约。

旧 KOF/BO3 比赛、原等待报名及自由走动入口保留。新模式要求原生 profile 能力通过检查，内核不匹配会显示不可用，不能凭模式名硬开。`data/v7/native-eligibility.json` 将已有真实引擎扫描到的 34 个禁用/未载入武将按 profile 隔离，选将时显示原因、准备时再次校验；原生引擎本身仍作最终检查。该名单不是全技能组合认证。当前原生适配针对本项目的无名杀 1.11.6 文件；以后升级内核应新增/更新 profile、跑能力及实战回归后开放，不宣称任意新内核已兼容。

不支持精确恢复未结束原生小局。关闭/读档/技术中断后显示重开当前无赌注小局或放弃；保留已结算比分，旧窗口/分支/小局的赛果拒绝入账。当前无赌注。

## 剧情与存档

剧情文本、节点、确认和奖励仍由原剧情 VM 管理，不新增台本。开店场景可触发现有已满足条件的章节；等待中的章节满足条件后用同一个世界底部覆盖层呈现。原“故事”入口保留为手动回顾/选择兼容入口；它打开时自动对话不会叠上去。

整张世界仍按天保存 08:00 日初快照。读取日档同时倒回解锁、伙伴、邀请、借用阵容、比分与回执，创建新分支。已完成历史比赛可保留其原分支证据，活动系列赛重新绑定新分支并进入恢复流程。旧存档不补发赠礼，旧物品、印刷稀有度、成本、钱包不清空。未知未来进度版本原样保留、当前功能禁用。

日档保留窗口仍为既有配置（默认 30 日），不是永不裁剪。挑战记录、解锁和回执位于当前世界，不依赖第 3 日等旧档永远存在；F 对“第 1 日被正常裁剪”的意见不作为缺陷修改。
