# 策略来源与失效链

更新：2026-10-27（OPT-15）。只梳理现行/历史来源，不更改三档价格、配盒或三模式平均公式。

| 来源 | 现行用途 | 更新/兼容边界 |
| --- | --- | --- |
| `data/backend-rules.json` | 新世界默认经营参数、强度阈值、strength-tiers-4 定价 | `config.apply` 保存到当前 world.rules；同版本重连保留显式值 |
| `data/strength-modes.json`、`ideal-yield-anchors.json`、native eligibility | 两回合理想收益与校准、身份/模式分 | `strengthFingerprint` 参与 ratingVersion；不改变印刷 |
| `data/print-editions.json` | 固定发行分级、主题池和卡盒配额 | 只影响新封装；旧实物/密封内容已有快照 |
| `data/v7/economy-policy.json` | 默认顾客预算、V7 价格工具默认值 | `v7-policy.economyPolicy(world.rules)` 将现行 strengthPricing 注入价格工具 |
| `supply-pricing.DEFAULT_STRENGTH_PRICING` | 旧档缺字段的历史五档回退 | 不是新档默认，不能拿它覆盖新档三档 |
| `data/long-term-policy.json` | 高手顺延、伙伴、借款目标与未来接口 | 保留现有迁移和日档记录，不与供应商欠款混算 |

失效链：配置修改 → 校验 → 单事务 world.rules 更新 → 完整规则 JSON 比较 → 当前 Runtime 的 catalogue provider 换键（最多3项）→ 后续查询读取新目录。日初回退/导入恢复当时规则与分支，报价/预览及世界相关草稿按现有机制失效。源码导入的评分 JSON 为模块静态依赖，修改文件后需重载，不靠旧进程缓存自动热替换。

ratingVersion = 规则声明版本 + 评分模型/阈值/模式权重/评分 fingerprint 内容哈希；它不等于 printVersion。服务指纹属于服务/桥接代码可用性，`dev/runtime` 对 modules/data/content 的监视另负责通知页面重载，不能用指纹代替发行或业务版本。

`initialiseRating` 只迁移识别的旧评分，当前版本 marker 存在时不覆盖显式配置；`initialiseV7` 只在 operationsVersion 尚未建立时初始化 V7 默认。这是明确的旧档升级边界，不是每次启动重置参数的入口。没有在本轮扩大自动迁移范围。

只读命令 `npm run audit:policies` 产生默认来源、版本、SHA256、现行档位和兼容边界清单；它不读取实际存档。用户档案的真实生效值需用该档 `config.list` 查询，不能仅看仓库 JSON 推断。

验证：`tests/policy-preservation.mjs` 经真实 Host 采购后应用隔离自定义参数，重连仍保留，已封装实物与订单字节一致，日初回退恢复原策略。固定16个发行版本、旧实物评分迁移和三个赛制公式继续由 `ideal-yield-and-editions` 覆盖。
