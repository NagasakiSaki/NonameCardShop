## 1. 现行架构 vs 目标解耦架构差异

| 维度 | 现行实现 (Current Hooks) | 目标架构 (Profile Adapter) | 演进收益 |
| --- | --- | --- | --- |
| **代码注入** | `integration/duel.js` 直接重写 `lib.imported.mode.identity` 的核心函数 | 独立赛制定义模块，无名杀作为纯黑盒运行，仅通过受控 API 触发 | 升级无名杀版本时无需修改上游任何源码或私有函数。 |
| **生命周期** | 依赖全局 `lib.onload2.push` 异步时序 | 外部显式握手协议（`ready` -> `session_init` -> `start`） | 消除时序竞争与冷启动失败隐患。 |
| **状态持有** | 将 `game.shopDuel` 状态直接挂载在引擎全局对象 | 状态完全收敛于宿主环境（`ShopHost` 内部状态机） | 杜绝全局变量污染，提高内存回收效率。 |
| **资源查找** | `tools/extract.mjs` 正则扫描本地目录提取素材 | 建立标准化引擎资源导出器与 Manifest 映射字典 | 避免上游文件重命名导致卡牌图面缺失。 |

## 2. 身份与资源映射差异 (`cardKey` / `actorId`)

1. **卡牌标识解耦**：
   - 卡店游戏内的卡牌流通、上架寄售和库存使用的是业务 `cardKey`（如 `card_pack_01_c05`）；
   - 无名杀引擎使用的是内部卡牌代号（如 `sha`, `shan`, `tao`）；
   - 两者之间通过 `data/cards.json` 的 `sourceRef` 字段进行映射，**业务层绝对不直接把无名杀内部变量当作商品唯一ID**。
2. **角色标识解耦**：
   - 剧情角色持久身份为 `personId`（如 `person_zhou_ye`）；
   - 在对局中，周野出战时仅指定其出战武将阵列（`roster: ["sunce", "zhouyu", "luxun"]`）；
   - 角色人格不与特定的武将牌面绑定，周野在不同章节可以调整出战阵列，不影响其剧情身份。
