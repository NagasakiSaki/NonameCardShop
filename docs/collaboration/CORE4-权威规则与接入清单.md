# CORE4：主模型工序

对应 [本轮分工](2026-10-24-窗口与牌桌新版分工.md) 与 [共享草案](PLAY4-共享界面与接口草案.md)。**清单尚未实施。** 本轮高质量工序由主模型承担，外部模型不得代改正式规则。以下各阶段可分批提交，EXE不在本批。

## C4-1 / 先冻结契约与基础

- [ ] 逐一核对地图实际交互ID、现有路由、窗口管理器、暂停和输入阻挡；区分独立器具窗、嵌套选将窗与地图非模态候战条。
- [ ] 在 `contracts/` 明确即时交付、赠品、桌费/队列、收藏与30分钟结算字段；共享草案不是已实现API。
- [ ] 制定固定页容量/尺寸策略，主内容分页而不是藏滚条；长技能完整可读。窗口重复打开、Esc、resize、父子焦点、迟到响应与worldReset都能清理。
- [ ] 保留 FAST-04 的全量搜索/有界DOM、评分排序修复与未知结果找回，不复制旧候选覆盖。

主要入口：`frontend/ui/window-manager.mjs`、`frontend/app-shell.mjs`、`frontend-next/screens/workspace.mjs`、`frontend-next/components/workspace/`、`frontend/world/interaction-router.mjs`、`assets/frontend/maps/`、`contracts/card-shop-host.d.ts`。

## C4-2 / 采购、赠品与独立器具窗

- [ ] 新 `supplier.placeBasketOrder` / 单品下单用同一事务完成原价核对、资金/授信扣除、订单与真实盒包入库；失败全不发生，响应丢失能查原号。内部可以保留报价/预览，不让玩家多点无意义按钮。
- [ ] 合并“运输等待/签收”新主线；为旧已付pending/arrived订单制定兼容兑现路径，不能因默认改成即时而重新扣款、漏货或改掉旧发行/成本。
- [ ] 新档赠品配置化：盒/散包数量、指定商品或最低有效供货价选择；禁用主题不入选，密封大保底与原发行快照保持真实。推荐默认1盒，最终参数实施时记录。
- [ ] 赠品是真实库存、成本0、有可追溯来源，不是营业收入/采购支出；新档初日快照要包含它。重连、创建响应重试、日初恢复和导入不补发第二份，旧档不静默发奖或清空。
- [ ] 接 FAST-06，独立采购/仓库/拆包；主模型把已有零售、收银、单卡市场、垃圾桶改为各自固定页窗口。收银不再复用货架管理窗，不增加逐单手动结账。仓库转场走导航，开包/上架/单卡交易仍校验对应设施距离。
- [ ] 开包用一次明确确认、一次权威提交；结果多页展示，跳动画、关闭重开不会重抽或丢已获卡牌；“全部打开”明确散包/整盒范围。

主要入口：`modules/backend/runtime.mjs`、`basket.mjs`、`products.mjs`、`trading.mjs`、`world.mjs`、`profiles.mjs`、`storage.mjs`；现有 `supplier.receive/receiveAll` 和 `SupplierBasketOrderResult.status:'pending'` 都要同步兼容处理。

## C4-3 / 价格与新评分的分阶段工作

- [ ] 复核 FAST-08 的现价/预算与真实拒买链，确认预算、售价接受上限、货架、商品可供货与路径的影响；整体下调价格，但不把所有不购买归因于单一价格值。
- [ ] 新价格同时考虑采购、建议零售、盒折扣、单卡参考值/实际净收入、客户钱包、首次补货、免费赠品和自动任务奖励；选小规模实际经营场景检查能成交且不会简单无限套利。
- [ ] 用户给出新强度方法后再定标准化输入、版本、缺失值和解释字段，区分规则估计/实测数据；列BO3/KOF代表样本及局限，不能声称存在未经出处支持的官方统一强度标准。
- [ ] 从新全局评分统一生成N/R/SR/SSR、主题分布和强度价格档；保留单包小保底、整盒固定计数/大保底、发行时冻结与旧版本并存。
- [ ] 用户新方法未到时，可先修可负担性和明确拒买Bug；不把临时价格校准写成新评分体系已完成。旧盒/已付订单/旧实物成本/已接受桌费不得追溯改写，新版生效时点及旧档行为写入记录。

主要入口：`modules/backend/catalog.mjs`、`supply-pricing.mjs`、`products.mjs`、`distribution.mjs`、`trading.mjs`、`visits.mjs`、`data/backend-rules.json`、`data/power-model.json`、`data/cards.json`。

## C4-4 / 收藏、桌费与真正候战

- [ ] 增加独立的收藏偏好，推荐按本存档cardKey持久保存，缺字段默认空集，随日初/手动档恢复；绝不复用保护或改变参赛资格。无持卡的星标不产生副本，选将仍选实际可用inventoryRef。
- [ ] 桌费可由店家设置，有整数范围、版本、反馈及新老报价政策；玩家自身费用、对手/NPC费用分别解释，收入不在排队时无条件确认。保留已有升级效果并明确与手动设置的优先关系。
- [ ] 新建队列状态，不能用“要求已找到对手的combat.preview”直接实现等待；明确报名、可取消、过期/打烊、对手到达、阵容/费用重验、匹配和正式match的边界。
- [ ] 等待中关闭交互窗，释放该窗暂停/输入阻挡，显示非模态状态条；手动移动、其他器具和跨房间按明确规则可用，不因关窗取消排队。
- [ ] 提供手动/自动移动切换。先保证自由行动；自动模式可沿合法路径漫游或执行已定义的店内服务，手动输入接管时不抢控制。自动买卖/开盒/丢卡不作为本轮隐式行为。
- [ ] NPC加入相同候战机制，与买包/开包/拾牌/离店和原有currentMatchId协调；检查真实持卡、流通、赛制、预算与座位，避免一人多桌、桌位永久预留、全员门口等待或无人对手时死等。
- [ ] 接 FAST-07 大厅、选将、星标及等待条；候选草稿选满后一次确认，不随点选提交比赛。牌桌设置和选将改动使过期预览正确失效。

主要入口：`modules/backend/matches.mjs`、`npc-tables.mjs`、`visits.mjs`、`management.mjs`、`runtime.mjs`、`world.mjs`、`storage.mjs`、`frontend/ui/combat-room.mjs`、`frontend/app-shell.mjs`。

## C4-5 / 时间和无名杀接口是主模型高风险工序

- [ ] 正式开局到整场结束冻结经营，BO3局间选择也覆盖；玩家对局执行器继续运行。普通交互暂停/手动暂停/比赛暂停分清所属，释放比赛原因不会误释放其他暂停。
- [ ] NPC模拟比赛纳入同一时间策略。先定义串行或并行时间批次；避免模拟依赖已暂停的世界tick而永不结束，避免多桌各自无条件加30分钟。
- [ ] 整场正常结束、已正式开始后的认输，由同一持久结算事务恰好推进30游戏分钟、释放锁/座位并记账；重复result、重新挂载、窗口refresh、进程重启、结算响应丢失都不能重复推进。中断重试不算完赛，未开局取消不计耗时。
- [ ] 30分钟走统一经营推进机制，而不是前端写clock或跳过全部定时逻辑；明确任务到期、订单、NPC耐心/离场和打烊阈值的处理。跨阈值不自动无提示创建第二天或清垃圾；日初恢复保留原语义。
- [ ] 提前走 `/api/runtime → engineOrigin → iframe → ready/replacement/result → trustedEngineEvent`，检查来源、frame、gameId/matchId与分支。当前已存在真实桥接，不能只因为候选缺功能就重装/修改vendor引擎。
- [ ] 从当前正式地图入口走通一场BO3和一场KOF（含换将/手牌继承），外加载入失败/超时、关闭重开、旧事件、投降和最终结算。fixture强制终局和真实手动打完要分开记录，不能拿旧legacy测试宣称新版通过。
- [ ] 关闭界面、待下一局、中断和完整恢复的语义明确；恢复不了的牌局如实显示，不能把重发一局等同继续原局。下注开关本轮不顺手开放。

主要入口：`integration/host-battle.mjs`、`engine-server.mjs`、`engine-preload.js`、`npc-engine.mjs`、`modules/backend/matches.mjs`、`runtime.mjs`、`frontend/ui/combat-room.mjs`。参考 `tests/backend-browser.mjs`、`tests/battle-lifecycle.mjs`；`tests/duel.cjs` 是旧入口覆盖，只作机制参考。
