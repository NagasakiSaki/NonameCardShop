## 任务

1. 从 `assets/frontend/maps/store.json`、`battle-room.json`、`frontend/app-shell.mjs`、`frontend/ui/` 与正式 `frontend-next/screens/` 核对所有交互点、快捷入口、窗口与玩家可见按钮。按实际默认入口区分正式/旧classic/previous/Mock，不能把所有旧页面都列为玩家正在看到的Bug。
2. 输出 `interactions.csv`：实际ID、房间、器具名称、默认入口、现有窗口、目标独立窗口、保留动作、转移/删除的重复动作、精确文件/行号。仓库实体不存在时标“主模型决定是否新增”，不虚构导航已存在。
3. 输出 `copy.csv` 或 JSON：稳定key、原文、建议玩家文案、出现位置、何时显示/隐藏、理由。覆盖采购/入库/拆包结果、货架/市场/垃圾桶、牌桌/候战/选将、任务/存档与错误；优先移除Host、DTO、引用ID、分支等实现用语。保留玩家真正要知道的价格/数量/失败信息。
4. 输出 `layouts.md`：每窗最重要信息、一个主动作、必要次动作、固定页布局、空/加载/失败/未知状态。采购完成只提示“已入库”，不设计强制询价→订购→等运输→签收→确认入库等重复流程。
5. 对现有零售/单卡市场/垃圾桶/长技能给分页与精简建议，留给主模型复用改造。采购/仓库/开包具体代码由FAST-06做，牌桌/选将由FAST-07做；本包不重复开发另一套。
6. 可交低保真HTML示例或结构图；没有视觉工具就提供尺寸/内容块与可验证布局要求，不声称已看图。无需新人物或美术生成。
