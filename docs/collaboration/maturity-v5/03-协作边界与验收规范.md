# 03：外部分工、交付与减少主模型用量

适用全部 MV5-*，不追溯改旧交付。用户操作外部模型；本方案不依赖另有一个高质量模型。高速模型遇到复杂任务按子阶段提交，不要求独自一次完成架构重写。

## 1. 谁实际完成工作

外部模型负责研究、数据、纯模块、完整前端、适配器候选、工具、测试、复现、文档、接入补丁；MV5-17 负责收包与候选沙盒整合，MV5-16 独立审查与复现。主模型不再手工逐文件搬运、补完半成品、重复研究资料或替外部作者写全部测试。

主模型集中在五个小门槛：

1. 冻结玩法目标与首批合同；未决问题一次汇总，能采用保守兼容默认的先继续。
2. 钱/卡/预留/费用/奖励/时间唯一结算点与真实证据口径。
3. 引擎可信事件、身份映射冲突、持久迁移与回退政策。
4. 独立审计的严重问题裁决，以及必要代表场景抽查。
5. 分批正式合并、精确 Git 提交与私有发布；源码稳定后另决定 EXE。

这不等于外部作者不能写后端。它们必须交 **候选后端实现 + 正式路径补丁 + 受影响用例**；主模型审关键差异，不重新实现整包。普通局部修复由原作者返工，除非已影响用户当前正式版必须立即止损。

## 2. 工作区与可写范围

工程 `D:\GameDev\NonameCardShop`。每包只写 `deliverables/maturity-v5/MV5-XX/`。可在本包下建 `src/`、`tests/`、`config/`、`patches/`、`evidence/`、`sandbox/`。正式代码、contracts、data、assets、vendor、其他交付与用户原图只读；不 git reset/clean、不改用户存档、不停不属于自己的服务、不提交推送、不打正式 EXE。

**相较旧分工的扩展**：允许在自己的 sandbox 内应用候选正式路径补丁并完整运行；允许跨模块提供补丁，但只有表内归属的包能主改同一目标文件。写越界发现统一记 `gaps.md`，不假装已经正式绑定。

不要复制 GB 级 vendor 或整套用户素材。MV5-17 先提供可复现沙盒方案：复制必要文本源码，静态素材/引擎仅只读复用；Windows junction/symlink 的目标不能写，无法安全保证时使用明确的只读静态服务。候选不能依赖未登记的全局包、固定个人绝对路径或运行时 CDN。

## 4. 分阶段交付，避免半成品和过度设计

每个代码包交三小步：A 固定输入输出/差异、1 个成功与1 个失败样例；B 一个完整纵向用例和测试；C 在同样接口下补剩余边界。A 控制在一个短文档，不等待主模型逐段聊天确认；只有合同冲突、高风险政策或无法兼容的选择才进入门槛 G1/G2。

少用新依赖、泛型框架与全局重构。先复刻当前行为，再加最小新玩法。没有完整恢复能力就按当前 interrupted/redeal 策略交，不为了漂亮接口假造恢复。

## 5. 每包必交文件

- `DELIVERY.md`：按本目录模板，建议不超过 120 行，先写能用什么和怎么接；真实未完成项不可省。
- `manifest.json`：包号、基线 HEAD、相关正式文件哈希、依赖包/合同版本、候选/目标文件映射、运行命令、已知限制；不是新运行时依赖。结构参考 [manifest 模板](manifest模板.json)，示例/null 必须替换或删除不适用行，不能把占位值当真实指纹。
- `gaps.md`：字段/能力/政策缺口，含受阻用例、已试路径、保守回退；没有缺口写“无已知接口缺口”。
- 代码包：`src/` 或按最终目标路径组织的源码；`patches/` 最小统一补丁；`tests/` 自包含用例与必要 fixture。
- 研究/实测包：结构化 CSV/JSON 和 `evidence/`；截图只留代表样例，原始日志本地保留并给索引，报告不要贴几千行。

正式接入不能反向 import `deliverables/`，不能 import demo/fixture。若候选只能在 fixture 跑，明确标 `candidate-only`，不得写“正式可用”。构建脚本不可下载未固定版本的 latest 依赖。

## 6. 证据与测试规则

每条结论标 `static`、`unit`、`host-integration`、`browser-real`、`engine-controlled`、`engine-natural`、`manual-observation` 或 `unverified`。静态检查源码/DELIVERY 中存在某词，不算界面验收。真实引擎强制死亡只算 engine-controlled，不算真人完整打完。

使用动态端口 `startShopServer({port:0,enginePort:0})`、新浏览器 context/内存仓库；只关闭自己建立的进程。默认经济体验用例不能注入高资金、无限顾客或任意流通来证明平衡；合成极端样例可用，但单独标。

复用旧测试时将 `CARD_SHOP_TEST_RESULTS` 指向本包 `evidence/`；脚本若写死 `.local`、`test-results` 或其他路径，只在本包 sandbox 中运行，或给出输出可配置的候选 patch，不因此越界写正式工程。启动正式源码的只读静态服务本身不代表获准写其目录。

测试按 [05 矩阵](05-验收场景矩阵.md) 选择受影响链：新增纯函数测一次核心不变量，接入测一次成功+一次失败/恢复，修复后重跑失败项与真正受影响链。未改模块不反复全库运行。不以减少用量为由省略资金、迁移、可信结果的必要断言。

测试失败区分产品缺陷、批准的设计变化和 fixture/断言过期。不得只改断言让错误变绿；报告 before/after、原因与仍保留的旧兼容覆盖。测试测量期间相关文件变动则记录新基线，只重测受影响项。

## 7. 独立复核与接入闭环

作者自测 → 17 校验交付完整性/路径/补丁/依赖 → 16 对指定变更与全项目入口做独立复现 → 原作者改候选 → 17 沙盒接入及定向测试 → 主模型读取摘要/关键补丁、通过门槛 → 正式分批合并。

16 与 17 可由同一高速模型分时承担，但做过实现的包不能再自称独立审计。若只有两名外部模型，互换包审查；若确实无独立人选，标作者自测并扩大主模型抽查，不能伪造独立性。

有严重结算/迁移/伪造战绩问题时停该包接入，其他独立包继续。普通返工由 17 发给用户可复制的短任务，包含问题 ID、文件/行、复现、预期和需重跑项；用户转发原作者。不得自动给其他 Agent 发消息。

## 8. 减少额度的具体要求

1. 公共参考只在 01 和 MV5-01 增补一次，下游复用；变动资料才重新核对。
2. 主模型默认只读每包 DELIVERY、manifest、审计阻塞项和关键补丁，不重读全部原始日志。
3. 工具输出先筛选后展示。`engine-manifest.json`、`data/cards.json` 可能是巨大单行 JSON，必须 parse 后选字段，禁止 cat 全文。
4. 图像批量生成/参数核对、数据抄表、文案、性能采样和旧测试迁移均在外部完成；主模型只抽代表样例。
5. 接入失败不转由主模型补完整包；先返给作者一个具体缺口，17 复测并更新摘要。
6. 日常集成用最小风险场景组；每个里程碑再做一次关联链全回归。没有新变化不重复证明同一件事。

## 9. 发布与恢复底线

只提交本轮正式采用的文件；用户未提交 `docs/美术与前端独立开发交接文档.md` 与旧 deliverables 保留。私有发布沿用 `npm run publish:private`，不推根仓库含上游 Home 的历史。默认不清旧档、不自动把旧世界升级经济、不在有活动比赛时换 profile。正式发布由主模型完成，外部模型提供候选和可回退方案即可。
