## 两个阶段

### A. 现在的基线盘点与复现

记录实际HEAD/dirty，从默认根页面与当前真实Host出发，不把旧classic/previous/Mock页面当正式入口。

- `coverage.md` 覆盖全项目模块：启动/profile/存档、窗口与输入/暂停、采购/仓库/开包/零售/二级市场/垃圾桶、顾客与导航、任务/经营/经济、牌桌/对战、素材/生成、桌面/发布、契约/测试。每项写已读入口、沿调用链复核/动态复现/只静态读/未覆盖的深度，不能扫文件名就写全审计通过。

- `findings.json`：实际发生的现象、期望与依据、P级、最小输入/步骤、证据文件、文件/行号、置信度与未知。纯猜测和静态线索另列，不为报数制造Bug。
- 优先查真实报错/钱卡丢失或重复/无法参赛/顾客永久占桌/暂停与控制卡住；发现严重问题及时在DELIVERY中标出，继续不依赖它的只读工作。

### B. 主模型接入后的定向补测

收到实际新基线后再做，不现在拿旧版失败冒充新版结果。只重测受影响链，不重复全库。

| 链路 | 必要观察 |
| --- | --- |
| 独立窗口/分页 | 各器具默认打开自己的窗；五种尺寸无长滚动/裁切/双滚条；页外数据可搜索；父子Esc/焦点/草稿正确 |
| 即时进货 | 同一成功事务扣一次钱/授信并入库；失响应原号找回；库存数量、发行与成本正确；旧已付款订单不重复收货 |

| 候战/行动 | 玩家窗口关闭后可手动走动、用其他器具；手动/自动不抢输入；取消/打烊/对手离开后释放座位与卡；NPC不会重复排队/堵门 |

| 引擎 | 当前默认入口真实加载ready、BO3/KOF结束/换将、错误/超时/关窗/重开、旧或伪消息不被计费结算；区分实际引擎、fixture终局和纯单测 |
| 价格/购买 | 记录实际售价、顾客钱包、库存与购买条件；不是只看到价格变低就声称NPC会买；新评分未发布时标待验 |
