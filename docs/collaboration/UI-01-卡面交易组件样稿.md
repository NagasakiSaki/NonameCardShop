# UI-01：卡面为主的交易组件样稿（可交给 zcode / WorkBuddy）

在 `D:\GameDev\NonameCardShop` 工作。读 `docs/下一版前端重建开发文档.md`、`docs/协作任务分工与任务包.md`。本任务只做可预览候选稿，真实 Host 接入由主模型负责。

允许写入：`frontend-next/components/`、`frontend-next/mock/`、`frontend-next/styles/`、`frontend-next/experiments/card-trade/`、`tests/frontend-next/card-trade.mjs`。不要改现有 `frontend/`、入口、后端、契约、游戏存档、根包文件。用现有 JS/CSS/Canvas 能力，不引入框架/远程字体/远程卡图或付费资源。

输入素材从工程现有资源读取，遵循文档像素规范。至少提供 CardTile、ProductTile、CardDetailPanel 和 SupplierBasket 的纯展示组件；展示卡面优先，卡包/卡盒/单卡明确分开。供应商页面直接显示进货单位、每盒包数、库存、单价、数量、小计、总计和模拟收货状态。

在 Mock 模块显式定义并注释最小演示结构：Card（id、name、artUrl、rarity、ownedCount、availableCount、price）、Product（id、kind、name、artUrl、unitPrice、stock、packsPerBox）。它们**不是正式 v2 DTO**；不擅自修改 `contracts/`。价格由输入传入，不在 UI 发明评分/出货/定价公式。用整数分保存演示金额，格式化时再显示。

组件只通过回调表达查看详情、增减数量、模拟提交；禁止 import Host、发真实交易请求或读写 localStorage/IndexedDB。页面顶部常驻“界面样稿 / 模拟数据”，刷新恢复。数量和结果用文字明确，不能只有颜色。卡图缺失有可辨的占位，不破版。

验收：

1. 1366×768 能看到卡面、稀有度、x 数量和价格，不需要先逐条点开列表。
2. 406×1000 无全局横向溢出，操作按钮仍可用；卡面比例正确。
3. 选商品→数量→购物篮→模拟收货不超过必要步骤；提交按钮清楚标注模拟。
4. 独立预览入口在 `frontend-next/experiments/card-trade/index.html`，控制台无异常；提供两种视口截图。

只为样稿核心交互做一次隔离浏览器检查；不要调用正式引擎或整体回归。交付样稿、预览 URL、截图、尚未接入列表。主模型审美/信息架构审查和接口冻结后，再另派真实接入任务。
