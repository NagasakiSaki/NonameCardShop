## 目标与明确方向

用户希望角色立绘保留原版插画的身形、姿势、发型和服装，减少从头用代码几何拼人物的工作量。优先尝试“原版角色全身立绘 → 像素化 → 关键细节修整”，不继续把人物改成统一站姿、同一身体模板。

## 候选工具与选择原则

1. 优先对比 [PixelOE](https://github.com/KohakuBlueleaf/PixelOE)：轮廓处理和细节保留优于仅缩小放大这一方向值得验证。固定版本；记录使用 legacy CLI 还是 API，当前 README 明示旧 CLI 将弃用。不要把安装 PyTorch、Slang 或 GPU 环境当作默认前提，报告实际依赖和本机耗时。
2. 轻量对照采用 [Pixel It](https://giventofly.github.io/pixelit/) 或确定性缩小/色板量化。浏览器本地处理，不要求用户上传原图到第三方服务。
3. 使用 [Pixelorama](https://pixelorama.org/user_manual/image_effects/) 做分层和局部修整，可保留 `.pxo` 或兼容源文件；[CLI](https://pixelorama.org/user_manual/cli/) 用于可复现导出。
4. [ImageMagick](https://usage.imagemagick.org/quantize/) 可以作为尺寸/颜色的基础对照，不保证其普通像素化即达到美术目标。

本任务允许先试少数候选再选一个主流程，不要安装整套无关生成模型，也不使用付费服务。不要仅凭项目 README 就宣称本项目人物转换质量合格。

## 转换流程

1. 从索引确认角色与正确服装版本，使用原版角色全身立绘。保留原姿势与比例，去掉无关背景；原图若不透明，背景处理过程要可追溯。
2. 先确定目标画布与人物实际占比，再做像素转换。脚不能截断、头顶不能切掉；不拉伸成统一身材。
3. 至少对比轻量基线与 PixelOE 候选，记录缩小策略、轮廓、色板/颜色数、抖动和 alpha 处理。尤其检查透明边缘有没有黑边/白边，不能假设库会正确保留透明通道。
4. 面部和重要衣饰进行少量局部修整：眼睛不糊成色块，头发/脸/衣服轮廓分明，五官符合原图视角。三分之四脸的两眼可以因透视不同，不能为了“对称”改坏原图。
5. 从同一张全身像素立绘裁出头像，保留角色特征；不要直接把全身挤到头像方框里。
6. 保存原始参数和修整步骤，能够重跑，不只交最后几张 PNG。

## 候选规格与兼容边界

当前正式立绘是 128×224、头像 96×96。新立绘候选建议比较 **256×448 与 384×672 原生画布**，不是把旧像素立绘放大；目标是从原版高分辨率输入保留更多结构。两种尺寸都保持原人物纵横比，用透明留白适配。

- 小样主交付 256×448 RGBA PNG，同时提供 384×672 对照；用户确认后再冻结最终规格。
- 头像交付现有兼容的 96×96，并提供 128×128 对照；记录裁切矩形和头顶/下巴安全区。
- 1× 原生图、2× 最近邻放大图、拟用于游戏面板的实际显示尺寸都要可预览。
- 不修改 `standing-portrait.mjs` 常量或正式资源读取器强行接新尺寸；主模型审查后统一调整 manifest 和校验。
- 不承诺全图硬限 16/32 色。小样比较 64/96 色及原方案，优先保留眼睛、白色衣服和深色头发的层次；需要更多颜色时说明理由。

以上是候选要求，尚未成为正式游戏契约。
