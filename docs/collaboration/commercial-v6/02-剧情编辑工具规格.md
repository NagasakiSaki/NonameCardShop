# 02：剧情编辑器与内容制作工具

**这是工具任务规格，尚未有正式编辑器/API。** 目标是让策划和用户不用修改游戏 JavaScript，就能改台词、选项、条件、流程与场景，并预演真正会发生的经营/对战结果。

## 1. 技术选择与成熟参考

| 参考 | 已核实能力与本项目采用方向 |
| --- | --- |
| [ink / Inky 官方介绍](https://www.inklestudios.com/ink/) 与 [Inky 源码](https://github.com/inkle/inky) | 可边写边试、错误定位、跳转与导出；借鉴快速预览和清晰源文件。不能把“能导出故事网页”当成本游戏经济/存档已接通 |
| [inkjs](https://github.com/y-lohse/inkjs) | 是 JavaScript 的 ink 实现，适合作为未来成熟脚本导入/运行选项的研究对象；须固定版本并验证编译输出/保存格式，不与 inkle 的官方运行器混称 |
| [Yarn Spinner Dialogue Runner](https://docs.yarnspinner.dev/components/dialogue-runner) | 对话、选项、命令与表现层分离的设计；不把文档中的 Unity 组件直接套到 Phaser |
| [Tiled World 文档](https://doc.mapeditor.org/en/stable/manual/worlds/) 与 [自定义属性](https://doc.mapeditor.org/en/stable/manual/custom-properties/) | 多地图与元数据分开编辑，可作为地点/出入口绑定来源；地图导入与剧情编辑是两个适配层 |

资料核对日：2026-10-25。默认实施采用**本项目的受约束结构化剧情源 + 表单/关系图编辑器 + 同一运行器预览**，不为基础故事自造完整编程语言。源格式 `.story.json` 是唯一编辑真源，编译包只由工具生成。这个选择便于高速模型和非程序员共同维护，并可把钱/卡副作用限制在已有业务合同内。

若以后改为 Ink 或 Yarn 作为唯一真源，必须先提供一个实际经营/选择/等待/保存恢复 PoC 和完整 round-trip/迁移方案，再替换内容适配器。不能同时要求作者同步维护 Ink 与 JSON 两份分支真源；不支持的语法明确拒绝，不能静默丢效果。首版不下载/安装这些外部工具作为硬依赖。

## 2. 项目文件与稳定身份

拟定目录，仅为后续目标：

```text
content/story/<campaignId>/
  project.json                 # 项目/内容版本、依赖能力、入口章节
  characters.json              # 人物ID、显示名与外观角色引用
  chapters/*.story.json        # 场景、节点、边、条件、动作参数
  text/zh-CN.json              # lineId -> 台词/选择文本
  locale/<locale>.json         # 翻译，不复制流程
  layout/*.layout.json         # 编辑器图位置，不影响游戏逻辑
  tests/*.scenario.json        # 情境输入、操作与预期
```

当前游戏仍没有这些正式目录，候选只能落各自 deliverables。ID 包含 campaign/chapter/scene/node/line/choice/effect；不按台词内容或节点索引生成。删除、复制、重命名、拆章都要保留引用/迁移映射。角色显示名可改，不换 actor 身份。文件输出排序稳定，便于 Git diff；编辑器布局坐标变化不触发玩法版本变更。

## 3. 首版必须具备的工作流

1. 新建/打开项目 → 选择章节/场景 → 新增对话/选择/等待等节点。
2. 用表单选择说话人、立绘状态、台词、下一节点；选项可排序，条件从注册表选择，不输入 JavaScript。
3. 绑定真实业务条件/动作：例如等待一笔密封商品成交、等待完成某场考核；选择“打开货架”只打开操作界面。
4. 实时错误提示 → 定位缺失角色/节点/素材/能力或无法通过的条件。
5. 文本预演 → 情境模拟 → 隔离游戏内预览。三种模式标清证据级别，不能混成“已实装”。
6. 保存草稿/撤销重做 → 验证 → 内容包构建 → 查看差异/兼容报告 → 输出发布候选。编辑保存不直接改玩家正在游玩的剧情版本。

非程序员验收：按教程在编辑器中新建一段三选项场景，绑定一项已支持条件，预演分支，导出、关闭再打开继续编辑；全程不手写 JSON/JS。模板是加速器，不以要求用户复制代码替代界面。

## 4. 首版节点与字段

| 节点 | 必需内容 | 不能隐式做什么 |
| --- | --- | --- |
| `line` | lineId、speakerId、允许的表现 cue、next | 显示一句“货已到”不创建库存 |
| `choice` | choiceId、lineId、条件/不可用理由、target | 点选不自动支付或消耗卡牌，除非进入明确业务确认 |
| `branch` | 受约束条件树与至少一个 fallback | 不能执行字符串表达式或依赖 UI 文本 |
| `wait` | 事件/状态条件、离开后策略、超时/取消出口 | 不能占着暂停等游戏分钟流逝，造成自锁 |
| `action` | 已注册语义动作ID、参数、effectId、成功/失败出口 | 不能 eval、任意改 world、直接加钱/牌或跳版本 |
| `cue` | 允许的立绘/镜头/声音/移动请求、可跳过属性 | 表现移动不能穿墙、复制 NPC 或改变权属 |
| `transition` | 地点/入口 ID、许可条件、失败/返回出口 | 不能用不合法的 roomId 直接传送 |
| `end` | 场景结束策略、任务/联系人的意图引用 | 不能把对话结束当作经营任务已完成 |

条件树首版只支持 `all/any/not` 和注册谓词（有界比较、标志、实际任务/赛事状态等），明确 value 类型、作用域、事件来源和版本。必须能表达“条件不满足时显示理由”，不只隐藏入口。

## 5. 编辑界面

项目/章节树、节点列表与关系图、属性表单、条件/动作面板、文本预览、错误面板六部分。节点之间可定位、搜索、按人物/地点/任务筛选，显示孤岛/循环/等待出口。首版优先稳定编辑与连线关系，自动布局、复杂拖线、批量翻译和专业时间轴后置。

图形画布允许平移/缩放，编辑属性可滚动；这是制作工具。游戏中的购物/选将/剧情选择仍分页、主动作固定可达，不借编辑器扩展恢复玩家界面的长滚动流程。对话正文可自然换行、选项分页；高级台本/日志查看是工具面板。

必要编辑行为：撤销/重做、未保存标记、自动草稿恢复、显式保存/另存、导入/导出、复制节点并生成新 ID、删除前列受影响引用、缺图回退、资源 ID 选择、同文件被外部改动时提示冲突。不能静默覆盖磁盘新版本。

## 6. 预览、调试与校验

文本预演只展示台词/分支。情境模拟使用显式 fixture（第几日、余额、角色位置、已完成任务/考核等），可跳到节点、查看变量与执行 trace。隔离游戏预览使用真实 Host、临时仓库/浏览器 context 和独立测试 profile，副作用仅影响该副本；预览状态不能导入玩家正式进度或伪装成正式资格。

校验至少包含：重复/缺失 ID、悬空边、无出口等待、明显不可达场景、无界自循环、条件类型/作用域、缺失素材/动作/能力、语句插值、金额/数量范围、跨章节依赖、分支恢复、缺少失败路径、奖励重复入口。静态校验只说明结构可用；完整业务条件仍须真实运行。

预览时间可快进，但必须调用批准的时钟/模拟逻辑。给测试副本注入条件需要明确 `preview-fixture` 来源，不能给出“店长已通过真实考核”的正式结果。错误应带文件/scene/node/effect 定位，能从问题跳到编辑表单。

## 7. 编译、发布与回滚

保存编辑源、构建内容包、激活到存档是三个不同动作。内容包声明 schema/compiler/runtime/内容版本、依赖能力、资源摘要与 hash；机器生成 `storypack` 不手改。旧已完成节点/奖励回执保留，活动会话固定旧内容版本；更新时让用户知道会话继续/暂停/迁移的方案。

需要迁移的删除/改名节点给别名或迁移表。没有可信映射就保留旧版本或挂起场景并允许自由经营，不从剧情入口重新发奖。降级不一定无损，工具需说明兼容范围与备份。

## 8. 工具存储与运行边界

工具以独立本地页面运行，优先文件导入/下载与受限项目保存；浏览器支持的文件 API 可作为可选增强。若增加本地写文件服务，只允许选定内容项目根目录、校验规范化路径、限制文件大小/类型、会话校验并保留备份，不开放任意路径写入。编辑器不持有玩家游戏的经济命令能力。

素材浏览用 manifest ID，不向每个作者分发整个用户原图文件夹。编辑器不在显示台词时执行 HTML/脚本；任何第三方导入只当数据。首版无需账户、云协作、运行时 CDN 或新的全局 UI 框架。工具读我文件、不越权动我存档，是稳定性验收的一部分。

## 9. 分工

19/20 写故事与实际样例；21 拥有内容 schema/运行语义；22 做编辑器和项目 IO；23 做结构校验、构建、情境模拟/预演和发布差异；26 做玩家播出。22/23 可并行，不能各写一套不兼容的解析器。它们用同一份 schema、样例和编译结果，通过固定 golden fixture 检查一致性。
