# V7-B：三日高手、约战、解锁与经营伙伴

推荐能处理持久状态机的标准代码模型；高风险事务由主模型整合审查。只写 `deliverables/operations-v7/V7-B/`，不等A/C/D/E，不自行更改其合同。

## 连续任务

1. 建立独立version:1 progression状态与校验/恢复：epoch、唯一活跃阶段、到期队列、当前来访/邀请、延期、挑战登记、伙伴和回执。对照01默认15阶段，以共享目录fixture实现；不能从最近日志推导已解锁。
2. 三日调度：新档3/6/9…，旧档首次启用当前日+1后每3天；前关不通后关排队、同日不连刷。按持久visitId发出实际来访/接近/离店/次日返回意图，退出/被堵/闭店/忙碌有出口，不生成门口常驻人堆。
3. 统一邀战状态机：普通NPC可被点击邀请，高手主动发邀请；only现场/可达/空闲时对话就绪，同日一次主动提示。接受进入准备、明天再来记录次日，Esc或关闭视为本次延期。read-only查询不重复创建invite。
4. 败北后再试/明天、平局、准备取消、技术中断、窗口关闭/后台、读档旧响应逐项处理；不能把拒绝当永久失败。准备失败保留可恢复邀请，不吞牌/钱，不持永久暂停。
5. 随机挑战阵容服务：严格从本阶段待解锁主题选兼容武将，满足指定模式备战数。challenge-loan限定用途、独立ID、种子与接受时固定；不制造真实库存/市场流通，不清除普通NPC资格限制。卡池不足给出原因并按配置BO3可用回退，不能悄换主题。
6. 只消费C/D的可信整场胜利DTO做原子意图：过关、解锁产品、招募伙伴、回执。核对challengeId/stageId/对手/目标包/完整胜场/真实来源；重复、冲突、模拟和迟到事件不能发奖。用fixture演示提交成功与提交失败回滚政策，不宣称fixture过关是真实对局。
7. 伙伴不是纯文案：值班/停用、默认3席、至少招徕/收银/进货三类派生效果与上限；没有直接加假营业额。设计接managementEffects和未来订单冻结的明确adapter与测试。
8. 旧档初始化/未来版本opaque保留、晚期迁移、日初因果回卷、手动导入、已开始挑战配置锁定。至少模拟到45天并跨日志裁剪，记录队列、延期、阶段和伙伴。
9. 整理完整源码/测试与runtime/visits/world/management的精确接线建议；E的对话只消费你的只读offer，不写前端。
