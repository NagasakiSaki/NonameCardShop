# 按天存档与安全读档

入口：游戏顶部“按天存档”，桌面源码版也可从“存档→按天存档 / 读档”打开。档案窗口会暂停经营时间。当前进度仍按原有 localStorage 自动保存，按天档案另存 IndexedDB，避免多天完整快照挤满原存档空间。

每一天有三个位置：

- 当天起点：开始新一天自动创建，之后不会被本日的普通自动保存覆盖。升级后第一次留档只能记录当时进度，不能重建此前未保存的日初。
- 打烊档：当天完成结算后自动保存，之后刷新或整理垃圾桶不会覆盖这份结算时点；从这里读档再开始下一天会正常清桶、领取已满足的每日奖励。
- 手动档：点“保存当前时刻”，保存该分支当天最新的一份手动进度。

读取前先验证格式、规则和模块版本，再把当前进度写入“读档前备份”。备份失败会停止读档，原进度保留。成功读档后创建新的进度分支，保留原分支后续天数的档案；界面区分“本次进度”和“历史进度”。也可以在“读档前备份”中返回读档之前。

快照包含资金与债务、库存/货架/垃圾桶、订单、任务及奖励领取状态、账本、经营时间、比赛登记状态、像素人物位置、实体卡盒的所有既定内容和位置，以及经营/任务/各模块的配置。读取旧天数会一起恢复当时配置。完整无名杀引擎的进行中事件栈不在经营存档内，所以正在对局或开包时不允许手动存读档；比赛中断仍按现有恢复规则处理。

## 保留与迁移

`data/save-history.json` 配置每分支最多30天、最多20份读档前备份，可以改为1—365天、1—100份。保留策略显示在存档窗口；需要长期保留的节点请导出。

“导出”生成兼容原有完整存档格式的JSON，并附带每日档案和规则。通过每日档案入口导入时不会立即覆盖当前进度，点击“读取”才应用；导入采用独立档案身份，避免覆盖现有节点。普通桌面“导入存档”仍可读取其中的游戏进度，但恢复规则快照应使用每日档案入口。

档案库名为 `noname-card-shop-day-saves-v1`，随浏览器用户/地址，或桌面用户目录隔离。开发端口和正式试玩端口各有档案；测试使用临时浏览器或测试用户目录。清空浏览器网站数据会删除该地址的档案。换电脑、浏览器或入口地址前先导出，GitHub源码仓库不保存个人进度。

## 修改接口和测试

- `modules/save-history.js`：IndexedDB仓库、格式校验、原子写入与保留策略；`ShopHistory.createRepository()` 可使用独立数据库做测试。
- `save-history-ui.js`：日边界观察、规则快照、读档前备份、独立分支和界面。
- `ShopDaySaves.saveCurrent()`、`load(id)`、`exportRecord(id)`、`importRecord(file)`：异步接口，错误会拒绝Promise；`flush()` 等待已排队的日档写入。
- `shop-state.js`：只保留进度分支标识，实际档案不塞入游戏存档。
- `npm run test:saves`：真实IndexedDB测试，包括跨日快照、整盒/订单/任务/配置恢复、读档前恢复、写入失败保护、导入导出、保留策略和手机布局；也纳入 `npm test`。

本轮实现先提交源码，不重建包含存档功能的exe。继续用“开发启动.cmd”或“桌面开发.cmd”测试，待玩法稳定后统一打包。
