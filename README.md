# 无名小店 · Noname Card Shop

以武将卡牌为核心的卡店经营游戏原型：玩家经营卡店、拆包收藏、买卖单卡、经营牌桌，并参加高手挑战。技术路线为 **Phaser 像素世界 + HTML/CSS 界面 + JavaScript 经营规则 + 无名杀原生对战引擎**。

**2026-10-26：当前开发版本公开。** 本仓库包含源码和开发素材；最新修改以源码开发版为准，旧 EXE 尚未同步。明亮主题、64×64 地砖及全部 76 项设施/状态重绘已接入，真实经营与对局仍沿用原有规则；详见 [本轮前端整合记录](docs/reviews/2026-10-26-明亮前端与设施重绘接入.md)。

## 当前功能

- 独立卡店档案、新建/继续、按天回到当天开店时，以及精确时刻备份。
- 进货即入库、密封包盒货架、独立拆包台、自动收银、收藏与二级市场。
- 卡盒固定稀有度定额、散包出率与保底展示，旧实物保持原印刷版本和封装结果。
- NPC 购物/店内拆包/弃卡/拾卡、市场流通、后台模拟对战与实时收支。
- 每日自动领奖、阶段高手约战、主题解锁和经营伙伴。
- 高手从第 2 天开始，当前高手通关次日来下一位；落败可重选再战/次日赠包，提供伙伴排班与分类菜单、七条设施升级路径。
- 海玲作为债主在开局登场：剧情借款 20,000，第 7 天首期目标 5,000，可分次还款、每期赢牌抵扣一次；与进货欠款分账。
- 二级市场只交易 SR/SSR；完成首期借款目标可取得户外前置资格。户外、炒卡与工艺系统保留后续扩展接口。
- 外观仅保留五团25位 BanG Dream 角色，店长默认千早爱音，可免费换装；顾客类别与外观独立。
- 三种玩家对战：**1v1 三将接力、斗地主换边 BO3、2v2 BO3**。多人模式接入原生无名杀，支持可选队友接管。
- 对战房间、公开对手备战池、两阶段选将与阵容锁定；KOF 换将重新摸四张，不继承手牌。
- 滚动选将和交易、保持滚动位置、每页一组大包盒与完整武将卡册、经营卡面右键查看技能。
- 按卡包进入选将、跨包保留名单，包内按当前模式分数降序；斗地主当局按地主/农民身份分排序。
- 两回合理想血差/牌差收益论，强中与拆装备小额加分；发行配额与印刷等级独立冻结，评分和解锁不改变卡包出率。

详细规则以 [三赛制与定价规则](docs/architecture/三赛制与定价规则.md)、[滚动选将修复](docs/reviews/2026-10-26-滚动选将与卡包图鉴修复.md) 和当前代码为准。旧记录中的单将 BO3、四模式、旧价格、强制分页等不是当前规则。[架构与规则文档索引](docs/architecture/README.md) 区分了现行文档与历史文档，接手时先看它。

## 启动开发版

主要开发环境：Windows，Node.js **22.12 或更新版本**、Git、Git LFS。卡图、音频等使用 LFS，缺少真实资源时不能只下载指针文件运行。

```powershell
git lfs install
git clone https://github.com/NagasakiSaki/NonameCardShop.git
cd NonameCardShop
git lfs pull
npm ci
node dev/start-game.mjs
```

也可在依赖准备完成后双击 `一键启动游戏.cmd`。开发页面为 `http://127.0.0.1:5190/frontend/index.html`，原生引擎使用 5191 端口。首次从启动页创建独立测试卡店。

不要直接双击 HTML 或使用 file://；启动器会检查服务版本与原生模式能力。进行中的对局结束后再刷新页面。

完整桌面开发、Electron 和浏览器测试依赖可以使用 `npm run setup` 安装，详见 [开发指南](docs/DEVELOPMENT.md)。开发版不要求先打包 EXE。

## 测试

```powershell
npx playwright install chromium
npm run test:rooms
npm run test:long-term
```

最近三赛制、房间、经营与滚动交互检查记录见 [验收文档](docs/reviews/2026-10-26-滚动选将与卡包图鉴修复.md)。受控引擎夹具通过不代表所有武将技能、自然难度或长期经济平衡已验证。

维护时可用 `node tests/run.mjs --task=OPT-13 --list --details` 查必要范围，再按任务执行；完整结构回归和失败补跑见 [测试范围与证据等级](docs/architecture/测试范围与证据等级.md)。素材默认生成隔离候选，`npm run art:reproduce` 检查可复现；内核候选先用 `npm run engine:stage -- --source 目录` 生成差异报告，[不会自动替换正式引擎](docs/architecture/上游内核升级暂存流程.md)。

高手顺延、设施升级、借款阶段目标及未来镀层/交易所接口见 [长线经营规则与维护说明](docs/architecture/长线经营与高手挑战-v1.md)。

最新评分假设、固定发行和选将接口见 [两回合收益论与分包选将](docs/architecture/两回合收益论与固定发行-v1.md)，专项检查为 `npm run test:ideal-yield`。复杂技能的理论初估与已校准技能分开标记。

## 目录与贡献

| 目录 | 用途 |
| --- | --- |
| `frontend/` | Phaser 世界、主外壳、统一窗口、对话与三赛制房间 |
| `frontend-next/` | 正式经营组件、卡面交易、设施窗口与适配 |
| `modules/backend/` | 库存、钱包、出货、NPC、时钟、存档与规则 |
| `integration/` | Host 与原生无名杀模式接入 |
| `vendor/` | 已登记的上游引擎与库，保留原始声明 |
| `contracts/`、`data/`、`content/` | 接口、规则、注册与内容 |
| `config/` | 桌面运行范围等跨层维护配置 |
| `tools/`、`tests/`、`docs/` | 素材工具、测试、维护与设计文档 |

欢迎报告可复现的问题和提交 PR。请注明存档类型、操作步骤、模式、截图与日志，移除私密信息；优先在独立测试档验证。资金/库存/存档只通过后端事务改变，真实胜负只通过引擎桥确认。

[当前前端专项任务书](任务分发/前端专项-明亮二次元卡店-2026-10-26/README.md) 明确了明亮二次元风格、所有设施细化重绘、文件边界和交付要求。其他候选实现进入正式目录前需要接线与回归，不把演示截图当正式功能。

## 发布维护

维护者使用过滤发布副本导出历史，排除上游浏览器用户缓存。当前公开仓库更新使用 `npm run publish:public`；命令会核对目标可见性。`npm run publish:private` 仍只允许私有目标，防止误用。

本地存档、环境变量、测试产物、AI 工具工作目录和未经接入的候选文件不属于自动发布内容，不要直接全量打包本机目录上传。

结构整理与恢复说明见 [工程目录与维护边界](docs/architecture/工程目录与维护边界.md)。`npm run backup:stable` 在工程外创建带真实素材、SHA256 和 Git 历史的本机源码快照；浏览器存档需在游戏内另行导出。`npm run audit:structure` 只读检查引用、分层与缺图清单；`npm run test:all` 汇总完整当前回归并保留失败报告。旧测试规格与替代覆盖见 [归档说明](docs/archive/test-specs/README.md)。

下一位维护模型使用 [全面优化接管包](docs/handoff/2026-10-27-全面优化接管包/README.md)：完整冻结规则、架构/事务边界、22 项任务、启动指令和核查快照。交接核查发现的“明亮场景素材未被桌面打包范围纳入”已在 [2026-10-27 阶段 A 执行记录](docs/reviews/2026-10-27-阶段A-资源闭包与契约校准.md) 修复：运行范围补入 `assets/frontend-bright-anime`，并新增 `tests/package-closure.mjs` 按真实构建 filter 验收 159 条清单资产引用（不止手写目录）。
