供应商可选散包或完整卡盒。散包每包5张，至少1张R+；完整卡盒24包/120张，常规固定 C60/U36/R18/SR5/UR1，进阶 C36/U60/R15/SR7/UR2，典藏 C12/U60/R34/SR11/UR3。卡盒进价/建议售价分别为3050/4360、3860/5515、5610/8015，随参考卡价与定价配置计算。

## 一天的完整流程

1. **08:00 准备**：WASD / 方向键移动，E 交互，B 背包；也可点击地面或家具自动寻路。
2. **进货下单**：柜台选择卡包、数量并支付进货款。默认 30 个游戏分钟后送达，需在“收货 / 仓库”签收入库。
3. **补货 / 拆包**：仓库未拆卡包可以在左侧陈列架上架整包，也可在柜台拆出 5 张单卡。允许重复，按“×数量”叠放。拆包消耗库存，不重复扣款；中途取消不消耗卡包。
4. **开门营业**：顶部按钮进入 09:00；准备时钟到 09:00 后等待手动开门。营业中仍可继续下单和签收。
5. **AI 顾客购物**：不同顾客有预算、偏好和价格承受度，走到货架挑货，再到柜台付款。不合适会离开。可以调整单卡与整包售价。
6. **任务推进**：手账打开任务簿领取奖励，领取主线奖励后解锁后续。营业额只统计顾客付款，任务奖励单列。
7. **20:00 自动打烊**：也可提前打烊。记录营业额、进货总额、成本、奖励与资金，保留最近 30 天日报。营业成本只扣一次。
8. **开始下一天**：先捡回想留下的垃圾桶卡片，再点“领取每日奖励，开始第 N 天”。垃圾桶此时清空，每日指标 / 任务重置，其余库存、订单、资金、欠款与主线保留。

**垃圾桶只保留到当天结束。** 打烊结算不立即清空，可以先去捡回；开始下一天才清空。背包、货架和仓库不受影响。

## 时间与经营参数

- 默认每真实秒推进 2 个游戏分钟，可暂停及 1 / 2 / 4 倍速。
- 普通背包、柜台、任务簿不暂停营业；手册、编辑器、结算、对局、后台时暂停，不计算离线经营。
- 晨昏光照与时段客流变化，晚间变暗并亮灯。
- 首日目标 ¥180，每天增加 ¥60，上限 ¥900；营业成本默认 ¥30。
- 初始资金 ¥1200；常规/进阶/典藏进价 ¥120/150/230，整包建议售价 ¥175/215/330，按槽位和单卡参考价计算。
- 单卡 C/U/R/SR/UR 基准价 ¥8/16/48/160/480；货架默认共 36 件，可放整包与单卡。
- 显式勾选赊购可使用默认 ¥300 额度；销售 / 任务现金收入优先还欠款，未支付的营业成本也形成欠款。
- 日报收支差额是营业额减去本日进货总额和营业成本。进货含赊购、还有未售库存，任务奖励 / 偿还旧欠款另计，因此它不同于现金变化或会计利润。

时钟与顾客参数位于 `data/business.json`；槽位与进售价规则位于 `data/balance.json`。

## 编辑任务与扩展

手账 → 全部任务 → 任务 / 经营编辑器。支持 JSON 导入、校验、应用、导出、恢复默认，不重置收藏。修改保存到当前浏览器，导出后替换项目 JSON 可成为默认配置。

- `data/tasks.json`：主线依赖、每日目标、限时销售、条件、奖励、家具导航。
- `data/tasks.schema.json`：任务编辑补全。
- `data/business.json` / `business.schema.json`：时钟、供应商、价格、成本、客流、顾客画像。
- `integration/task-extensions.js`：注册新指标、条件、奖励及玩法事件。
- **完整接口与可复制示例：`docs/TASK_AUTHORING.md`。**

接口包括 `ShopTasks.registerMetric/registerCondition/registerReward`、`ShopBusiness.on/emit`。JSON 只引用注册名，不执行函数字符串或 eval。任务稳定 ID、幂等奖励、过期与换日重置均已实现；奖励提供器失败会回滚整次领取。
